#### 1.3 `send(text)`（assets.py:7481-7502）

#### 1.4 `sendStreaming(text, imageTokens)`（assets.py:7532-7638）

- `myView = viewToken` を控える。`missed = false`。
- `fetch('/api/chat/stream', { method:'POST', headers:{'Content-Type':'application/json'}, body: JSON.stringify({ text, images: imageTokens }) })`。fetch が例外 → `return false`。`!res.ok || !res.body` → `return false`（→ `sendAtOnce` にフォールバック。サーバが `_TurnError` の 400 JSON を返した場合もここに該当し、`sendAtOnce` が同じ本文で `/api/chat/send` を再送して同じエラーを受け取り、`api()` の例外として `{role:'assistant',kind:'error',message}` を描く）。
- 逐次描画用のローカル: `node`（`div.streaming`）と `buf`（本文）。
  - `openText()`: `node` が無ければ `#thinking` を除去し `lastRole=null`、`slot('assistant')` に `div.streaming` を追加。
  - `closeText()`: `buf.trim()` が空なら `node.remove()`、あれば `is-done` クラス（点滅カーソル解除）。`buf` が空でなければ `revealCitedSources(buf)`（assets.py:6845。本文中の `[出典n]` 番号で出典カードの折りたたみを確定）と `feedbackRow()`（評価行を末尾へ）。`node=null; buf=''`。
- SSE の自前パーサ（`EventSource` は POST 不可のため。assets.py:7605-7637）: `res.body.getReader()` + `TextDecoder`。受信文字列を `'\n\n'` で分割し最後の断片は `rest` に持ち越し。各ブロックの行について `'event: '` → `ev`（既定 `'message'`）、`'data: '` → `payload` に連結。`payload` 空なら skip。`JSON.parse` 失敗の行は捨てる。`handle(ev, data)`。読み取り中の例外 → 同一ビューなら `{kind:'error', message:'通信が途切れました: ...'}` を描く。ループ後、同一ビューなら `closeText()`。`return true`。

#### 1.5 イベントごとの画面動作（`handle(event, data)`）

| event | data | UI の処理 |
|---|---|---|
| `delta` | `{"text": 文字列}` | `viewToken !== myView` なら `missed=true` で無視。同一ビューなら `openText()`、`buf += data.text`、`node.innerHTML = mdToHtml(buf)`、`scrollDown()` |
| `text_end` | `{}` | `closeText()` |
| `running` | `{"name": ツール名, "label": 日本語ラベル}` | `setBusy(true, data.label)`（「考えています」→「SQL実行 (SELECT)」等に差し替え） |
| `item` | 描画アイテム（`_web_log` 形式。`role, kind, ...`） | 別ビューなら `missed=true`。同一ビューなら `closeText(); lastRole=null; addItem(data); setBusy(true,'考えています'); scrollDown()` |
| `end` | `{"chat_id", "title"}` | 同一ビューなら `currentChatId = data.chat_id || currentChatId`。別ビューかつ `missed` かつ `currentChatId === data.chat_id` なら `openChat(data.chat_id)`（保存済み完成形を読み直す）。常に `refreshHistory()`（`GET /api/history`）と `scheduleMemoryRefresh()`（3秒→7秒→15秒後に `GET /api/memory` を見て `updated_at` が変わっていれば toast） |

`addItem(item)`（assets.py:6933）は `kind` で分岐: `text`（ユーザーなら `userTurn`、AI なら `mdToHtml` + `catalogLinks`）、`sql`（折りたたみブロック。`item.label || item.tool`、`purpose`、`pre.mono` に `sql`、`explanation` があれば「このSQLがしていること」）、`table`、`chart`（plotly の `figure`）、`file`（`item.url` があり `replaying` でなく `autoDownload` なら `window.location.href = item.url`）、`error`、`sources` など。

#### 1.6 `sendAtOnce(text, imageTokens)`（assets.py:7504-7530、フォールバック）

- `r = await api('/api/chat/send', { text, images: imageTokens })`。同一ビューなら `r.items.slice(1).forEach(addItem)`（先頭は既に描いたユーザー発言）、`currentChatId = r.chat_id || currentChatId`。別ビューで `r.chat_id === currentChatId` なら `openChat(r.chat_id)`。`refreshHistory(); scheduleMemoryRefresh()`。例外は `{kind:'error', message:e.message}`。

#### 2.3 `POST /api/chat/stream`（core.py:8708-8763, `stream()`）

1. `chat, scope, text = _begin_turn()`
2. `if not chat.get("id"): chat["id"] = chats.new_id(); _hold_chat(chat["id"])`（通常は `_begin_turn` 内の `_persist` で既に ID 確定済み）

5. `generate()`:

### 3. `_begin_turn()`（core.py:8535-8597）の手順

`/send` と `/stream` の共通前処理。失敗は `_TurnError`。

1. **検証**（8541-8546）: `text = str(body.get("text") or "").strip()`。空 → `_TurnError("質問を入力してください。")`。`llm.is_configured()`（brain.py:12941 = `llm_chat_url()` と `llm_api_key()` が両方非空）が false → `_TurnError("LLMが未設定です。env の OPENAI_* を設定してください。")`。
2. **スレッドローカルの準備**（8550, 8554）:
   - `rag.set_current_user(g.user)`（brain.py:11943）: `_rag_local.user = user`、`_rag_local.sources = 0`（出典番号の通し番号をリセット）。dispatch は利用者を引数に持たないため。
   - `results.new_turn()`（brain.py:7404）: `_turn_local.turn = "t_" + uuid4().hex[:8]`。result_id の使い回し（`find_by_sql` brain.py:7487）を「同じ質問の中」に限定する区切り。
3. **会話の読み込み** `chat = _load_current()`（8556 / 定義 core.py:7912）: `session["chat_id"]` があれば `_hold_chat(cid)` → `chats.load_chat(g.user, cid)`（core.py:1349。`render_log` を `_decode_item`、`messages` を `heal_messages` で修復）。無ければ `{"id":None,"title":"","created_at":"","messages":[],"render_log":[]}`。
4. **画像**（8558-8560）: `images, show = _images_from(body.get("images"))`（core.py:7859）: トークン列の先頭 `config.IMAGE_MAX_COUNT`（既定 4）枚を `_fs_get(token, username)` で引き、`send=[{"mime","b64"}]`（base64 本体のみ）と `show=[{"filename","mime","size","url":"/api/file/<token>"}]`。`images` があり `models.is_vision(models.current(g.user))` が false → `_TurnError("いま選ばれているモデルは画像を扱えません。")`。
5. **ユーザー発言の追加と保存**（8566-8575）:
   - `chat["messages"].append(llm.user_message(text, images))`（brain.py:13568）。
   - `n_img = llm.drop_old_images(chat["messages"])`（brain.py:13639、§7.2）。落とした枚数を print。
   - `chat["render_log"].append({"role":"user","kind":"text","content":text,"at":chats.now(), **({"images":show} if show else {})})`
   - `_persist(chat)`（core.py:7926）— ルーターLLMやリアルタイム取り込みの前に保存（別会話へ切り替えて戻ったときに質問が消えて見えないように）。
6. **スコープ決定** `scope = _auto_scope(text, chat)`（8577 / §3.1）。
7. **空スコープ判定**（8582-8585）: `not scope and not rag.rag_available(g.user)`（brain.py:11990 = `rag_targets(user)` が非空か）→ `_TurnError("いま調べられるものがありません。サイドバーの SQLite3 か LightRAG で、使うものにチェックを入れてください。")`。※この時点で質問は保存済み。
8. **リアルタイム取り込み** `_realtime_refresh(scope)`（8586 / §3.2）。
9. **システムプロンプトを index 0 に**（8590-8596）: `messages[0]` が `role=="system"` でなければ `insert(0, {"role":"system","content":""})`。その後 `messages[0] = {"role":"system","content": llm.build_system_prompt(scope, admin=_is_admin(), model=models.current(g.user), memory=memory_prompt(g.user))}`（毎ターン作り直し。保存時は system を落とす → §10）。
10. `return chat, scope, text`

#### 3.1 `_auto_scope(question, chat)`（core.py:8464-8517）— DB/表ルーター

1. `scope = build_scope({f.name: [] for f in db.list_db_files()})`（core.py:7417）: 各 DB ファイルについて `{"path": str(f), "alias": alias, "name": f.name, "tables": [全テーブル], "meta": catalog.load_meta(f)}`。alias は `db.aliases_for`（core.py:123）→ `alias_for`（113）: ファイル名 stem の `[^\w]` を `_` に、先頭が数字なら `db_` を付け、`main/temp` は `_db` を付加、衝突時は `_2, _3…`。
2. `off = set(rag.excluded_tables(g.user))`（brain.py:11972 = prefs の `tables_off`）。あれば各 `s["tables"]` から除き、空になった DB はスコープから外す。
3. `if not scope: return scope`
4. `config.SCOPE_MODE`（env `SCOPE_MODE`、既定 `"auto"`、許容 `auto/router/all`、不正値は `auto`）:
   - `"all"` → そのまま返す（収まらなければ後段の `prompt_for_scope` が要約モードに落ちる）。
5. `limit = models.inline_limit_for(models.current(g.user))`（§6.3）。`SCOPE_MODE == "auto"` かつ `catalog.inline_length(scope) <= limit`（core.py:3768 = 全文版カタログの総文字数）→ そのまま返す（ルーター省略・全部入り）。
6. それ以外（`router`、または `auto` で収まらない）: `chat_history = [render_log の role=="user" かつ kind=="text" の content]`; `picked = llm.route_tables(question, scope, chat_history)`（§3.1.1）。
7. `picked` が truthy のとき:
   - `chat["table_names"]`（この会話で実際に SQL が触った `"DBファイル名.テーブル名"`。`_persist` が積む）を `rpartition(".")` で割り、スコープ内 DB なら `picked[dbn]` に追加（ピン留め）。
   - `picked = llm.expand_tables_by_relations(picked, scope)`（§3.1.2）。
   - 各 `s` について `sel = picked.get(s["name"])`。`sel` があり `off` があれば `off` を再度除外。`sel` が非空なら `s["tables"] = sel`（`picked` に無い DB は全テーブルのまま）。
8. `picked` が None（判定不能・失敗・`"*"`）→ 絞らずに返す（→ 要約モード）。

##### 3.1.1 `llm.route_tables(question, scope, history)`（brain.py:13149-13210）

- 対応表 `known`: `f"{alias}.{table}"` と `table` 単独（他 DB と重複しないものだけ）を小文字キーで `(db_name, table)` に引く。`alias.table` は必ず引ける。
- `total`（全テーブル数）`<= 8` → `None`（絞る意味がない）。
- `cards = "\n".join(db_text_cached(alias, path, tables, full=False))`（要約版カタログ）。
- `ask`: 直近 `history[-3:]` を `（直前の質問: …）`、最後に `今回の質問: {question}`。
- `_create(model=config.OPENAI_MODEL, messages=[{"role":"system","content":_ROUTE_TABLE_SYSTEM},{"role":"user","content": cards + "\n\n" + ask}], temperature=0, max_tokens=300)`。`config.OPENAI_MODEL` は config.py:249 で **ハードコード `"gpt-5.6-sol"`**（env では設定しない）。`_ROUTE_TABLE_SYSTEM`（brain.py:13133）は「JSON 配列 `["alias.table", ...]` だけを出力、迷ったら含める、全部要る/判断できないときは `["*"]`」。
- 応答から `re.search(r"\[.*?\]", content, re.DOTALL)` → `json.loads`。例外は print して `None`。`"*"` を含めば `None`。各要素を `known` で引き `{db_name: sorted(tables)}`。1件も引けなければ `None`。

##### 3.1.2 `llm.expand_tables_by_relations(picked, scope)`（brain.py:13213-13253）

- `base`（元の選択のスナップショット）に対してのみ判定（連鎖させない＝1ホップ）。
- 各 DB の `meta["relationships"]` を `parse_endpoint_cols(from/to, alias)` で `(alias, table, cols)` に分解。`from` 側テーブルが `base[from_db]` に入っていれば `to` 側テーブルを追加（方向は子 → 参照先のみ）。テーブルは `profile_db(path)["tables"]` に実在するものだけ。

#### 3.2 `_realtime_refresh(scope)`（core.py:8520-8532）

- `jobs.refresh_realtime(scope)`（core.py:6416）: `realtime_jobs()` のうち `db_file` がスコープ内かつ `table` がスコープの `tables` に含まれるものを取り込み直す。スクレイパー型は前回実行から `scrape_wait_minutes(job)`（`scrape_interval_minutes`、未設定なら `importer.scrape_defaults()[1]`＝`config.SCRAPER_MIN_INTERVAL_MIN` env 既定 30 分）経っていなければスキップ。結果を `[realtime] OK/NG db/table: message` で print。例外は握って print（質問は止めない）。

### 7. LLM へ渡す履歴 `llm.history_for_llm(messages, model, tool_defs)`（brain.py:13669-13712）

#### 7.1 手順

1. `head, blocks = _turn_blocks(messages)`（brain.py:13613）: `role=="system"` と最初の user より前のメッセージを `head`、`role=="user"` から次の `user` の手前までを1ブロック（tool_calls と tool 結果が離れないように）。
2. `len(blocks) <= config.CHAT_KEEP_TURNS_MIN`（env 既定 2）→ `messages` をそのまま返す。
3. `context, _ = models.context_window(model or config.OPENAI_MODEL)`
4. `used = Σ tokens_for(_msg_chars(m))`（head）`+ tokens_for(len(json.dumps(tool_defs)), "json")`（tool_defs があるとき）。`_msg_chars`（brain.py:13592）: content 文字列長、配列なら text 部分の長さ＋`image_url.url`（data URI）の長さ、`tool_calls` は JSON 化した長さ。
5. `left = context - used - config.CHAT_ANSWER_RESERVE_TOKENS`（env 既定 6000）。負なら 0。`room = int(left / 0.55)`（文字）。
6. ブロックごとの文字数 `sizes`。`total > room` かつ 残りブロック数 `> CHAT_KEEP_TURNS_MIN` の間、古い方から落とす（`cut` を数える）。
7. `cut == 0` → 元のまま。`cut > 0` → `head` を **コピー**し、`out[0]`（system）の content 末尾に `\n\n※ この会話は長くなったため、古い方の{cut}回ぶんのやり取りは履歴から外れています。そこで話した内容は覚えていないので、必要なら聞き直してください。` を付け、`blocks[cut:]` を連結して返す。保存側 `chat["messages"]` は変更しない（巻き戻し位置がずれないように）。

#### 7.2 `llm.drop_old_images(messages, keep_turns=None)`（brain.py:13639-13666）

- `keep = config.CHAT_KEEP_IMAGE_TURNS`（env 既定 2）。`len(blocks) <= keep` → 0。
- 古い `blocks[:len-keep]` の `role=="user"` で content が配列のメッセージについて、`image_url` パートがあれば、content を `text + "\n（この質問には画像がN枚ありましたが、会話が長くなったため履歴からは外しました。画像の中身を聞かれたら、貼り直してもらうよう伝えること）"` の **文字列**に差し替える（メッセージ自体は消さない）。戻り値は落とした枚数。これは `chat["messages"]` を直接書き換える（`_begin_turn` 内で `_persist` の前に実行され保存される）。

#### 8.4 `_create(**kwargs)`（brain.py:13087-13130）— 引数の自動調整と 429 対応

- `attempt = _apply_quirks(kwargs)`（`_QUIRKS[model] = {"set":{…},"drop":{…}}` をプロセス内で記憶）。
- `while fixes < _MAX_FIX (4)`: `client().chat.completions.create(**attempt)`。
  - 例外がレート制限（`status_code == 429` または `"rate_limit"` を含む）: `waits >= config.LLM_RATE_LIMIT_RETRIES`（env 既定 3）なら `RateLimited("混み合っています（レート制限）。…「続けて」と送ってください。…")`。そうでなければ `_rate_limit_wait(e, waits)`: `retry-after` ヘッダ秒 → `"try again in X(ms|s|m)"` を +0.5 秒 → `2**attempt`、いずれも `config.LLM_RATE_LIMIT_MAX_WAIT`（env 既定 20 秒）で頭打ち。`time.sleep` 後に再試行。
  - それ以外: `_fix_for(str(e), attempt)`（brain.py:13015）: `reasoning_effort`+`function tools` → `set reasoning_effort="none"`; `reasoning_effort`+`does not support` → 同; `reasoning_effort`+`unrecognized` → `drop reasoning_effort`; `'temperature'`/`'top_p'` + `does not support`/`only the default` → drop; `max_tokens`+`max_completion_tokens` → `set max_completion_tokens=v, drop max_tokens`。該当なし・同じ直しの繰り返し → そのまま raise。`_learn(model, ...)` で記憶し、`attempt` を組み直して再試行。
- 表ルーター（§3.1.1）・パーソナライズ抽出・AI 下書きも同じ `_create` を通る。

### 2. LLM クライアント（brain.py 旧 llm.py 部分）

#### 2-1. クライアント生成と設定判定
- `_client: OpenAI | None = None`（brain.py:12931）。プロセス内シングルトン。
- `is_configured()`（brain.py:12941-12943）: `bool(llm_chat_url() and llm_api_key())`。接続先・キーとも「モデル設定」画面の保存値 > env。
- `client()`（brain.py:12946-12954）: `OpenAI(base_url=_derived_base(llm_chat_url(), "/chat/completions") or None, api_key=llm_api_key() or "not-set")`。`_derived_base`（brain.py:12935-12938）はフルパス URL の末尾 `/chat/completions` を落として SDK 用 base_url にする。`max_retries` は指定していない（＝ OpenAI SDK 既定の自動再試行 2 回がそのまま効く。コード注記 brain.py:13046-13047「SDKも2回までは自動で投げ直す」）。
- 使うモデル名は `models.current(user)`（brain.py:2288-2298）: `prefs.get_model(user)` が `available()` に含まれればそれ、無ければ `default_model()`（brain.py:2071-2073: 管理者設定の `default` > `config.OPENAI_MODEL`）。

#### 2-2. `_create(**kwargs)` — 呼び出し口と再試行方針（brain.py:13087-13136）
`client().chat.completions.create(**attempt)` を包む唯一の入口。`chat()`／`chat_stream()`／`_ask_json()` はすべてここを通る。

**状態（プロセス寿命）**
- `_QUIRKS: dict[str, dict] = {}`（brain.py:12990）: モデル名 → `{"set": {引数: 値}, "drop": {引数, ...}}`。再起動で消える。
- `_MAX_FIX = 4`（brain.py:12992）: 1 回の呼び出しで引数を直しに行く上限。
- `_apply_quirks(kwargs)`（brain.py:12995-13001）: `drop` の引数を外し `set` を上書きしたコピーを返す。
- `_learn(model, set_=..., drop=...)`（brain.py:13004-13012）: `_QUIRKS` に記録し `print("[llm] {model} の呼び出し方を調整しました: set=... drop=...")`。

**引数エラーの自動修正 `_fix_for(message, kwargs)`（brain.py:13015-13048）** — エラー文（小文字化）を見て `(set_, drop)` を返す。上から順に判定:
1. `"reasoning_effort"` かつ `"function tools"` → `({"reasoning_effort": "none"}, None)`
2. `"reasoning_effort"` かつ `"does not support"` → `({"reasoning_effort": "none"}, None)`
3. `"reasoning_effort"` かつ `"unrecognized"` → `(None, "reasoning_effort")`
4. `'temperature'` または `'top_p'` が引用符付きで現れ、かつ `"does not support"` か `"only the default"` → `(None, その引数名)`
5. `"max_tokens"` かつ `"max_completion_tokens"` → `({"max_completion_tokens": kwargs["max_tokens"]}, "max_tokens")`（`max_tokens` が None なら該当せず）
6. どれにも当たらなければ `None`

**レート制限（429）の判定と待ち時間**
- `_RETRY_IN = re.compile(r"try again in\s+([\d.]+)\s*(ms|s|m)\b", re.IGNORECASE)`（brain.py:13051）
- `_is_rate_limit(e)`（brain.py:13054-13055）: `getattr(e, "status_code", None) == 429` または `"rate_limit" in str(e).lower()`
- `_rate_limit_wait(e, attempt)`（brain.py:13058-13076）— 優先順:
  1. `e.response.headers["retry-after"]` があれば `min(float(raw), LLM_RATE_LIMIT_MAX_WAIT)`
  2. エラー文の `try again in X(ms|s|m)` → 秒に換算し `min(sec + 0.5, LLM_RATE_LIMIT_MAX_WAIT)`
  3. 手がかり無し → `min(2.0 ** attempt, LLM_RATE_LIMIT_MAX_WAIT)`（attempt=1,2,3 → 2 秒・4 秒・8 秒）
- `class RateLimited(Exception)`（brain.py:13079-13084）: 諦めたときに投げる。文面: `"混み合っています（レート制限）。{waits}回・合計{waited_total:.1f}秒待ちましたが解消しませんでした。少し時間をおいてから「続けて」と送ってください。ここまでに取得したデータは残っています。"`

**`_create` 本体の制御フロー**
```
model = str(kwargs.get("model") or "")
attempt = _apply_quirks(kwargs)          # 学習済みの調整を適用
fixes = waits = 0; waited_total = 0.0
while fixes < _MAX_FIX:                   # 最大4回の引数修正
    try:
        return client().chat.completions.create(**attempt)
    except Exception as e:
        if _is_rate_limit(e):             # 429 は引数修正の回数に数えない
            if waits >= config.LLM_RATE_LIMIT_RETRIES:   # 既定3
                raise RateLimited(...) from e
            waits += 1
            sec = _rate_limit_wait(e, waits); waited_total += sec
            print("[llm] レート制限。{sec:.1f}秒待って投げ直します（{waits}/{RETRIES}回目）")
            time.sleep(sec); continue
        fixes += 1
        fix = _fix_for(str(e), attempt)
        if fix is None: raise             # 直し方が分からないエラーはそのまま上へ
        set_, drop = fix
        if set_ and all(attempt.get(k) == v for k, v in set_.items()): raise   # 同じ直しの繰り返し
        if drop and drop not in attempt: raise
        _learn(model, set_=set_, drop=drop)
        attempt = _apply_quirks(kwargs)
return client().chat.completions.create(**attempt)   # 13136: 修正4回を使い切った後の最後の1投（例外はそのまま上がる）
```
- 429 以外の例外（タイムアウト・5xx・接続失敗・ツール呼び出し解析エラー等）は `_fix_for` が None を返すため **再試行せず即 raise**（SDK 内部の 2 回は別）。
- 429 の待ちは既定で最大 3 回（sleep 3 回）。4 回目の 429 で `RateLimited`。

#### 2-3. `chat(messages, tool_defs=None, model=None)` — 非ストリーミング（brain.py:13715-13749）
- kwargs: `model=model or config.OPENAI_MODEL`, `messages`, `temperature=config.OPENAI_TEMPERATURE`
- `defs = tools.BUILTIN_TOOLS if tool_defs is None else tool_defs`。`defs` が真（非空）のときだけ `tools=defs`, `tool_choice="auto"` を付ける。**`[]` を渡すと `tools` キーごと省略**（＝文章でしか答えられない状態。`_append_final_answer` がこれを使う）。
- `config.OPENAI_TOP_P is not None` なら `top_p`、`config.OPENAI_MAX_TOKENS is not None` なら `max_tokens`。
- `resp = _create(**kwargs)`; `msg = resp.choices[0].message`; `msg.finish_reason = resp.choices[0].finish_reason` を後付け（`AttributeError/ValueError/TypeError` は握る）。戻り値は SDK の message オブジェクト（`.content`, `.tool_calls[i].id/.function.name/.function.arguments`, `.finish_reason`）。

#### 2-4. `class StreamedMessage`（brain.py:13752-13781）
- `chat()` の message と同じ属性形にそろえたストリーミング組み立て用オブジェクト。
- 内部クラス `_Fn(name="", arguments="")`（13759）、`_Call(id="", name="", arguments="")`（13763: `self.type = "function"`, `self.function = _Fn(...)`）。
- `__init__`（13768-13772）: `content = ""`, `tool_calls = None`, `finish_reason = None`, `_parts: dict[int, dict] = {}`（index → `{"id","name","arguments"}`）。
- `_finish()`（13774-13781）: `_parts` が空なら `tool_calls = None`、あれば `sorted(self._parts.items())`（index 昇順）で `_Call(p["id"], p["name"], p["arguments"])` のリストにする。

#### 2-5. `chat_stream(messages, tool_defs=None, model=None)` — ストリーミング（brain.py:13784-13829）
- ジェネレータ。`("text", 差分文字列)` を文字が届くたびに yield、最後に `("done", StreamedMessage)` を 1 回だけ yield。ツール呼び出しは途中経過を出さない。
- kwargs: `model=model or config.OPENAI_MODEL`, `messages`, `tools=tool_defs if tool_defs is not None else tools.BUILTIN_TOOLS`, `tool_choice="auto"`, `temperature=config.OPENAI_TEMPERATURE`, `stream=True`（＋ `top_p`／`max_tokens` は 2-3 と同条件）。**`chat()` と違い `tool_defs=[]` でも `tools=[]` をそのまま送る**（キーを落とさない）。
- チャンク処理: `for chunk in _create(**kwargs)`:
  - `chunk.choices` が空 → skip
  - `chunk.choices[0].finish_reason` があれば `out.finish_reason` に保存
  - `delta.content` があれば `out.content += delta.content` して `yield ("text", delta.content)`
  - `delta.tool_calls` の各 `tc` について: `part = out._parts.setdefault(tc.index, {"id": "", "name": "", "arguments": ""})`; `tc.id` があれば `part["id"] = tc.id`（上書き）; `tc.function.name` があれば `part["name"] += name`; `tc.function.arguments` があれば `part["arguments"] += arguments`（**index で束ね、断片は連結**）
- ループ後 `out._finish()` → `yield ("done", out)`。

#### 2-6. LLM に渡す履歴の作り方
- `user_message(text, images=None)`（brain.py:13568-13589）: 画像無しなら `{"role":"user","content":text}`。画像ありなら `content` は配列 `[{"type":"text","text":...}, {"type":"image_url","image_url":{"url":"data:<mime>;base64,<b64>","detail":"auto"}}...]`。`IMAGE_MIMES = {"image/png","image/jpeg","image/gif","image/webp"}`（13565）以外は捨てる。
- `_turn_blocks(messages)`（13613-13636）: `head`（system と最初の user より前のもの）と `blocks`（`role:user` から次の user の手前まで＝1 質問のかたまり）に分ける。落とすときは必ずこの単位（tool_calls と tool を離さないため）。
- `drop_old_images(messages, keep_turns=None)`（13639-13666）: `CHAT_KEEP_IMAGE_TURNS`（既定 2）より古いブロックの user 発言の `image_url` パートを、テキスト＋注記 `"（この質問には画像が{n}枚ありましたが、会話が長くなったため履歴からは外しました。画像の中身を聞かれたら、貼り直してもらうよう伝えること）"` の文字列に差し替える（**メッセージ自体は消さない**：巻き戻しの番号がずれるため）。戻り値は落とした枚数。`chat["messages"]` を破壊的に更新する（`_begin_turn` core.py:8568 と `rewind` core.py:8822 から呼ばれる）。
- `history_for_llm(messages, model=None, tool_defs=None)`（13669-13713）: **保存側 `chat["messages"]` は触らず控えを返す**。
  1. `len(blocks) <= CHAT_KEEP_TURNS_MIN`（既定 2）なら messages をそのまま返す
  2. `context, _ = models.context_window(model or config.OPENAI_MODEL)`（brain.py:2179-2196: 管理者登録 `context_overrides()` 完全一致→部分一致 > `config.MODEL_CONTEXT_WINDOWS` 長い名前から部分一致 > `MODEL_CONTEXT_DEFAULT`）
  3. `used = Σ tokens_for(_msg_chars(m)) for m in head` ＋ `tool_defs` があれば `tokens_for(len(json.dumps(tool_defs)), "json")`
  4. `left = max(0, context - used - CHAT_ANSWER_RESERVE_TOKENS)`; `room = int(left / TOKENS_PER_CHAR_TEXT)`（`TOKENS_PER_CHAR_TEXT = 0.55` brain.py:13504、`TOKENS_PER_CHAR_JSON = 0.31` 13506、`tokens_for` 13509-13512）
  5. 古いブロックから `total > room and len(blocks) - cut > CHAT_KEEP_TURNS_MIN` の間 `cut += 1`
  6. `cut == 0` なら messages をそのまま返す。落とした場合は head のコピーを作り、`head[0]` が system ならその `content` 末尾に `"\n\n※ この会話は長くなったため、古い方の{cut}回ぶんのやり取りは履歴から外れています。そこで話した内容は覚えていないので、必要なら聞き直してください。"` を足し、`blocks[cut:]` を連結して返す。

### 3. ツール定義と実行（brain.py 旧 tools/__init__.py 部分）

#### 3-1. 定義の組み立て `build_tools(entries, admin=False)`（brain.py:12695-12724）
- `ov = custom_tools.builtin_overrides(entries)`（管理者による無効化・説明上書き）
- `BUILTIN_TOOLS`（最終形は brain.py:12530 = 各モジュールの組み込み ＋ `KNOWLEDGE_TOOLS` ＋ `[WHOAMI_TOOL, REPORT_GAP_TOOL]`。`_RETIRED = {"plot_chart"}` は brain.py:9373-9374 で除外済み）を走査:

  - `name in ADMIN_TOOLS and not admin` → skip（`ADMIN_TOOLS` 12558 = `explore_import_files`(9989) ∪ `analyze_usage`(11448)）

  - `ov[name]["description"]` があれば description を差し替え
  - `name in SQL_TOOLS` なら `_with_explanation(t)`（12679-12692）で `explanation` 引数（`_EXPLANATION_PARAM` 12668-12676、型 string、SQL の日本語解説 3〜5 行）を properties に注入。**required には足さない**

- `custom_tools.collect_everywhere(entries)` の各ユーザー定義ツールは `validate_custom_tool(tool, set())` が空（＝問題なし）のときだけ `to_schema(tool)` で追加。

#### 3-2. 実行 `dispatch(name, arguments_json, scope, entries=None, admin=False)`（brain.py:12842-12878）
戻り値は常に `{"ok": bool, "llm_content": str(JSON), "render": dict|None, "verify_alerts"?: [alert]}`。`_err(message)`（7543-7548）は `{"ok": False, "llm_content": _json({"error": message}), "render": {"role":"assistant","kind":"error","message": message}}`。`_json` は `json.dumps(obj, ensure_ascii=False, default=str)`（7539）。

順序:
1. `json.loads(arguments_json)`（空なら `{}`）。`JSONDecodeError` → `_err("ツール引数のJSON解析に失敗しました: ...")`
2. `name in ADMIN_TOOLS and not admin` → `_err("'{name}' は管理者だけが使えます。")`（build_tools で渡していなくても守りは 2 箇所）
3. `_coerce_lists(name, args)`（12784-12799）: スキーマ上「文字列の配列」の引数（`_LIST_PARAMS`）に素の文字列が来たら 1 要素配列にする
4. `_missing_required(name, args)`（12746-12766）: `_REQUIRED[name]`（スキーマの required、12737）のうち `_HAS_DEFAULT = {"title","filename","chart_type","purpose"}`（12743）を除き、`None` または長さ 0 の str/list/dict/tuple を「欠落」と判定 → `_err("'{name}' の必須の引数が指定されていません: ...（{name} の必須引数は ...）この引数を入れて呼び直してください。列名が分からないときは、先に describe_table か run_sql_query で列を確認すること。")`
5. `_gather_sqls(args, scope, sqls)`（12802-12820）: 引数の入れ子を再帰で歩き `sql`（非空文字列）と `result_id`（→ `results.get(scope, rid)["sql"]`）を全部集める（検算用）
6. `handler = _HANDLERS.get(name)` があれば `_attach_folder_save(args, _attach_verification(handler(args, scope), sqls, scope))`。例外は `_err("ツール '{name}' の実行でエラー: {e}")`

**`class _Guard`（8131-8204）— 同じ呼び出しの見張り**
- `LIMIT = 2`（8146）: `repeated()` が呼ばれた総回数がこれに達したら打ち切り
- 属性: `failed: dict[tuple, str]`（失敗した呼び出し→理由）、`done: set[tuple]`（成功した呼び出し）、`repeats = 0`
- `key(call)`（8154-8155）: `(call["name"], (call.get("arguments") or "").strip())`。引数 JSON 文字列そのままなので空白違いは別キー
- `seen(call)`（8157-8160）: キーが `failed` または `done` にある（成功・失敗どちらも）
- `note(call, res)`（8162-8171）: `res["ok"]` なら `done.add`。それ以外は `json.loads(res["llm_content"]).get("error", "")` を理由に `failed[k]`（読めなければ `"同じ内容で失敗しました。"`）
- `repeated(call)`（8173-8194）: `repeats += 1`。前回成功なら `{"error": "この呼び出しは既に実行済みです。もう一度は実行しません。", "hint": "前回の結果はこの会話の中に残っている。それを使って、いま利用者への回答を書くこと。同じツールを同じ引数で呼び直してはいけない。本当に別の情報が要るなら、引数を変えて呼ぶこと。"}`、失敗なら `{"error": "同じツールを同じ引数で呼び直しています。実行しませんでした。", "previous_error": failed[k], "hint": "引数を直してから呼ぶこと。直せないなら、そのツールは諦めて別の方法（表だけで示す・SQLを見直す・ユーザーに確認する）に切り替える。同じ呼び出しをもう一度行ってはいけない。"}`（いずれも `json.dumps(ensure_ascii=False)` の文字列）
- `stuck`（8197-8199）: `repeats >= LIMIT`
- `stop_reason`（8202-8204）: `done` があり `failed` が空なら `_LOOP_MESSAGE`、それ以外 `_STUCK_MESSAGE`

**`_call_previews(calls, scope, question)`（8089-8128）— 実行前に画面へ出す項目**
- 各 call について `json.loads(arguments)`（`JSONDecodeError` → `{}`）、`custom = custom_tools.collect_everywhere(scope)` から同名ツール検索。
- 分岐（上から順、該当 1 件のみ）:
  1. `name in tools.SQL_TOOLS and "sql" in args` → `{"role":"assistant","kind":"sql","tool": name,"call_id": c["id"],"sql": args["sql"],"purpose": args.get("purpose",""),"explanation": args.get("explanation",""),"question": question,"tables": tables_in_sql(args["sql"], scope)}`
  2. `custom is not None` → 同じ `kind:"sql"` 形で `sql = tools.render_sql(custom)`, `purpose = f"{description[:60]} / 引数: {k=v!r, ...}"`（引数なしは `"（引数なし）"`）, `explanation = custom["description"]`（AI の解説ではなく登録時の説明）, `call_id`, `tables`
  3. `name == "describe_table"` → `{"role":"assistant","kind":"text","content": f"🛠 テーブル詳細を確認: `{table}`","tables": [{"db": owner["name"], "table": table}]}`（`db` 省略時は `scope[0]`）
  4. その他のツール → プレビュー無し
- `tables_in_sql(sql, scope, limit=6)`（7474-7498）: scope の各表名が `alias.table` または裸の表名として SQL に現れるかを正規表現で判定し `[{"db": s["name"], "table": name}]` を最大 6 件。

#### 4-3. `_advance(chat, scope, question)` — 非ストリーミング版（8241-8295）
```
guard = _Guard(); retried_empty = False
for _ in range(config.MAX_AGENT_STEPS):                      # 既定10
    try:
        defs  = tools.build_tools(scope, admin=_is_admin())   # 毎回作り直す
        model = models.current(g.user)
        msg   = llm.chat(llm.history_for_llm(chat["messages"], model, defs), defs, model=model)
    except Exception as e:
        render_log.append({"role":"assistant","kind":"error","message": _friendly_llm_error(e)})
        return                                                 # 終了5: LLM 例外（最終回答なし）
    messages.append(_msg_to_dict(msg))
    if msg.content: render_log.append({"role":"assistant","kind":"text","content": msg.content})
    calls = _extract_calls(msg)
    if not calls:
        if (msg.content or "").strip():
            _note_if_cut(chat, msg); return                    # 終了1: 正常な最終回答
        messages.pop()                                         # 空の assistant を履歴から消す
        if not retried_empty:
            retried_empty = True; continue                     # 終了2a: ツール付きのまま1回だけ聞き直す（for を1つ消費）
        if _append_final_answer(chat) is None:
            render_log.append(_stop_note(_EMPTY_MESSAGE))      # 終了2b
        return
    fresh = [c for c in calls if not guard.seen(c)]
    render_log.extend(_call_previews(fresh, scope, question))  # 未実行の呼び出しだけプレビュー
    _execute(chat, calls, scope, guard)                        # 全 calls（seen は差し戻し）
    if guard.stuck:
        _append_final_answer(chat)
        render_log.append(_stop_note(guard.stop_reason)); return   # 終了3
_append_final_answer(chat)
render_log.append(_stop_note(_LIMIT_MESSAGE))                  # 終了4: 往復上限

- 空応答の `continue` は for のイテレーションを 1 つ消費する（空応答が 1 回あると実質 9 往復）。

#### 4-4. `_execute(chat, calls, scope, guard=None)`（8406-8435）— ツール実行と検算アラート

- `_fresh_alerts(chat, alerts)`（8396-8403）: `render_log` 内の `verify_key` 集合に無い `a["key"]` だけ残す（同じ警告を会話内で繰り返さない。key にデータ版が入るのでデータが変われば再度 1 回出る）。

#### 4-5. 最終回答の補助
- `_note_if_cut(chat, msg)`（8338-8348）: `getattr(msg, "finish_reason", None) != "length"` なら None。`"length"` なら `_stop_note(_CUT_MESSAGE)` を render_log に積んで返す。
- `_append_final_answer(chat)`（8351-8380）: ツール無しで最後にもう 1 回だけ書かせる。
  - `llm.chat(llm.history_for_llm(chat["messages"], models.current(g.user)) + [{"role":"user","content": "ここまでの会話をふまえて、直前の質問に日本語で答えてください。ツールは使えません。すでに得られた結果があれば、それだけを根拠に簡潔に答えること。必要な情報が得られていない場合は、憶測で埋めず「うまく処理できませんでした。もう一度質問してください」とだけ伝えること。内部の仕組み（ツール名・データベースの構成・システムの状態）を説明してはいけない。"}], [], model=models.current(g.user))` — **第 2 引数 `[]`（= `tools` キーを送らない）**
  - 例外 → `print("[chat] 最後の回答をまとめられませんでした: ...")` して None。本文空 → None。
  - 成功時: `messages.append(_msg_to_dict(msg))`（**注入した user 発言は履歴に残さない**）、`render_log.append({"role":"assistant","kind":"text","content": text})` して返す。
- `_friendly_llm_error(e)`（8309-8327）: `str(e).lower()` を見て
  1. `"error parsing tool call"` → 「モデルの応答が途中で乱れたため、処理を続けられませんでした。もう一度送ってください（ローカルのモデルではまれに起きます）。」
  2. `"out of memory"` or `"cudamalloc"` → 「ローカルLLMのメモリが足りず、応答を作れませんでした。少し待ってからもう一度送ってください。」
  3. `"timed out"` or `"timeout"` → 「モデルの応答が時間内に返りませんでした。もう一度送るか、質問を短く分けてください。」
  4. それ以外（`RateLimited` も含む）→ `f"LLM呼び出しに失敗しました: {s[:160]}"`

#### 4-6. `_stream_advance(chat, scope, question)` — ストリーミング版（8622-8707）
- `_sse(event, data)`（8618-8619）: `f"event: {event}\ndata: {json.dumps(data, ensure_ascii=False, default=str)}\n\n"`
- SSE イベント（`stream()` docstring 8711-8717 と実装から）:

| event | data | 出る場所 |
|---|---|---|
| `delta` | `{"text": 差分}` | `llm.chat_stream` が `("text", …)` を返すたび（8636） |
| `text_end` | `{}` | 1 回分の本文が終わった時点。tool_calls の有無にかかわらず出す（8654, 8673） |
| `item` | `_web_log([item])[0]`（描画アイテム 1 件） | LLM エラー（8643）、切れ注記（8658）、最終回答／空応答注記（8666-8671）、SQL プレビュー（8677-8678）、ツールの描画物・検算カード（8689-8690）、打ち切り時の回答と停止注記（8694-8699）、上限時（8702-8706） |
| `running` | `{"name": ツール名, "label": TOOL_LABELS.get(name, name)}` | 1 ツールを実行する直前（8684-8685）。差し戻し（seen）では出ない |
| `end` | `{"chat_id", "title"}` | `generate()` の finally、`_persist` 後（8754-8755）。中断時は出ない |

ループ本体は `_advance` と同型で、違いは:
- LLM 呼び出しが `llm.chat_stream(llm.history_for_llm(messages, model, defs), defs, model=model)` で、`kind == "text"` なら `delta` を yield、`"done"` なら `msg = payload`（8631-8639）。例外時は `kind:"error"` item を積んで yield して return。`msg is None`（done が来なかった）なら return（8646-8647）
- `calls` が無いときは `text_end` → 本文ありなら `_note_if_cut` の結果を item で流して return。空応答は `messages.pop()` → 1 回目 `continue` → 2 回目 `_append_final_answer` の item か `_EMPTY_MESSAGE` の item
- `calls` があれば `text_end` → `fresh` のプレビューを render_log に積み 1 件ずつ item → 各 call について: `guard.seen(c)` なら `_execute(chat, [c], scope, guard)`（差し戻しのみ・イベント無し）、そうでなければ `running` → `before = len(render_log)` → `_execute(chat, [c], scope, guard)` → `_web_log(render_log, before)` の新規分を item で流す（**1 呼び出しずつ実行・逐次描画**）
- `guard.stuck` → `_append_final_answer` の item（あれば）→ `guard.stop_reason` の item → return
- for を抜けたら `_append_final_answer` の item（あれば）→ `_LIMIT_MESSAGE` の item

#### 4-7. `POST /api/chat/stream`（8708-8760）— GeneratorExit と保存

    try:
        yield from _stream_advance(chat, scope, text)
    except GeneratorExit:                                     # 画面を閉じた／更新した
        aborted = True; raise
    except Exception as e:                                    # 途中で落ちても接続は閉じる
        yield _sse("item", {"role":"assistant","kind":"error","message": _friendly_llm_error(e)})
    finally:
        _persist(chat)                                        # 進んだところまで必ず保存
        _schedule_memory(user, chat)                          # 別スレッド。end は待たない
        if not aborted:
            yield _sse("end", {"chat_id": chat.get("id"), "title": chat.get("title", "")})
return Response(stream_with_context(generate()), mimetype="text/event-stream",
                headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"})
```
- 会話ロック: `_hold_chat(cid)`（7881-7898）は `chats.lock_for(user, cid)`（1090-1101、会話ごとの `RLock`）を `CHAT_LOCK_WAIT_SEC`（120 秒）まで待って取得し `g._chat_lock` に置く。待ちきれなければ print して続行。解放は `app.teardown_request(_release_chat)`（15574、`_release_chat` 7901-7908）。
- 切断後に保存された内容は、ブラウザ側が `end` を受け取らないため、`missed` フラグ付きで `openChat(chat_id)` により保存済みの完成形を読み直す設計（assets.py:7566-7577）。
- 切断で `tool_calls` に対する `tool` が欠けた履歴は、保存時／読込時の `heal_messages`（1264-1296）が丸ごと落として 400 を防ぐ。

#### 4-8. 回答後の `_schedule_memory(user, chat)`（2144-2157）— パーソナライズの書き直し
- 条件: `user is not None` かつ `memory_enabled(user)`（2014-2016: `memory_settings()["enabled"]`（1692-1715、`data/memory_settings.yaml` > config）かつ本人の `prefs.memory_off` が偽）かつ `llm.is_configured()`。

#### 6-3. `_persist(chat)`（7926-7971）
1. `render_log` が空で `id` も無ければ何もしない（話すまでファイルを作らない）。既存の会話は空でも保存（巻き戻しで全消ししたときの復活防止）
2. `id` が無ければ `chats.new_id()` を採番し `_hold_chat`
3. `db_names` = 既存 ∪ `render_log` の `kind=="sql"` アイテムの `sql` から `db.dbs_named_in(sql)` で集めた DB 名（sorted）
4. `table_names` = 既存 ∪ 各 DB の `catalog.profile_db(path)["tables"]` の表名を `(?<!\w)表名(?!\w)`（IGNORECASE）で SQL に当てて拾った `"{db}.{table}"`（sorted）。プロファイル失敗は無視
5. `saved = chats.save_chat(g.user, id, messages, render_log, db_names=..., tables={}, table_names=..., title=..., created_at=...)`
6. `saved["deleted"]` なら `session["chat_id"]` を外して返す。そうでなければ `session["chat_id"] = id`、`chat["title"], chat["created_at"] = saved["title"], saved["created_at"]`

### 9. 1 問の時系列（ストリーミング経路）

1. ブラウザ `sendStreaming` → `POST /api/chat/stream {text, images:[token]}`
2. `_begin_turn`: 検証 → `rag.set_current_user` → `results.new_turn` → 会話ロック＆読込 → user 発言を messages/render_log に積み **保存** → `_auto_scope`（必要なら表ルーター LLM 呼び出し）→ `_realtime_refresh` → system prompt 作り直し
3. 会話 ID 確定・`session["chat_id"]`・`turn_id` 捕捉 → `Response(stream_with_context(generate()))`
4. `generate`: threading.local を入れ直し → `_stream_advance`:
   - 往復ごとに `build_tools` → `history_for_llm` で文脈に収める → `chat_stream` → `_create`（引数自動修正 ≤4 回、429 待ち ≤3 回、その他は即エラー）→ `delta` 逐次 → `text_end`
   - tool_calls あり: `_call_previews`（未実行分）→ 各 call: `running` → `_execute`（`_Guard` 判定 → `dispatch` → 検算 → tool メッセージ → render）→ `item`
   - 終了条件: 本文のみ（＋length 注記）／空応答（1 回再試行→ツール無し再回答→`_EMPTY_MESSAGE`）／`_Guard.stuck`（2 回目の同一呼び出しで打ち切り→ツール無し再回答→`_LOOP_MESSAGE`/`_STUCK_MESSAGE`）／`MAX_AGENT_STEPS` 到達（→ツール無し再回答→`_LIMIT_MESSAGE`）／LLM 例外（`_friendly_llm_error`）
5. finally: `_persist`（db_names/table_names 集計 → `save_chat` → index 更新）→ `_schedule_memory`（別スレッドで `extract_memory`）→ 中断でなければ `end`
6. teardown で会話ロック解放。ブラウザは `end` で `refreshHistory()`／`scheduleMemoryRefresh()`。

### 5. `dispatch(name, arguments_json, scope, entries=None, admin=False)`（`brain.py:12842-12878`）— 実行の全段

戻り値は常に `{"ok": bool, "llm_content": str, "render": dict|None}`。検算で不一致があったときだけ第4キー `"verify_alerts": [alert]` が付く。

| 段 | 処理 | 失敗時の戻り |
|---|---|---|
| 1 | `args = json.loads(arguments_json) if arguments_json else {}` | `json.JSONDecodeError` → `_err("ツール引数のJSON解析に失敗しました: {e}")` |
| 2 | `if name in ADMIN_TOOLS and not admin` | `_err("'{name}' は管理者だけが使えます。")`（「守りは2箇所で持つ」＝build_tools と dispatch） |
| 3 | `args = _coerce_lists(name, args)`（`12784`） | 失敗なし（破壊的に同じ dict を書き換える） |

| 6b | 無ければ `custom_tools.collect_everywhere(entries or [])` から `name` 一致を探す。無ければ `{"ok": False, "llm_content": _json({"error": f"未知のツール: {name}"}), "render": None}`（`_err` ではなく render None） | — |

補足: `_HANDLERS` を先に引くので、組み込みと同名のユーザー定義ツールは組み込みが勝つ。`builtin_tools.enabled: false` は `build_tools` だけが見て `dispatch` は見ない（履歴から名指しで呼ばれれば実行される）。`ADMIN_TOOLS` のみ2段構え。

#### 5-1. `_coerce_lists(name, args)`（`12784-12799`）
- `_LIST_PARAMS.get(name)` に載る引数について、値が `str` なら `[v.strip()]`（空文字なら `[]`）に直す。
- 対象は `BUILTIN_TOOLS` 由来のトップレベル引数のみ（入れ子の `sheets.items.chart.value_columns` などは対象外、ユーザー定義ツールも対象外）。
- 例（宣言から）: `pivot_table.index`、`analyze_stats.columns/control`、`regression.features`、`clustering.features`、`funnel_analysis.steps/labels`、`compose_email.to/cc/bcc/attach_filenames`、`data_quality.tables`、`search_knowledge_base.knowledge_bases`、`build_report.summary/recommendations/caveats`、`export_docx.summary/caveats`、`distribution_analysis.fit`、`plot_*` の `path/dimensions`、`_INLINE_COLUMNS` が付いた各ツールの `columns`。docstring は「13個ある同じ形の引数すべてに効く」と述べる。
- 理由（docstring）: `index="地域"` のように素の文字列で来ると1文字ずつに散り「『地』という列がありません」になる。

#### 5-2. `_missing_required(name, args)`（`12746-12764`）
- `_REQUIRED[name]` を回し、`_HAS_DEFAULT = {"title","filename","chart_type","purpose"}`（`12743`）はスキップ。
- 値が `None`、または `str/list/dict/tuple` で `len == 0` のものを不足とする。`0` / `False` は正しい値として通す。
- `_allow_result_id` が `required` から `sql` を抜いているので、`sql` の欠落はここでは検知されず `fetch()` の `AnalysisError` が出す。
- 実効的に検査される必須引数（`required` − `sql` − `_HAS_DEFAULT`）: run_sql_query=なし / plot_dual_axis=x,bar_y,line_y / pivot_table=index,values / analyze_stats=method / export_excel=sheets / export_csv=files / export_text=body / hypothesis_test=method / regression=target,features / distribution_analysis=target / forecast=time_col,value_col / timeseries_analysis=time_col,value_col / monte_carlo_simulation=formula,variables / scenario_analysis=formula,scenarios / bootstrap_estimate=target / clustering=features / abc_analysis=label_col,value_col / export_pptx=slides / build_report=sections / export_docx=sections / find_mail_recipients=なし / compose_email=subject,body / compare_periods=period_col,value_col / data_quality=なし / detect_anomalies=time_col,value_col / funnel_analysis=steps / cohort_analysis=id_col,period_col / market_basket=transaction_col,item_col / survival_analysis=duration_col / explore_import_files=なし / propose_glossary_term=term,description,how / propose_example=question,summary / show_er_diagram=なし / open_table=table / analyze_usage=method / describe_table=table / plot_comparison=x,y / plot_trend・plot_composition・plot_distribution・plot_relationship=なし / plot_kpi=value / search_knowledge_base=query / who_am_i=なし / report_gap=kind,what。

#### 5-3. `_gather_sqls(node, scope, acc)`（`12802-12820`）
- dict を再帰: キー `"sql"` で非空文字列 → `acc.append(v)`；キー `"result_id"` で非空 → `_results.get(scope, v)` を引き `entry["sql"]` があれば append；それ以外は値へ再帰（list も辿る）。
- ハンドラ実行**前**に走る（そのツール自身が新しく預ける result_id は拾わない）。ユーザー定義ツールだけは実行直前に `render_sql(tool)`（`:name` 未置換）を足す。

#### 5-4. `_attach_verification(res, sqls, scope)`（`12823-12839`）
- `not res.get("ok") or not sqls` → そのまま返す。
- `verify.alerts_for(sqls, scope)`（`core.py:4074`）を呼び、例外は `print("[verify] 検算でエラー（回答は続行）")` して `res` を返す。alerts があれば `res["verify_alerts"] = alerts`。

#### 5-5. `_attach_folder_save(args, res)`（`12881-12912`）
- `args.get("save_to_folder")` が真で、`res["render"]["kind"] == "file"` かつ `render["data"]` があるときだけ。
- `importer.save_to_user_folder(_current_user(), filename or "file", data, stamp=args.get("folder_stamp") is not False, overwrite=bool(args.get("folder_overwrite")))`（`core.py:5212`）: 出力先 `output_dir()`（`core.py:5134`、env `OUTPUT_DIR` 既定 `""`／画面保存値優先）＋ `user_folder_name(user)`（`5201`: 禁止文字 `_BAD_NAME_CHARS` を `_`、64文字）。`stamp=False` なら `_STAMP_RE`（`5209`）で末尾の `_YYYYMMDD_HHMM` を外す。既存ファイルは `overwrite` なら置換、でなければ `_2, _3…`。tmp に書いて `os.replace`。
- 成功: `render["saved_to"]`, `render["replaced"]`、`llm_content` の JSON に `"folder": "フォルダにも保存した: {path}（前のファイルを置き換えた）"`。失敗: `render["save_error"]`、`"folder": "フォルダへの保存は失敗（ダウンロードはできる）: {e}"`。`llm_content` が JSON でなければ触らない。
- ロボット実行は `FOLDER_TOOLS` に対し `save_to_folder` / `folder_stamp` / `folder_overwrite` をロボットの設定で上書きする（`core.py:9958-9966`）。

#### 5-6. `_err(message)`（`brain.py:7543`）
```
{"ok": False, "llm_content": _json({"error": message}),

```

### 6. ユーザー定義ツール（`custom_tools`、`brain.py:7147-7370`）

- 定義の形: `{"name","description","parameters":[{"name","type","description","required"}],"sql","render","chart","enabled"}` を各 DB の `.meta.yaml` の `tools:` に保存。収集時に `owner`（alias）と `owner_file`（ファイル名）を付ける。
- 定数: `RENDER_KINDS = ("table","chart","chart_dual","excel","csv","none")`（`7147`）、`PARAM_TYPES = ("string","integer","number","boolean")`（`7148`）、`_NAME_RE = ^[A-Za-z][A-Za-z0-9_]{0,47}$`（`7151`）、`_BIND_RE = (?<!:):([A-Za-z_][A-Za-z0-9_]*)`（`7153`、`::` は型キャストとして除外）。
- `collect_everywhere(selected=None)`（`7311`）: `db.list_db_files()` 順に全 DB の meta を読み、dict でないもの・名前空・重複（先勝ち）・`enabled is False` を除外。`selected` があれば `dbs_named_in(sql)`（`core.py:175`）が名指しする DB（名指し無しは置き場 DB とみなす）が1つも選ばれていないツールを外す。
- `validate_custom_tool(tool, existing_names)`（`7194`）: 名前（正規表現・`builtin_names()`（`7160`、最終 `BUILTIN_TOOLS` から）・既存名と重複）、説明必須、SQL 必須、パラメータ名 `^[A-Za-z_][A-Za-z0-9_]*$`・重複・型、SQL の `:名前` と定義の双方向対応（`bind_names`, `7184`）、`render` の妥当性、`chart` なら `chart.chart_type ∈ charts.CHART_TYPES` と `charts.required_fields(ct)`、`chart_dual` なら `chart.x` / `chart.bar_y` / `chart.line_y`。
- `to_schema(tool)`（`7264`）: `{"type":"function","function":{"name","description","parameters":{"type":"object","properties":{name:{"type","description"}},"required":[required!=False のもの]}}}`。
- `coerce_params(tool, args)`（`7285`）: 定義された型へ変換（integer→int, number→float, boolean→`1/0`（`True`/`"true"`/`"1"`/`"yes"`）, それ以外 str）。値 `None` は `None`（NULL バインド）。変換不能は `ValueError("パラメータ '{pn}' を {t} として解釈できません: ...")`。
- `render_sql(tool)`（`12561`）= `tool["sql"].strip()`（置換しない）。
- `_run_custom(tool, args, scope)`（`12566-12654`）:
  1. `coerce_params` の `ValueError` → `_err`。
  2. `scope = db.widen_scope(sql, scope)`。
  3. 上限 `cap = min(config.EXPORT_MAX_ROWS, 1_048_575)` if render ∈ {excel, csv} else `None`（＝`run_select` 既定 2,000）。
  4. `db.run_select(sql, scope, params=params, max_rows=cap)`。失敗 → `_err(f"ツール '{name}' のSQL実行エラー: {e}")`。
  5. `rid = _results.put(scope, columns, rows[:MAX_RESULT_ROWS], truncated or len(rows)>len(keep), sql=sql, label=f"{name}（ユーザー定義ツール）")`。
  6. `llm_content = {"tool","columns","row_count","truncated","rows": 先頭 SAMPLE_ROWS_FOR_LLM 行,"result_id","note"}`。
  7. render 分岐: `none` → `render: None` / `excel`・`csv` → `excel.build_excel([sheet], title=description)` または `exports.build_csv(columns, rows, chart.encoding or DEFAULT_ENCODING)` → `llm_content = {"status":"file_ready","tool","filename","columns","row_count","note"}`、`render = {"kind":"file","filename","mime","data","sheets":[_preview_rows(...)]}`（失敗 `_err("ファイルの作成に失敗しました: ...")`）/ `chart` → `chart.x`,`chart.y` が結果列に無ければ `_err` → `render kind "chart"`（`chart_type` 既定 `"bar"`, x, y, color, barmode, title）/ `chart_dual` → `x`＋`bar_y`＋`line_y` 検査 → `render kind "chart_dual"` / それ以外 → `render kind "table"`（columns, rows, truncated）。

### 7. データ取得の共通経路（`brain.py:7539-7800`）

#### 7-1. `fetch(spec, scope, *, label=None, max_rows=None)`（`7619-7690`）
戻り値 `(columns, rows, truncated, result_id, total_rows)`。判定順:

1. `spec["rows"] is not None` かつ（`rows` が真 または `sql`/`result_id` がどちらも空）→ `_inline_table`（`7565`）。`rows: []` と `sql` が同時に来たら SQL を採る（雛形ごと `rows: []` を付けてくる実測対策）。
2. `rid = spec["result_id"].strip()`。無ければ `results.find_by_sql(scope, spec["sql"])` で補い、ヒット時 `print("[results] 同じSQLなので実行し直しません（{rid} を使い回します）")`。
3. `rid` あり: `results.get(scope, rid)` が `None` → `AnalysisError("result_id '{rid}' のデータが見つかりません。古くなって捨てられたか、別の会話の結果です。sql を指定して取り直してください。")`。`max_rows and entry["truncated"] and entry["sql"] and max_rows > len(entry["rows"])` なら元 SQL で `db.run_select(sql, db.widen_scope(sql, scope), max_rows=max_rows)` を取り直し（total は `_total_rows`）。それ以外は預かりをそのまま返す（total `None`）。
4. `sql` 空 → `AnalysisError("sql と result_id のどちらも指定されていません。...")`。
5. `scope = db.widen_scope(sql, scope)` → `db.run_select(sql, scope, max_rows=max_rows)` → `keep = rows[:config.MAX_RESULT_ROWS]` → `rid = results.put(scope, columns, keep, truncated or len(rows)>len(keep), sql=sql, label=label)` → `total = _total_rows(sql, scope) if truncated else None`。

`_inline_table`（`7565-7616`）: `rows` が list でなければ `AnalysisError`。`columns` は list/tuple のときだけ採用。dict の配列なら出現順に鍵を集める、配列の配列なら幅を揃え `列1, 列2…` を補う。`cap = max_rows or MAX_RESULT_ROWS` で切り、`results.put(..., sql=None, label=label or "AIが組み立てた表")`。戻り total は `len(raw) if truncated else None`。

`_total_rows(sql, scope)`（`7551`）: `SELECT COUNT(*) FROM ({sql})` を `max_rows=1` で実行、失敗は `None`。

#### 7-2. `source_note` / `render_source_note`（`7693`, `7707`）
- LLM 向け: `{"source_row_count","source_truncated"}` ＋ 切り詰め時 `{"source_total_rows", "warning": "上限 {cap or MAX_RESULT_ROWS:,} 行で切り詰めました。実際は {total:,} 行あります。この結果は全体の一部です。全体を語るなら、SQL側でGROUP BY で集計するか、条件を絞って取り直してください。"}`。

### 8. SQL 実行の安全機構（`fetch` → `db.run_select`、`core.py:140-560`）

- `validate_select(sql)`（`core.py:294`）: 空 → `ValueError("SQLが空です。")`；`_trim_tail`（前後空白と末尾 `;`）；検査用コピーは `_blank_quoted`（`_QUOTED`, `266`、引用符の中身を空に）→ `_strip_sql_comments` → `_trim_tail`；`";" in probe` → 「複数ステートメントは実行できません」；先頭が `select`/`with` 以外 → 「SELECT文(または WITH ... SELECT)のみ実行できます。」；`_FORBIDDEN`（`252`: insert|update|delete|drop|alter|create|truncate|attach|detach|reindex|vacuum|pragma|grant|revoke|begin|commit|rollback|savepoint|merge）または `_REPLACE_INTO`（`257`）→ 「書き込み・DDL系のキーワード '...' は使用できません」；`_SCHEMA_TABLE`（`262`: sqlite_master/schema/temp_master/temp_schema/sequence/stat*, pragma_*）→ 「SQLiteの管理表 '...' は読めません。…」。実行するのはコメントを残した元 SQL。
- `run_select(sql, scope, max_rows=None, timeout_s=None, params=None)`（`483`）: `scope` 空 → `ValueError("対象のDBがありません。SQLは実行できません。…sql の代わりに rows で表をそのまま渡して呼び直すこと。…")`。`max_rows = max_rows or config.MAX_RESULT_ROWS`、`timeout_s = timeout_s or config.QUERY_TIMEOUT_SEC`。`use = narrow_scope(safe_sql, scope)`（`209`）。`allowed` = scope 要素の `tables` の和集合（`tables` が空/None の要素が1つでもあれば `None`＝制限なし）。`connect_scope`（`157`: `file::memory:` を main に、各 DB を `?mode=ro` で ATTACH、上限 `MAX_ATTACHED = 10`）。`set_authorizer(_make_authorizer(allowed, _view_closure(...)))`（`395`, `350`: 許可アクション `SQLITE_SELECT/READ/FUNCTION(+RECURSIVE)`、`sqlite_` で始まる表の READ は常に DENY、`allowed` 外の表は DENY、ビュー経由のみ通す）。`set_progress_handler(10000命令ごと, 経過 > timeout_s で中断)`。`sqlite3.Error` は `explain_error(e)`（`460`、`_MISSING_FUNC_HINTS` 24語の対応表、`no such column` → describe_table 案内、`syntax error` → 専用ツール案内）で包み直す。`fetchmany(max_rows + 1)` で `truncated = len(rows) > max_rows`。
- `widen_scope(sql, scope)`（`185`）: SQL が `alias.` で名指しする DB を `{"path","alias","name","tables": None}` として追加（`MAX_ATTACHED` まで）。`connect_ro(path)`（`144`）は単一 DB の読み取り専用接続（timeout 30 秒、プロファイリング用）。

### 12. 各ツール実処理の要点（追加の分岐・上限）

- **グラフ（`_plot_chart`）**: `fetch(args, scope, label=title)` → `item = {k: args.get(k) for k in _CHART_FIELDS}`、`chart_type` 既定 `"bar"` → `charts.validate(item, columns)`（`brain.py:3795`: 未知種別／`required_fields`（`3791`）の欠落・列不在／`LIST_FIELDS=("path","dimensions")`／任意指定 color,size,text,y2,z,lower,upper,target,facet の存在。`target` は数値なら列名扱いしない）。`CHART_SPECS`（`3712-3774`）は 54 種（比較12・推移11・構成8・分布8・関係12・指標3）。
- **`pivot_table`**: `analysis.pivot(columns, rows, index, cols=pivot_col, values, aggfunc(既定 "sum", `AGG_FUNCS`: sum/mean/count/median/min/max/std/nunique), margins, percent(`PERCENT_MODES`: row/column/total), rank_by)`。
- **`analyze_stats`**: `method` ∈ describe/correlation/outliers。outliers は `target` 必須（`_err("outliers には target（外れ値を調べる数値列）が必要です。")`）、`outlier_method` 既定 `"iqr"`（`OUTLIER_METHODS_EXT`: iqr/zscore/modified_zscore/percentile/mahalanobis）、カンマ区切りで複数列。
- **stats**（`11317-11393`）: `hypothesis_test`（`method` ∈ `TEST_METHODS`: ttest_1samp/ttest_ind/ttest_rel/mannwhitney/wilcoxon/anova/kruskal/chi2…、`alternative` 既定 two-sided）、`regression`（`method` 既定 ols ∈ ols/logistic/poisson）、`distribution_analysis`（bins 既定 20、`fit` ∈ norm/lognorm/expon/gamma/uniform/triang）、`forecast`（periods 既定 6、method 既定 auto ∈ auto+naive/drift/moving_average/linear/holt/holt_winters/arima）、`timeseries_analysis`（window 既定 3）、`bootstrap_estimate`（statistic 既定 mean ∈ mean/median/std/sum/p90、trials 既定 5000）、`clustering`（k 既定 3、"auto" 可）、`abc_analysis`（thresholds 既定 [70, 90]）、`monte_carlo_simulation`（trials 既定 10000、sql 任意→`_select_for`）、`scenario_analysis`（SQL なし）。
- **business**（`9391-9425`）: `compare_periods`、`funnel_analysis`（steps）、`cohort_analysis`（max_periods 既定 12）、`market_basket`（min_support 既定 1.0、top 既定 25）、`detect_anomalies`（window 既定 7、threshold 既定 3.0、changepoints 既定 True）、`survival_analysis`。`data_quality`（`9513`）: `_MAX_TABLES = 12`、`tables` は `表名` / `alias.表名` どちらでも、問題の深刻度: 0行→高、主キー重複→高、主キー無し→中、列が全て空→中、NULL ≥ 30%→中、空文字 ≥ 10%→低、値1種類→低、参照整合性の孤児→高。
- **`explore_import_files`**（`9971`）: `file` があれば `_preview`（`9882`: `importer.is_within_allowed`、`rows` 1〜`_MAX_PREVIEW_ROWS=20`（既定5）、`header_row`、`sheet`）、無ければ `_listing`（`9764`: `importer.allowed_dirs()`、`path` は `is_allowed_dir`、`recursive`、`pattern`、`only_not_imported`、`check`（`_MAX_CHECK=20` 件まで `filecheck.inspect_file`）、表示 `_MAX_ROWS=300` 件、対応拡張子 `config.IMPORT_EXTENSIONS = (".csv",".tsv",".txt",".xlsx",".xlsm")`）。`importer.ImportError_` / `PermissionError` / `OSError` を `_err` に。
- **`analyze_usage`**（`11425`）: `usage.analyze(method, days, user)`、`method` ∈ `usage.METHODS`（summary/users/trend/tools/databases/errors/questions）＋ `"imports"`。
- **`export_excel`**: シートごと `fetch(sh, scope, label=name, max_rows=min(EXPORT_MAX_ROWS, 1_048_575))`、`chart`（dict）/`charts`（list）を `excel.build_excel(built, title=purpose or filename)` へ（`ValueError` → `_err("Excelのグラフを作れませんでした: ...")`）、`filename = exports.safe_filename(filename, "xlsx")`（`3390`: 禁止文字→`_`、末尾 xlsx/csv/txt/md/zip 除去、80文字、`_%Y%m%d_%H%M` 付加）。
- **`export_csv`**: `encoding` 既定 `exports.DEFAULT_ENCODING = "utf-8-sig"`（`ENCODINGS`: utf-8-sig/utf-8/cp932）、`delimiter` 既定 `"comma"`（`EXPORT_DELIMITERS`: comma/tab/semicolon）、各ファイル `fetch(..., max_rows=EXPORT_MAX_ROWS)`。
- **`export_text`**: `format` 既定 `"md"`、節ごと `fetch(..., max_rows=EXPORT_MAX_ROWS)` → `exports.table_to_text(columns, rows, "markdown"|"plain")` を `{{heading}}` の位置に差し込み（無ければ末尾追記）。
- **`export_pptx`**: `_slide_from_sql`（`10836`）が kind ∈ {table, chart} かつ sql/result_id のスライドだけ `fetch`（0行は `PptxReportError`）、chart は `category_column`（既定 columns[0]）/`value_columns`（既定 残り全列）/scatter を series に変換。`pptx_report.build_pptx(built, title, subtitle, footer)`、`SLIDE_KINDS`（`5151`）= title/agenda/section/message/table/chart/kpi/compare/closing、`PPTX_MAX_TABLE_ROWS = 12`（`5168`）。ファイル名 `pptx_safe_filename`（日時なし）。

### 13. 検算（相互検証、`core.py:3896-4165`）

- ルール: 各 DB の `.meta.yaml` `checks:` → `normalize`（`3908`）: `{"name"(既定 "検算"), "left":{"label"(既定 "左"),"sql"}, "right":{"label"(既定 "右"),"sql"}, "tolerance_pct"(既定 `DEFAULT_TOLERANCE_PCT = 0.5`、負は 0), "drilldown", "enabled"}`。左右 SQL 空は落とす。
- `checks_for(scope)`（`3934`）: scope 各要素の `meta`（無ければ `catalog.load_meta`）から有効なもの、`owner = alias`。
- `tables_in(sql, scope)`（`3951`）: scope の `tables` 名を正規表現（`alias.表` / 素の表名）で照合し `{(alias, table)}`。
- `run_check(check, scope, use_cache=True)`（`4014`）: キー `(_fingerprint(check), _data_version(check, scope))`（`_data_version` = 関係 DB ファイルの `st_mtime_ns` の組）。`_scalar`（`3972`: 1行1列、None→0.0、`float`）で左右を取り、失敗は `ok_run False, error`。`diff = lv - rv`、`base = max(|lv|,|rv|)`、`pct = |diff|/base*100`（base 0 なら 0.0）、`match = pct <= tolerance_pct`。不一致かつ `drilldown` があれば `run_select(drilldown, scope, max_rows=DRILL_ROWS=8)` を `drill` に（失敗は `drill.error`）。結果は `_verify_cache`（`_CACHE_MAX = 300` 超で全消去、`4059`）。`version` は `_version_key`（md5 8桁）。
- `alerts_for(sql_texts, scope)`（`4074`）: 空文字を除いた SQL・scope・ルールが無ければ `[]`。`touched = ∪ tables_in(sql)`。各ルールで `involved = tables_in(left.sql + " " + right.sql)` が `touched` と交わるものだけ `run_check`。`not ok_run or match` は無言。alert = `{"key": f"verify||{owner}||{name}||{_check_key}||{version}", "name","left_label","left","right_label","right","diff","pct","tolerance_pct","drill"}`。集めた SQL 自体は実行しない（ユーザー定義の `:name` 入りでも害なし）。
- LLM への到達: `_execute` → `_fresh_alerts`（`8396`: `render_log` の `verify_key` 既出を除外）→ `_merge_alerts`（`8383`: `llm_content` が JSON dict なら `"verification_warnings": [verify.llm_note(a)]` を追加、そうでなければ末尾に `"\n\n【検算の不一致】" + json`）。`llm_note`（`4125`）= `{"check", <left_label>: left, <right_label>: right, "difference", "difference_pct", "instruction": "この2つの数字は一致するはずですが食い違っています。…必ず注記してください。差異の理由を推測で断定しないこと。", "difference_detail_sample"?: {columns, rows[:3]}}`。
- 画面への到達: 同じ `_execute` で `verify.render_item(a)`（`4144`）を `render_log` に積む: `{"kind":"report","title":"⚠ 検算: {name}","tables":[{"name":"2つの経路の比較","columns":["経路","値"],"rows":[(left_label,left),(right_label,right),("差",diff),("差の割合", f"{pct}%（許容 {tol}%）")]}, +{"name":"差の内訳（先頭のみ）", drill}],"notes":[...],"verify_key": key}`。同じ会話では `verify_key` 一致で1回だけ、データの版が変われば再度出る。
- 発火はツール実行後（`dispatch` 6a/6c → `_attach_verification`）。`_attach_verification` 内の例外は握って回答を止めない。

### 14. core 側の実行ループ（`_advance` / `_stream_advance` / `_Guard` / プレビュー）

- ループ回数: `config.MAX_AGENT_STEPS`（env `MAX_AGENT_STEPS`、既定 10、`config.py:306`）。各ステップ `defs = tools.build_tools(scope, admin=_is_admin())` → `llm.chat(llm.history_for_llm(messages, model, defs), defs, model)`（`history_for_llm`, `brain.py:13669`: 文脈に収まらない古いターンを落とす。`CHAT_KEEP_TURNS_MIN` 既定 2、`CHAT_ANSWER_RESERVE_TOKENS` 既定 6000）。
- tool_calls 無し: 本文あり → 最終回答（`_note_if_cut` で `finish_reason=="length"` なら `_CUT_MESSAGE`）。本文も無し → その assistant を pop、1回だけ再試行、それでも空なら `_append_final_answer`（ツール `[]`）か `_EMPTY_MESSAGE`。
- tool_calls あり: `fresh = [c for c in calls if not guard.seen(c)]` → `_call_previews(fresh, scope, question)`（`core.py:8089`）を `render_log` へ → `_execute`。
- `_call_previews`: `c["name"] in tools.SQL_TOOLS and "sql" in args` → `{"kind":"sql","tool","call_id","sql","purpose","explanation","question","tables": tables_in_sql(sql, scope)}`（`7474`, 最大6件）；ユーザー定義 → `kind sql`（`sql = tools.render_sql(custom)`、`purpose = 説明[:60] + 引数`, `explanation = description`）；`describe_table` → `kind text` "🛠 テーブル詳細を確認: `table`" ＋ tables。
- `_Guard`（`8131`）: `key = (name, arguments.strip())`、`failed{key: 理由}` / `done{key}` / `repeats`。`seen` は成功・失敗どちらも。`note` は `ok` なら done、でなければ `json.loads(llm_content)["error"]`（読めなければ "同じ内容で失敗しました。"）。`repeated` は done なら「この呼び出しは既に実行済みです。もう一度は実行しません。」＋hint、failed なら「同じツールを同じ引数で呼び直しています。実行しませんでした。」＋`previous_error`＋hint。`LIMIT = 2`（`8146`）で `stuck` → `_append_final_answer` → `stop_reason`（`_LOOP_MESSAGE` if done and not failed else `_STUCK_MESSAGE`）。上限到達は `_LIMIT_MESSAGE`（`8305`）。
- ストリーミング版は `llm.chat_stream`（`brain.py:13784`）で `("text", 差分)` を `delta` に流し、`("done", StreamedMessage)` を受けてから上と同じ処理。実行前に `running` を1件ずつ送り、実行後 `_web_log(render_log, before)` の差分を `item` で送る。

### 18. 設計上の注意点（コードで確認したもの）

1. `plot_chart` は宣言だけ引退。`_HANDLERS`・`SQL_TOOLS`・`TOOL_LABELS` に残り、`builtin_names()` は引退後の一覧から引くため同名のユーザー定義ツールを作れるが、実行は組み込み側が勝つ。
2. `builtin_tools.enabled: false` は `build_tools` のみで効き、`dispatch` は判定しない。`ADMIN_TOOLS` だけが2段構え。
3. `_allow_result_id` が `required` から `sql` を外すため、`_missing_required` は `sql` 欠落を検知しない（`fetch` の `AnalysisError` が担当）。`_HAS_DEFAULT` により `run_sql_query` と `plot_trend/composition/distribution/relationship` は実質必須チェックなし。
