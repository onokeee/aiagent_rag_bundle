### 1. 第1層 `validate_select(sql: str) -> str`（core.py:294-329）

#### 1.1 検査用コピー（probe）の作り方 — 順序固定

```
cleaned = _trim_tail(sql)                                           # (a)
probe   = _trim_tail(_strip_sql_comments(_blank_quoted(cleaned)))   # (b)(c)(d)
```

- (a) `_trim_tail`（279-281）: `sql.strip().rstrip(";").strip()` — 前後空白と**末尾に並んだ `;`** を落とす。
- (b) `_blank_quoted`（284-292）: `_QUOTED` にマッチした塊を「先頭1文字＋末尾1文字」に潰す（`'don''t drop it'` → `''`、`"delete"` → `""`、`` `x` `` → ``` `` ```、`[delete]` → `[]`）。
  - `_QUOTED`（266）: `'(?:[^']|'')*'|"(?:[^"]|"")*"|`(?:[^`]|``)*`|\[[^\]]*\]` — `''` / `""` / ` `` ` のエスケープも1塊として食う。
- (c) `_strip_sql_comments`（269-276）: `--[^\n]*` → `" "`、`/\*.*?\*/`（DOTALL）→ `" "`。**必ず (b) の後に呼ぶ**（docstring 明記。生SQLに当てると値の中の `--` / `/* */` まで消える）。
- (d) もう一度 `_trim_tail`（コメントを消した結果、末尾に `;` が露出する場合のため）。
- **実行するのは `cleaned`（コメントを残した元SQL）**。probe は判定にしか使わない。理由（docstring 294-306）: `SELECT '2024/*x*/end'` を除去すると `'2024 end'` に黙って変わる／`WHERE note = 'foo -- bar'` は引用符が閉じず構文エラーになる。

#### 1.2 判定順序とエラーメッセージ（すべて `ValueError`）

| # | 条件 | メッセージ | 行 |
|---|---|---|---|
| 1 | `not sql or not sql.strip()` | `SQLが空です。` | 307-308 |
| 2 | `cleaned` が空 | `実行可能なSQLがありません。` | 309-311 |
| 3 | `probe` が空 | `実行可能なSQLがありません。` | 313-315 |
| 4 | `";" in probe` | `複数ステートメントは実行できません(SELECT文を1つだけ指定してください)。` | 316-317 |
| 5 | `probe.lower()` が `select` でも `with` でも始まらない | `SELECT文(または WITH ... SELECT)のみ実行できます。` | 318-320 |
| 6 | `_FORBIDDEN.search(probe) or _REPLACE_INTO.search(probe)` | `書き込み・DDL系のキーワード '{語}' は使用できません。読み取り専用です。` | 321-323 |
| 7 | `_SCHEMA_TABLE.search(probe)` | `SQLiteの管理表 '{名}' は読めません。テーブルの一覧・列の名前・型は、データカタログの説明としてすでに渡されています。そちらを見てください。` | 324-328 |
| — | 通過 | `return cleaned` | 329 |

#### 1.3 正規表現の定義

- `_FORBIDDEN`（252-256）: `\b(insert|update|delete|drop|alter|create|truncate|attach|detach|reindex|vacuum|pragma|grant|revoke|begin|commit|rollback|savepoint|merge)\b`、`re.IGNORECASE`。**19語**。`replace` は意図的に不在（コメント 245-248: `replace(X,Y,Z)` は文字列関数で常用するため）。
- `_REPLACE_INTO`（257）: `\breplace\s+into\b`、IGNORECASE。
- `_SCHEMA_TABLE`（262-263）: `\bsqlite_(master|schema|temp_master|temp_schema|sequence|stat\d*)\b|\bpragma_\w+`、IGNORECASE。コメント（259-261）: `sqlite_master` には全表・全ビューの名前と CREATE 文が入るので、読めると「対象から外した表」の名前と定義が見える。`pragma_*` はテーブル値関数（`pragma_table_info` 等）の代替経路を塞ぐ。

#### 1.4 この層で「していない」こと（コード上の事実）

- SQL文字列の**長さ上限は無い**。
- `EXPLAIN` / `EXPLAIN QUERY PLAN` / `VALUES(...)` は判定5（select/with で始まらない）で拒否される。実行計画は AI に見せない（内部の `view_used_data` だけが EXPLAIN を使う、§9.3）。
- `\b` 境界は Unicode `\w` に依存するため、`create_log` や `受注create` のような識別子はキーワードとして誤検出しない（`_` も日本語も `\w`）。
- 検査は `validate_select` 単体で完結し、DBには触れない。

#### 1.5 セルフテスト `_sql_guard_selftest`（539-594）

- ok_cases 8本: `SELECT 1` / `select a.x from t a join u b on a.id=b.id` / `WITH t AS (SELECT 1 AS a) SELECT a FROM t` / `SELECT replace(name,'株式会社','') FROM t` / `SELECT * FROM t WHERE x='delete me'` / `SELECT * FROM t WHERE note=';'` / `SELECT * FROM t WHERE s='don''t drop it'` / `SELECT "delete" FROM t`
- ng_cases 9本: `DELETE FROM t` / `DROP TABLE t` / `UPDATE t SET x=1` / `SELECT 1; DELETE FROM t` / `INSERT INTO t VALUES(1)` / `PRAGMA table_info(t)` / `ATTACH DATABASE 'x.db' AS z` / `REPLACE INTO t VALUES(1)` / `SELECT * FROM t WHERE x='a'; DROP TABLE t`

- ガードすり抜けは `!! ガードすり抜け:` の print のみで、終了コードには反映されない（566-572）。

### 2. 第2層 読み取り専用接続（core.py:140-172）

#### 2.1 URI と接続

- `_ro_uri(path)`（140-141）: `Path(path).resolve().as_uri() + "?mode=ro"`（例: `file:///C:/.../data/%E3%83%87%E3%83%BC%E3%82%BF.db?mode=ro`）。
- `connect_ro(path)`（144-150）: `sqlite3.connect(_ro_uri(path), uri=True, timeout=30)`。単一DBの読み取り専用接続（プロファイリング・表ビューア・メール宛先検索用）。`timeout=30` は取り込み側の書き込み接続と同じ値（既定5秒だと大きな表の入れ替えコミット中に `database is locked` で落ちる、docstring）。
- `MAX_ATTACHED = 10`（154）: SQLite が同時に ATTACH できる上限（main は空メモリDBなので実質この数）。
- `connect_scope(paths_aliases)`（157-172）:
  1. `len(paths_aliases) > MAX_ATTACHED` → `ValueError("1つのSQLで扱えるDBは10個までです（この問い合わせはN個を必要としています）。SQLiteの制限です。テーブル名を『DB名.テーブル名』の形で書けば、実際に使うDBだけを繋ぐので多くの場合はこの制限に当たりません。")`
  2. `conn = sqlite3.connect("file::memory:", uri=True)` — **main は空の :memory:**。`uri=True` があるからこそ ATTACH 先の `?mode=ro` が URI として解釈される。
  3. 各 `(path, alias)` について `conn.execute(f'ATTACH DATABASE ? AS "{alias}"', (_ro_uri(path),))` — パスはプレースホルダ、alias は識別子として直接埋め込み（alias は `alias_for` で `[^\w]` を `_` に潰した後の値なので安全）。
- **PRAGMA は接続時に一切発行しない**（`query_only`、`foreign_keys`、`journal_mode` 等は未使用）。読み取り専用は `mode=ro` のみで担保。PRAGMA が出るのはプロファイリング（`PRAGMA table_info` / `PRAGMA foreign_key_list`、core.py:2524, 2530）、importer（5509）、表ビューア（15273, 15324）だけで、いずれも `run_select` 経路の外。

#### 2.2 エイリアス

- `_ALIAS_BAD = re.compile(r"[^\w]", re.UNICODE)`（108）、`_RESERVED_ALIASES = {"main", "temp"}`（110）。
- `alias_for(path)`（113-120）: `Path(path).stem` の記号・空白を `_` に、空または数字始まりなら `db_` を前置、`main`/`temp` なら `_db` を後置。日本語は残す（`売上.db` → `売上`。ASCII に絞ると「店舗マスタ」が `_____` になり複数DBを区別できない、コメント 104-107）。
- `aliases_for(paths)`（123-134）: 衝突時は `_2`, `_3` … を付ける（小文字比較）。

#### 2.3 スコープの伸縮（run_select の前後）

- `dbs_named_in(sql)`（175-182）: `list_db_files()` を走査し、`(?<![\w."])` + alias + `\s*\.`（IGNORECASE）に当たる DB のファイル名を返す（会話が触ったDBの記録に使う、core.py:7941）。
- `widen_scope(sql, scope)`（185-207、呼び出し側が run_select の前に呼ぶ）: SQL が `alias.` の形で名指しする DB を、選ばれていなくても足す。足す要素は `{"path": str(p), "alias": a, "name": p.name, "tables": None}`（**tables=None**）。`len(out) >= MAX_ATTACHED` で打ち止め。docstring の根拠: DBの選択は「見る範囲を絞る」ためのもので、アクセス制御ではない。
- `narrow_scope(sql, scope)`（209-250、run_select の内部）: `len(scope) <= 1` なら即 return。(1) `alias\s*\.` で名指しされた DB、(2) 修飾なしの表名 `(?<![\w."])` + 表名 + `(?![\w"])` が一致する DB（`s["tables"]` を走査）を集め、`picked[:MAX_ATTACHED] if picked else scope`。判断できないときは全部を返す（勝手に減らして `no such table` にしない）。

### 3. 第3層 SQLite オーソライザ（core.py:332-434）

#### 3.1 許可アクション

```
_ALLOWED_ACTIONS = {sqlite3.SQLITE_SELECT, sqlite3.SQLITE_READ, sqlite3.SQLITE_FUNCTION}   # 332
for _name in ("SQLITE_RECURSIVE",): if hasattr(sqlite3, _name): _ALLOWED_ACTIONS.add(...)  # 333-335
```

実環境の値（.venv で確認）: `SQLITE_SELECT=21`, `SQLITE_READ=20`, `SQLITE_FUNCTION=31`, `SQLITE_RECURSIVE=33`（存在する）。参考: `SQLITE_ATTACH=24`, `SQLITE_PRAGMA=19` は含まれない。戻り値は `SQLITE_OK=0` / `SQLITE_DENY=1`（`SQLITE_IGNORE=2` は使っていない）。

#### 3.2 `_make_authorizer(allowed: set | None, via_view: set | None = None)`（395-434）

- `allow_ci = None if allowed is None else {str(x).lower() for x in allowed}`、`via_ci = {str(x).lower() for x in (via_view or ())}`（SQLite は「SQLに書かれたとおりの綴り」で名前を渡すので小文字で比較、コメント 405-409）。
- コールバック `_authorizer(action, arg1, arg2, db_name, trigger)`（412-433）の分岐順:
  1. `action not in _ALLOWED_ACTIONS` → `SQLITE_DENY`（413-414）。
  2. `action == SQLITE_READ and str(arg1 or "").startswith("sqlite_")` → `SQLITE_DENY`（419-420）。**allowed の有無によらず**管理表は読ませない。
  3. `allowed is not None and action == SQLITE_READ and arg1` のとき（422-432）:
     - `name = str(arg1).lower()`; `name in allow_ci` → `SQLITE_OK`
     - `via_ci and name in via_ci and (trigger or not arg2)` → `SQLITE_OK`（ビューの中身を読んでいる最中＝第5引数 `trigger` にビュー名が入る、または列名 `arg2` が空の「表を参照する」照会。どちらも `via_view` に入っている名前に限る）
     - それ以外 → `SQLITE_DENY`
  4. その他 → `SQLITE_OK`（433）。
- `db_name` は受け取るだけで使わない → **allowed は表名だけのフラットな集合で、DB名で分離しない**。
- `allowed is None` のときは 2 の `sqlite_` 拒否と 1 のアクション制限だけが効く（表単位の制限なし）。
- `SQLITE_FUNCTION` は関数名（arg2）で絞っていない。`create_function` は呼んでいないので SQLite 組み込み関数だけが呼べる。

#### 3.3 ビューの扱い — `_view_closure(conn, aliases, allowed, sql="")`（350-392）と `_names_in`（338-345）

- `_names_in(text, name)`: `(?<![\w."])"?` + `re.escape(name)` + `"?(?![\w])`、IGNORECASE（引用符付き・無しの両方に当たる。`\w` は Unicode）。
- `_view_closure`:
  1. `not allowed` → `set()`。
  2. 各 alias について `SELECT name, type, sql FROM "{alias}".sqlite_master WHERE type IN ('table','view')` を実行（`sqlite3.Error` は握って continue）。**この SELECT は `set_authorizer` より前に実行される**（run_select 521-522 で `_make_authorizer(allowed, _view_closure(...))` の引数評価が先）ので、上記 3.2-2 の `sqlite_` 拒否には当たらない。
  3. `todo = [v for v in allowed if v in views and (not sql or _names_in(sql, v))]` — **SQLに名前が出てくる許可済みビュー**だけを起点にする（docstring: ここを絞らないと、入れ子ビュー用の穴（列名が空の READ を通す）から対象外の表の `COUNT(*)` が読めてしまう）。
  4. ビュー定義本文に `_names_in` で当たる表・ビュー名を `out` に集め、当たったのがビューなら `todo` に積んで増えなくなるまでたどる（自分自身と既出は除外）。
- 結果 `out`（表名とビュー名の集合）が `via_view` として `_make_authorizer` に渡る。
- ビューを SELECT すると SQLite は READ を「ビュー名」と「実体の表名（trigger=ビュー名）」の両方で通知するため、ビューだけを allowed に入れても、この closure が無いと元表で DENY される（コメント 355-358）。
- `profile_db`（2600-2603）は `sqlite_master` を `type IN ('table','view')` で引くので、ビューも `profile["tables"]` に入り、`build_scope` の `tables` にも入る（サイドバーでは `"type": "view"` で見分ける、core.py:7766）。

#### 3.4 `allowed` の作り方（run_select 509-515）

```
allowed: set | None = set()
for s_ in use:                      # use = narrow_scope の結果
    if s_.get("tables"): allowed |= set(s_["tables"])
    else: allowed = None; break     # 1つでも tables が無い/空/None なら制限なし
```

- したがって `widen_scope` が足した要素（`tables: None`）が `use` に残ると、**そのSQL全体で表単位の制限が外れる**（widen が足すのは SQL が alias を名指ししているときだけなので narrow でも必ず残る）。
- `_sql_scope`（13057-13078）・`_view_run`（11710-11721）・`view_export`（11759）が作る scope には `tables` キー自体が無い → 常に `allowed = None`（いずれも `admin_required` のルート）。

#### 3.5 順序の制約

- `connect_scope`（ATTACH）→ `set_authorizer` の順は入れ替え不可（`SQLITE_ATTACH=24` は許可アクションに無いので、先に付けると自分の ATTACH が DENY される）。
- DENY 時の例外は `conn.execute` 内で `sqlite3.Error` として捕まり `explain_error` を通るが、該当パターンは無いので SQLite の英語文言のまま `sqlite3.OperationalError` として再送出される（525-527）。

### 4. 第4層 タイムアウトと件数上限（core.py:523-529、config.py:307-309）

- `config.MAX_RESULT_ROWS = 2000`（config.py:307、env 不可・固定値）
- `config.QUERY_TIMEOUT_SEC = 10`（config.py:308、固定値）
- `config.SAMPLE_ROWS_FOR_LLM = 40`（config.py:309、固定値。LLMへ返す行数）
- `config.EXPORT_MAX_ROWS`（config.py:317）: env `EXPORT_MAX_ROWS`、既定 `1000000`。ファイル出力の上限。Excel は `min(config.EXPORT_MAX_ROWS, 1_048_575)` に丸める（brain.py:12576-12577、core.py:11762）。
- `config.PROFILE_TIMEOUT_SEC = 30`（config.py:322、固定値）、`PROFILE_STATS_MAX_ROWS = 2_000_000`（323）。

run_select 内:
```
start = time.time()
conn.set_progress_handler(lambda: 1 if (time.time() - start) > timeout_s else 0, 10000)   # 524
cur = conn.execute(safe_sql, params or {})                                                 # 526
columns = [d[0] for d in cur.description] if cur.description else []                      # 528
rows = cur.fetchmany(max_rows + 1); truncated = len(rows) > max_rows; rows = [tuple(r) for r in rows[:max_rows]]  # 529-531
```
- 10,000 VM命令ごとにコールバック、非0で SQLite が中断。`start` は execute の直前に1回だけ取り、fetchmany 中もリセットしない（execute + fetch 合計で `timeout_s` 秒）。
- `max_rows` / `timeout_s` に `0` を渡すと `or` で既定値に落ちる（無制限は表現できない）。
- `fetchmany` は `try/except sqlite3.Error` の外（525-527 の try は execute だけ）。fetch 中の中断は `explain_error` を通らない。
- 上限+1行を取って `truncated` を決めるだけで総件数は数えない。総件数は brain.py `_total_rows(sql, scope)`（7551-7562）が `SELECT COUNT(*) FROM ({sql.strip().rstrip(';')})` を `max_rows=1` で撃ち直す（例外は握って `None`）。
- プロファイリングは別系統 `_make_timeout(conn, seconds)`（core.py:2506-2513）: `box["t"]` を持ち、100,000 命令ごとに判定、クエリごとに `reset()`（`_profile_table` 2520-2537 で各PRAGMA/COUNT前に呼ぶ）。

### 5. `run_select(sql, scope, max_rows=None, timeout_s=None, params=None)` の全手順（core.py:483-534）

引数: `scope = [{"path": str, "alias": str, "name": str, "tables": list[str] | None, "meta": dict}, ...]`（path/alias 以外は経路により欠ける）、`params` は `:name` バインド用 dict。戻り値 `(columns: list[str], rows: list[tuple], truncated: bool)`。

1. `not scope` → `ValueError("対象のDBがありません。SQLは実行できません。出力したい内容が手元にある（文書を調べた・自分で整理した）なら、sql の代わりに rows で表をそのまま渡して呼び直すこと。DBのデータが必要なら、data/ にDBを置くよう利用者に案内する。")`（494-501）
2. `safe_sql = validate_select(sql)`（502）
3. `max_rows = max_rows or config.MAX_RESULT_ROWS`、`timeout_s = timeout_s or config.QUERY_TIMEOUT_SEC`（503-504）
4. `use = narrow_scope(safe_sql, scope)`（507）
5. `allowed` 構築（509-515、§3.4）
6. `conn = connect_scope([(s["path"], s["alias"]) for s in use])`（517）
7. `conn.set_authorizer(_make_authorizer(allowed, _view_closure(conn, [s["alias"] for s in use], allowed, safe_sql)))`（521-522）
8. progress handler（523-524）
9. `conn.execute(safe_sql, params or {})`、`sqlite3.Error` → `raise sqlite3.OperationalError(explain_error(e)) from e`（525-527）
10. columns / fetchmany / truncated（528-531）
11. `finally: conn.close()`（533-534）— 接続は1回のSELECTごとに作って捨てる。

バインド変数: 値はSQL文字列に埋め込まれず `conn.execute(safe_sql, params)` の名前付きプレースホルダで渡る（docstring 489-491）。`render_sql`（brain.py:12561-12563）は「UIのプレビュー用。実行時は :name のままバインドするので置換はしない」。

### 6. `explain_error(e)`（core.py:460-480）と `_MISSING_FUNC_HINTS`（439-457）

1. `no such function:\s*([A-Za-z_0-9]+)` → ヒントがあれば `"{msg} … SQLite には {fn}() がありません。SQLで書き直そうとせず、{hint} を使ってください。"`、無ければ `"… 標準のSQLite関数だけで書き直すか、専用の分析ツールを使ってください。"`
2. `no such column:\s*(\S+)` → `"{msg} … 列名が違います。describe_table でテーブルの列を確認してから書き直してください（推測で列名を作らないこと）。"`
3. `"syntax error" in msg` → `"{msg} … SQLite で解釈できない書き方です。ウィンドウ関数の一部・WITHIN GROUP・PIVOT などは使えません。集計や統計は専用ツール（pivot_table / analyze_stats）に任せてください。"`
4. それ以外 → `msg` そのまま。

`_MISSING_FUNC_HINTS` のキー: `stddev, stdev, stddev_samp, variance, var_samp, median, percentile, percentile_cont, percentile_disc, corr, regr_slope, stddev_pop, sqrt, power, date_trunc, now, year, month, day, concat, ifnull_, listagg, string_agg, top`（値は `analyze_stats(method='describe')` / `analyze_stats(method='correlation')` / `regression` / `strftime(...)` / `||` / `group_concat` / `LIMIT` など）。

`validate_select` の `ValueError` は try の外で投がるので `explain_error` を通らず、日本語のガード文言がそのまま呼び出し元（→ `_err("SQL実行エラー: ...")` → LLM）へ届く。

### 7. AIが見てよい表の決定（スコープ制御）

#### 7.1 `build_scope(selection: dict) -> list[dict]`（core.py:7417-7432）

- `selection = {DBファイル名: [表名, ...]}`。`files = {f.name: f for f in db.list_db_files()}`、`chosen = [files[n] for n in selection if n in files]`（存在するファイル名だけ）。
- 各DB: `prof = catalog.profile_db(f)`、`available = list(prof["tables"].keys())`（表＋ビュー）、`want = [t for t in (selection.get(f.name) or available) if t in available]`。
- 要素: `{"path": str(f), "alias": alias, "name": f.name, "tables": want or available, "meta": catalog.load_meta(f)}`。空リスト `[]` を渡すと全表になる。

#### 7.2 利用者が外した表 — `tables_off`

- 保存先: `prefs.yaml` の `KEYS = ("model", "rag_off", "rag_settings", "tables_off", "memory_off")`（core.py:1627）。パスは `config.USER_META_DIR / _key(user) / "prefs.yaml"`（1630-1635）、`USER_META_DIR = DATA_DIR / "users"`（config.py:431）、`_key(user) = user.safe_key`（auth.py:96-105: `username` の英数字と `-_.@` 以外を `_` に、64文字まで、空または `.` 始まりは `_` を前置）。
- `rag.excluded_tables(user=None) -> list[str]`（brain.py:11972-11981）: `prefs.load(...).get("tables_off")` が list なら `str` 化して返す。「選んだもの」ではなく「外したもの」を持つ（新しい表は既定で対象に入る）。
- 保存ルート `POST /api/tables/prefs`（core.py:14681-14695、`login_required`）: `known` = 全DBの `profile_db(f)["tables"].keys()`、`off` が list/tuple でなければ 400、`prefs.set_value(g.user, "tables_off", [str(t) for t in off if str(t) in known])`（実在する表だけ保存）。
- 表の改名時（`cleanup.rename_table`、core.py:7116-7130）は全利用者の `prefs.yaml` を走査して `tables_off` 内の旧名を新名に置換。
- サイドバー（`chat_index`、core.py:7752-7787）: 表ごとに `"on": t not in off`、`"type": info.get("type") or "table"`。DBの概念は見せない（7755-7756）。

#### 7.3 `_auto_scope(question, chat)`（core.py:8464-8517）— チャットの1質問ごとのスコープ

1. `scope = build_scope({f.name: [] for f in db.list_db_files()})` — 全DB・全表。
2. `off = set(rag.excluded_tables(g.user))`; あれば各要素の `tables` から除き、表が空になったDB要素は落とす（8483-8487）。
3. `not scope` → そのまま返す。
4. `config.SCOPE_MODE`（config.py:297-299、env `SCOPE_MODE`、既定 `"auto"`、許容 `auto|router|all`、それ以外は `auto`）:
   - `all` → 絞らずに返す。
   - `auto` かつ `catalog.inline_length(scope) <= models.inline_limit_for(models.current(g.user))` → 絞らずに返す。
   - それ以外（`router`、または収まらない `auto`）→ `llm.route_tables(question, scope, chat_history)`。
5. `picked` があれば: この会話で実際にSQLが触った表 `chat["table_names"]`（`"DBファイル名.表名"`、`rpartition(".")` で分割）をピン留め → `llm.expand_tables_by_relations(picked, scope)` → **再度 `off` で落とし直す**（8507-8512）→ `s["tables"] = sel`。
- 呼び出し元: `_begin_turn`（8577、`/api/chat/send` と `/api/chat/stream` 共通）、書き直しルート（8803）。

`inline_limit_for(model)`（brain.py:2153-2166）: `context_window(model)` × `CATALOG_CONTEXT_RATIO = 0.5`（2132）÷ `TOKENS_PER_CHAR_TEXT = 0.55`（13504）を `INLINE_LIMIT_MIN = 4_000`（2038）と `prompt_inline_limit() = INLINE_LIMIT_MAX = 400_000`（2039, 2120-2128）で丸める。モデル不明時のフォールバックは `config.PROMPT_INLINE_LIMIT_CHARS`（config.py:340、env、既定 `80000`）（core.py:3774-3785）。

#### 7.4 表ルーター `route_tables(question, scope, history)`（brain.py:13149-13210）

- 対応表 `known` は `alias.table`（必ず引ける）と `table` 単独（複数DBで曖昧なら除外）。
- 表の総数 `total <= 8` → `None`（絞らない）。
- LLM 呼び出し: `_ROUTE_TABLE_SYSTEM` + カード（`db_text_cached(..., full=False)`）+ 直前3件の質問、`temperature=0, max_tokens=300`。応答から `\[.*?\]` を JSON として読む。例外・`"*"` を含む・空 → `None`。
- 戻り値 `{DBファイル名: [表名...]}`。
- `expand_tables_by_relations(picked, scope)`（13213-13252）: `.meta.yaml` の `relationships` を `from → to` の1ホップだけ（元の選択のスナップショットに対して）足す。

#### 7.5 ロボット（マイロボット）実行時のスコープ

- ツール定義（brain.py:9285-9301）: `name: "describe_table"`、`parameters.properties = {"table": string}`、`required: ["table"]`（**`db` はスキーマに無い**。ハンドラは `args.get("db", "")` を読むだけ）。

  1. `tname` に `.` があり、先頭が scope 内の alias（小文字比較）で、`db_alias` が空か同じなら `alias.table` を剥がす。

### 8. 結果の預かり（result_id 経路）と `fetch`（brain.py:7391-7691）

- `MAX_ENTRIES = 40`（7391）、`MAX_CELLS = 400_000`（7393、行×列の合計）。`_store` はモジュール変数の `OrderedDict`（プロセス全体で共有、利用者単位ではない）。`_store_lock = threading.RLock()`。
- `scope_key(scope) = "|".join(sorted(path...))`（7433-7435、**tables は含まない**）。
- `put`（7461-7474）: `rid = "r_" + uuid4().hex[:8]`、エントリ `{"scope", "columns", "rows", "truncated", "sql", "norm_sql", "turn", "label"}`、`_evict()`（古い順に破棄）。
- `get(scope, rid)`（7477-7484）: `entry["scope"] != scope_key(scope)` なら `None`。DB には触れない。
- `find_by_sql(scope, sql)`（7487-7507）: 同じ質問（`current_turn()`）・同じ `scope_key`・同じ `normalize_sql`（空白正規化のみ、大小は区別）なら既存 rid を返す。
- `new_turn()`（7405-7409）: `"t_" + uuid4().hex[:8]`。`/api/chat/send` と `/api/chat/stream` の `_begin_turn`（core.py:8552）、ロボット実行（9905）で呼ぶ。
- `fetch(spec, scope, *, label=None, max_rows=None)`（7619-7691）→ `(columns, rows, truncated, result_id, total_rows)`:
  1. `spec["rows"]` が非 None: 中身があるか sql/result_id が無ければ `_inline_table`（DBを介さない表。`cap = max_rows or MAX_RESULT_ROWS`）。
  2. `result_id` 未指定なら `results.find_by_sql` で同一SQLの使い回しを試みる。
  3. `rid` あり: `results.get` が `None` → `AnalysisError("result_id '...' のデータが見つかりません。…")`。預けた結果が `truncated` で `max_rows > len(entry["rows"])` なら `entry["sql"]` を `widen_scope` → `run_select` で取り直す。それ以外は預けた結果をそのまま返す（**run_select を通らない**）。
  4. `sql` 無し → `AnalysisError("sql と result_id のどちらも指定されていません。…")`。
  5. `scope = db.widen_scope(sql, scope)` → `db.run_select(sql, scope, max_rows=max_rows)` → `keep = rows[:MAX_RESULT_ROWS]` を `results.put`、`truncated` なら `_total_rows`。
- `source_note(row_count, truncated, total, cap=None)`（7693-7705）: `{"source_row_count", "source_truncated", ["source_total_rows", "warning"]}`。warning 文: `"上限 {cap or MAX_RESULT_ROWS:,} 行で切り詰めました。実際は {total:,} 行あります。この結果は全体の一部です。全体を語るなら、SQL側でGROUP BY で集計するか、条件を絞って取り直してください。"`
- `render_source_note(truncated, total)`（7708-7718）: 画面用 `{"truncated": True, "source_total_rows": total}`。
- `_run_sql_query(args, scope)`（brain.py:10095-10125）: `fetch(args, scope, label=args.get("purpose"))`、例外は `_err(str(e))` / `_err(f"SQL実行エラー: {e}")`。LLMへは `{"columns", "row_count", "rows": 先頭 SAMPLE_ROWS_FOR_LLM=40 行, "result_id", "note", **source_note, "example_registered"}`、画面へは `{"role":"assistant","kind":"table","columns","rows"(全行),"truncated"}`。
- ツール定義 `run_sql_query`（brain.py:7943-7968）: `parameters.properties = {"sql": string, "purpose": string}`, `required: ["sql","purpose"]`。説明文「SELECT(または WITH ... SELECT)以外は実行不可」。
- SQLを受け取る組み込みツール `SQL_TOOLS_query = {"run_sql_query","plot_chart","plot_dual_axis","pivot_table","analyze_stats", *_CHART_TOOLS}`（10816-10817）。`_gather_sqls`（12802-12819）は引数の入れ子から `sql` と `result_id`（→ 預けた SQL）を全部拾い、`_attach_verification`（12823-12839）で検算に回す。

### 9. ビュー（CREATE VIEW）の検証と実行

#### 9.1 定数・関数（core.py:11633-11721）

- `VIEW_PREVIEW_ROWS = 20`（11640）。
- `_view_check_sql(sql) -> str`（11643-11649）: `strip().rstrip(";").strip()`、空なら `ValueError("SQLが空です。")`、`db.validate_select(sql)`（**ビュー定義の唯一の文字列ガード**）、整形後の `sql` を返す。
- `_view_run(path, sql, limit=VIEW_PREVIEW_ROWS)`（11710-11721）: `scope = [{"path": str(path), "alias": db.alias_for(path), "name": path.name}]`（tables 無し → allowed None）、`db.run_select(sql, scope, max_rows=limit)`、件数は `SELECT COUNT(*) FROM ({sql})` を `max_rows=1`（失敗は握る）。戻り `{"columns", "rows", "total"}`。
- `importer.create_view(db_path, name, sql, replace=False)`（core.py:5744-5768、**書き込み系**）: `db_path.parent.resolve() != config.DATA_DIR.resolve()` → `ImportError_("data/ の外は操作できません。")`; `sqlite3.connect(db_path)`（書込可）; `SELECT type FROM sqlite_master WHERE name = ?` で既存を見て、表なら `"'{name}' は既にテーブルとして存在します。…"`、ビューかつ `not replace` なら `"ビュー '{name}' は既にあります。…"`、`replace` なら `DROP VIEW IF EXISTS "{name}"`; `CREATE VIEW {_importer_qi(name)} AS {sql}`（**f-string 連結**。docstring「SQLは SELECT専用ガードを通ったものだけを渡すこと」）; `sqlite3.Error` → rollback + `ImportError_("ビューを作れませんでした: …")`。
- `importer.drop_table(db_path, table)`（5719-5741）: DATA_DIR チェック → `SELECT name, type FROM sqlite_master WHERE name = ? COLLATE NOCASE` で種類を見て `DROP {VIEW|TABLE} IF EXISTS "{real}"`。
- `list_views`（5771-5781、`mode=ro`、`type='view' AND name NOT LIKE 'sqlite_%'`）、`view_body`（5784-5789、`\bAS\b\s*(.+)$` で本体抽出）。
- `_importer_qi(name)`（5487-5488）: `"` を `""` にエスケープして二重引用符で囲む。`safe_name(name, fallback="col", *, table=False)`（5336-5356）: NFKC → `[^\w]`→`_` → `table=True` なら `_{2,}`→`__` を保つ、それ以外は `_+`→`_` → strip("_") → 数字始まりは `_` 前置 → `_RESERVED`（4494-4502、SQL予約語 68語）なら `_` 後置 → 64文字。

#### 9.2 ルート（すべて `bp_catalog` + `@admin_required`）

### 10. ユーザー定義ツール（カスタムツール）の検証と実行

#### 10.1 定義の検証（brain.py:7147-7261）

- `RENDER_KINDS = ("table", "chart", "chart_dual", "excel", "csv", "none")`（7147）、`PARAM_TYPES = ("string", "integer", "number", "boolean")`（7148）。
- `_NAME_RE = ^[A-Za-z][A-Za-z0-9_]{0,47}$`（7151）、`_BIND_RE = (?<!:):([A-Za-z_][A-Za-z0-9_]*)`（7153、`::` は除外）。
- `bind_names(sql)`（7184-7190）: 重複なし・出現順。
- `validate_custom_tool(tool, existing_names=frozenset()) -> list[str]`（7194-7261）: 名前必須／`_NAME_RE`／組み込み名（`builtin_names()` = `tools.BUILTIN_TOOLS` の全名）との衝突／既存名との衝突、説明必須、SQL必須、パラメータ名 `^[A-Za-z_][A-Za-z0-9_]*$`・重複・型、**SQL中の `:name` とパラメータ定義の相互対応**（未定義・未使用をそれぞれエラー）、`render` の妥当性、`chart` / `chart_dual` の必須項目。**`validate_select` は呼ばない**（SELECT縛りは実行時の `run_select` のみ）。
- `to_schema(tool)`（7264-7282）: OpenAI function 形式へ。`coerce_params(tool, args)`（7285-7308）: `integer→int`, `number→float`, `boolean→1/0`（`True`/`"true"/"1"/"yes"`）, それ以外 `str`; `None` は `None`; 失敗は `ValueError("パラメータ '{pn}' を {t} として解釈できません: …")`。

#### 10.2 保存・試行ルート（core.py、すべて `@admin_required`）

- `POST /api/catalog/tool`（`save_tool`、13706-13735）: `path_for(body.db)`、`action == "delete"` なら名前で除去、それ以外は `validate_custom_tool(tool, others)`（`original` を除く既存名）→ エラーなら 400 → `.meta.yaml` の `tools` に保存。**保存時に SQL は実行しない**。
- `POST /api/catalog/tool/try`（`try_tool`、13369-13400）: `validate_custom_tool` の結果（`'` 始まり＝名前衝突は除外）を `problems` として添え、`coerce_params(tool, _sample_params(...))` → `scope = _sql_scope(sql, path)` → `db.run_select(sql, scope, max_rows=8, params=params)`。
- `POST /api/catalog/tool/draft`（`_w_draft_tool`、13403-13473）: `llm.draft_tool` 最大2回、`custom_tool_safe_name` で名前を強制的に有効化、`_sql_scope`（db 指定あり）または `db.widen_scope(sql, [])`／全DB `[:MAX_ATTACHED]`（db 指定なし）で `run_select(max_rows=8, params=params)`。
- `_sql_scope(sql, path)`（13057-13078）: `[{"path": str(path), "alias": alias}]` に、SQL が `alias\s*\.` で名指しする他DBを `MAX_ATTACHED` まで足す。**tables キー無し → allowed None**。

#### 10.3 実行（brain.py:12566-12600、`_run_custom(tool, args, scope)`）

1. `sql = render_sql(tool)`; `params = custom_tools.coerce_params(tool, args)`（`ValueError` → `_err`）。
2. `scope = db.widen_scope(sql, scope)`（作った人がDBを意識しないため）。
3. `cap = min(EXPORT_MAX_ROWS, 1_048_575) if render in ("excel","csv") else None`。
4. `db.run_select(sql, scope, params=params, max_rows=cap)`（例外 → `_err(f"ツール '{name}' のSQL実行エラー: {e}")`）。
5. `keep = rows[:MAX_RESULT_ROWS]` を `_results.put(..., sql=sql, label=f"{name}（ユーザー定義ツール）")`。LLMへは先頭40行 + `result_id`。
- ツールの露出: `build_tools(entries, admin)`（12695-12727）は `validate_custom_tool(tool, set())` が空のものだけ `to_schema` で渡す（壊れた定義はAIに見せない）。`dispatch`（12842-12878）は `_HANDLERS` に無い名前を `custom_tools.collect_everywhere(entries)` から探し、`sqls.append(render_sql(tool))` してから `_run_custom`。

### 14. DB パスの解決とパストラバーサル対策

- `config.BASE_DIR = Path(__file__).resolve().parent`（config.py:18）。`config.DATA_DIR = Path(os.getenv("DATA_DIR", str(BASE_DIR / "data")))`（config.py:26、env `DATA_DIR`）。起動時 `DATA_DIR.mkdir(parents=True, exist_ok=True)`（config.py:480）。`PROFILE_CACHE_DIR = DATA_DIR / ".profile_cache"`（28）。カタログは `str(db_path) + ".meta.yaml"`（core.py:2238、`data/<DB>.db.meta.yaml`）。
- `db.list_db_files()`（core.py:86-89）: `config.DATA_DIR.glob("*.db")` のうち `is_file()` を名前順。サブフォルダは見ない。
- `db.path_for(name)`（92-103）: `target = Path(str(name or "")).name`（**ディレクトリ部分を捨てる**）→ `list_db_files()` の列挙結果と `p.name == target` で一致するものを返す。一致しなければ `FileNotFoundError(f"DBが見つかりません: {name}")`。`data/` に名前を連結しないので `../` を入れても外に出られない（docstring）。画面からの `db` 指定はすべてこの関数（core.py:7951, 8931, 11356-11403, 11730-11933, 12898-13741, 14231, 14252 など）か、`_resolve`（15148-15161、ファイル名または alias で列挙一致）を通る。

### 15. 認可（誰がどの経路を使えるか）

### 17. コードで確認した注意点（設計図に反映すべき事実）

1. `allowed` は「`use` の要素が1つでも `tables` を持たなければ None」（core.py:509-515）。`widen_scope` が足す要素は `tables=None` なので、SQL が別DBを `alias.` で名指しした瞬間に表単位の制限が全体で外れる。
2. `allowed` は表名だけの集合で `db_name` を見ない（core.py:412-433）。同名の表が複数DBにあれば区別しない（現行は単一DB運用）。
3. `sqlite_` 始まりの READ は `allowed` の有無によらず DENY（419-420）。加えて `validate_select` の `_SCHEMA_TABLE` で文字列段階でも拒否（262-263, 324-328）。`_view_closure` 自身の `sqlite_master` 読みはオーソライザ設定前に実行される（521-522）。
4. ビュー経由の元表読みは `via_view` かつ `(trigger or not arg2)` のときだけ通し、`via_view` は「SQLに名前が出てくる許可済みビュー」から辿った集合に限る（350-392, 425-431）。
5. マイロボットの実行は `build_scope(全DB)` をそのまま使い、`tables_off` を引かない（core.py:9906）。チャット（`_auto_scope`）とは異なる。
6. `result_id` 経路（`results.get`）は `run_select` を通らず、`scope_key` は path のみ（brain.py:7433-7484）。`_store` はプロセス共有。
7. `validate_custom_tool` は `validate_select` を呼ばない（brain.py:7194-7261）。保存ルート（core.py:13706-13735）も SQL を実行しない。SELECT 縛りは `try_tool` / `draft` / `_run_custom` の `run_select` 時のみ。
8. `validate_select` はビュー定義（`create_view` の f-string 連結）の唯一の文字列ガード（core.py:11643-11649, 5762）。
9. `fetchmany` は `try/except sqlite3.Error` の外（core.py:525-531）。`max_rows`/`timeout_s` の `0` は既定値に落ちる（503-504）。
10. `describe_table_text` は「存在しない表」のエラー文で `profile["tables"]` の全名（除外表を含む）を列挙する（core.py:3850-3852）。除外表そのものを指定した場合は説明を返さない（3855-3859）。

#### 1-2. `User` データクラス（auth.py:86-106）

#### 1-3. パスワードハッシュ（local 用、auth.py:109-129）

- `_ITER = 200_000`（:111）。
- `hash_password(password)`（:114-117）: `salt = secrets.token_bytes(16)`、`hashlib.pbkdf2_hmac("sha256", password.encode(), salt, _ITER)`。
  - 保存形式: `"pbkdf2_sha256$<iters>$<salt hex(32桁)>$<dk hex(64桁)>"`。
- `verify_password(password, stored)`（:120-129）: `stored.split("$")` で 4 要素に分解、`algo != "pbkdf2_sha256"` は False、反復回数は **保存値** `int(iters)` を使う、比較は `hmac.compare_digest(dk.hex(), hash_hex)`。`ValueError`/`AttributeError` は False。

#### 1-4. `LocalAuthProvider`（auth.py:151-186）と auth_users.yaml の形式

- `name = "local"`, `hint = "社内LDAP導入までの暫定アカウントです。"`。
- `_load()`（:163-170）: ファイルが無ければ `[]`。`yaml.safe_load` 失敗は `AuthError("ユーザー定義を読めませんでした: ...")`。返すのは `data.get("users") or []`。

  1. ユーザーが 0 件なら `None`（異常扱いしない。常設アカウントだけで運用できるため）。
  2. `u["username"].lower() == username.lower()`（**大文字小文字を区別しない**）で最初に一致した 1 件だけ検証。
  3. `verify_password(password, u.get("password_hash", ""))` が偽なら `None`（同名の 2 件目は見ない）。
  4. `groups = list(u.get("groups") or [])`、`is_admin = AUTH_ADMIN_GROUP in groups`。
- auth_users.yaml の形（`save_users_file` / `_mu_cmd_add` core.py:15655-15671 から）:

#### 1-5. `HttpApiAuthProvider`（LDAP 連携 API、auth.py:189-258）

- `name = "http"`, `hint = "社内アカウントでログインしてください。"`。
- `AUTH_API_URL` が空 → `AuthError("AUTH_API_URL が設定されていません…")`。
- 送信: `POST`、`Content-Type: application/json`、`Accept: application/json`、本文 `{AUTH_API_USER_FIELD: username, AUTH_API_PASS_FIELD: password}`（パスワード平文を JSON で送る。TLS は URL 次第）。
- 応答分岐:
  - `HTTPError` で `e.code in (400, 401, 403)` → `None`（認証失敗）。それ以外の HTTP エラー → `AuthError("認証APIがエラーを返しました: HTTP n")`。
  - 接続例外 → `AuthError("認証APIに接続できません: …")`。
  - 本文が JSON でない → `AuthError("認証APIの応答がJSONではありません。")`。空本文は `{}`。
  - `AUTH_API_SUCCESS_FIELD` が設定されていれば `bool(_dig(data, field))` が偽で `None`。未設定なら `status != 200` で `None`。
- 結果 `User`: `username = _dig(data, AUTH_API_USER_FIELD) or username`、`display_name = _dig(data, AUTH_API_DISPLAY_FIELD) or ""`、`groups` は `AUTH_API_GROUPS_FIELD` 指定時のみ（文字列 1 個なら 1 要素リストに）、`is_admin = bool(AUTH_ADMIN_GROUP) and AUTH_ADMIN_GROUP in groups`。
- `_dig(data, "a.b.c")`（:261-270）: ドット区切りで dict をたどる。途中で dict でない/キーが無ければ `None`。
- LDAP そのものに直接バインドする実装は無い。「LDAP 計画」は docstring（auth.py:2-8, 189-203）で「社内の認証API（LDAP連携API）に HTTP で問い合わせる」方式として `http` プロバイダを差し替え口にしている。

### 4. `login_required` / `admin_required`（core.py:7358-7388）

  g.user is None →

#### 5-2. 管理者専用ツール `ADMIN_TOOLS` と 2 か所の強制

- 定義（brain.py）: `ADMIN_TOOLS_files = {"explore_import_files"}`（:9989）、`ADMIN_TOOLS_usage = {"analyze_usage"}`（:11448）、`ADMIN_TOOLS_knowledge = set()`（:12378）。`_MODULES`（:12538-12547）の第 3 要素を集めて `ADMIN_TOOLS = {"explore_import_files", "analyze_usage"}`（:12558）。
- 強制点 1: `build_tools(entries, admin=False)`（brain.py:12695-12707）— `name in ADMIN_TOOLS and not admin` なら **宣言を AI に渡さない**。core.py からの呼び出しは `tools.build_tools(scope, admin=_is_admin())`（core.py:8251 `_advance`、:8629 ストリーム版）。
- 強制点 2: `dispatch(name, arguments_json, scope, entries, admin=False)`（brain.py:12841-12851）— `name in ADMIN_TOOLS and not admin` なら `_err(f"'{name}' は管理者だけが使えます。")` を返して実行しない（「渡していないツールを名指しで呼ばれても実行しない（守りは2箇所で持つ）」）。core.py からは `tools.dispatch(..., admin=_is_admin())`（core.py:8416, 8594, 8817）。
- 付随: ヘルプ画面のツール一覧も `name in tools.ADMIN_TOOLS and not g.user.is_admin` で非表示（core.py:15116）。ヘルプの `bases`（ナレッジベース一覧）も `rag.kb_list() if g.user.is_admin else []`（core.py:15133）。

#### 5-3. `_may_contribute_catalog()`（core.py:8228-8238）

### 11. デバッガ拒否と起動時の防御（core.py:15484-15540, 15875-15927）

- `_TRUE = ("1","true","yes","on","t","y")`（:15486）。`_DEBUG_ARGS = ("--debugger","--debug")`（:15526）。
- `_refuse_debugger()`（:15529-15540）: `os.environ["FLASK_DEBUG"]` が `_TRUE` に含まれる、または `sys.argv[1:]` に `_DEBUG_ARGS` のいずれかがあれば `raise SystemExit(_NO_DEBUG_MSG)`。`create_app()` の最初の行で呼ぶ（:15545）。理由（コメント）: Werkzeug デバッガの PIN はユーザー名・MAC アドレス・マシン ID から作る固定値で秘密にならない。
- `_is_loopback(host)`（:15515-15521）: `str(host or "").strip().lower() in ("127.0.0.1","localhost","::1")`。空文字は False（`app.run(host="")` は 0.0.0.0 と同じ）。
- 起動定数: `HOST = "0.0.0.0"`（:15881）、`PORT = 8000`（:15882）、`THREADS = 8`（waitress、:15884）、`DEBUG = False`（:15888）。
- `__main__`（:15890-15927）: 引数 `users`/`refresh`/`selftest` は CLI。`DEBUG and not _is_loopback(HOST)` → `SystemExit(_NO_DEBUG_REMOTE.format(host=HOST))`。`DEBUG` なら `app.run(debug=True, use_reloader=False, threaded=True)`、通常は `waitress.serve(app, host, port, threads=THREADS)`（ImportError 時は `app.run(debug=False)`）。
- `after_request _no_html_cache`（:15580-15591）: `text/html` に `Cache-Control: no-store`。他のセキュリティヘッダは付けない。

### 13. リクエスト本文の正規化 `_body()`（core.py:7391-7401）

- `save_settings(data, user)`（brain.py:6598-6631）: エラーが1つでもあれば `MailError(" / ".join(errors))`。保存形は `body_header` を `[:2000]` に切る、`alert_kinds` は `ALERT_KINDS` に含まれるものだけ、`ok_domains` は正規化。保存後 `print("[mailer] 設定を更新しました（user）: サーバ=host:port / 差出人=… / 宛先制限=N アドレス / テスト送信=dry_run")`。
- `mail_status()`（brain.py:6634-6655）: 画面向け。`configured, host, port, sender, sender_name, dry_run, body_header, show_sender, app_title, sample_body, senders, allow_addresses, alert_to, alert_enabled, alert_kinds, alert_kind_labels, restricted, timeout, allowed_domains, allowed_domains_label, ok_domains_source("screen"|"config"), max_recipients, problems, settings_file`。**認証情報は含めない**。
- ルート: `GET /api/mail/settings`（core.py:14496-14500, `@admin_required`, `log: sent_log(20)` を同梱）、`POST /api/mail/settings`（core.py:14503-14511, `MailError`→400）。

#### 1-6. 宛先の検索（`address_tables` / `find_recipients`）

- `address_tables(scope)`（brain.py:6704-6741）: `db.connect_ro` で各DBの `sqlite_master` を列挙。列名が `MAIL_HINTS` に部分一致（大小無視）する列を `mail_columns`。無ければ `_looks_like_email_column`（brain.py:6690-6701: 非NULL 20件をサンプルし、`"@"` と `"."` を含む値が半数以上）。`name_columns`/`dept_columns` は `_display_first` で「id/code/no・`_id`/`_no`/`_code`/番号/コード」末尾の列を後ろへ。
- `find_recipients(scope, query="", *, limit=50, table=None)`（brain.py:6744-6797）: 検索列 = mail+name+dept+残り列の**先頭12列**（`[:12]`）。`WHERE CAST("col" AS TEXT) LIKE :q`（**値はプレースホルダ**、列名は実在列のみ）。`LIMIT int(limit)`。候補の `email` は「mail 列のうち値に `@` を含む最初のもの」。候補 dict: `{email, name, dept, source:"alias.table", valid: EMAIL_RE, allowed: conf.allows(mail), row: 先頭8列}`。同一 email（小文字）は重複除去。

#### 1-7. 下書きの組み立てと検証

- `_norm_addresses(value)`（brain.py:6807-6820）: 文字列は `[,;\n]` 分割、`email.utils.parseaddr` でアドレス部だけ取り出す。
- `validate_draft(draft, *, system=False)`（brain.py:6823-6870）判定順:
  1. `s.problems()` 全部（`system=True` のときは「送信できる宛先」を含む文言だけ除外）
  2. To 空 → 「宛先(To)が空です。」
  3. To+Cc+Bcc 各 `EMAIL_RE`
  4. `total = len(to)+len(cc)+len(bcc) > s.max_recipients` → エラー（文言に `SMTP_MAX_RECIPIENTS`）
  5. `system=True`: 全宛先が `alert_to`（小文字比較）に含まれること
     `system=False`: `allow_addresses` 空 → 「送信できる宛先が1件も登録されていません…どこにも送信できません。」／各宛先 `s.allows(addr)` でなければ「… は送信が許可されていません（許可済みは N件）」
  6. 件名空、本文空
- `compose_body(draft)`（brain.py:6879-6895）: `[body_header({app}→APP_TITLE)] + [送信者行] + [body]` を `"\n\n"` 結合。送信者行は `show_sender` のとき `from_user`/`from_user_name` から「送信者: 表示名（ログインID: id）」または「送信者: id」。**画面の確認カードと送信本文は同じ関数**。
- `build_message(draft, attachments)`（brain.py:6898-6922）: `From`（`formataddr((Header(sender_label(),"utf-8"), s.sender))`）、`To`、`Cc`（あれば）、`Reply-To`（あれば）、`Subject`、`Date`（`formatdate(localtime=True)`）、`Message-ID`（`make_msgid()`）、本文 `set_content(compose_body)`。**Bcc はヘッダに書かない**。添付は `{"data","filename","mime"}` ごとに `add_attachment`（mime は `mimetypes.guess_type` → `application/octet-stream`）。
- `preview(draft, attachments)`（brain.py:6925-6945）戻り: `{from, to, cc, bcc, subject, body, body_lines, attachments:[{filename,size}], errors: validate_draft(draft), dry_run, smtp:"host:port (security)"}`。
- AI ツール `compose_email`（`_compose_email`, brain.py:10022-10060）: `to_query` があれば `find_recipients(limit=50)` の `valid` な候補を To に足す（候補ゼロなら `_err`）。draft は `{to, cc, bcc, subject, body, reply_to, from_user, from_user_name, attach_filenames}`。`llm_content.status` は `"mail_draft"`／`"mail_draft_invalid"`（`problems` 付き）。`render = {kind:"mail_draft", draft, preview}`。**AIは送信できず、画面の「送信」ボタンだけが出口**（note 文言で明示）。

#### 1-8. `mailer.send()` の検査順序と分岐（brain.py:6964-7016）

```
send(draft, attachments=None, user=None, *, system=False) -> record
```
1. `errors = validate_draft(draft, system=system)` → あれば `MailError`
2. `s = settings()`、`msg = build_message(draft, attachments)`
3. `recipients = to + cc + bcc`（`_norm_addresses`）
4. `record = {at, to, cc, bcc_count, subject, user, attachments:[filename...], dry_run, ok:False, message:""}`
5. **`s.dry_run` なら**: SMTP に接続せず `ok=True, message="下書きの確認のみ（SMTP_DRY_RUN=true のため送信していません）"`、標準出力に `[mailer] DRY RUN → 宛先／件名／本文（"  | " 付き）`
6. でなければ `_connect(s)`（brain.py:6952-6961: `ssl`→`SMTP_SSL(context=create_default_context())`、それ以外 `SMTP`、`starttls` なら `starttls(context)`、`user` あれば `login`）。接続失敗 → `record.message="SMTPサーバに接続できません（host:port）: e"` を `_mailer_log` してから `MailError`
7. `server.send_message(msg, from_addr=s.sender, to_addrs=recipients)`（Bcc はここで宛先に入る）。失敗 → `"送信に失敗しました: e"` を記録して `MailError`。`finally: server.quit()`
8. `_mailer_log(record)`（`_mailer_lock` 下で 200 件 FIFO）
- `test_connection()`（brain.py:7019-7036）: `problems()` があれば `{ok:False}`、`_connect` → `noop()`。
- `sent_log(limit=50)`（brain.py:7046-7048）新しい順。

#### 1-9. 添付の解決（会話の中からだけ）

  - 候補 `made` = `chat["render_log"]` の `kind=="file"` かつ `data` を持つ項目**のみ**（他の会話・ディスク・`_files` は見ない）。
  - `names` 空 → `([], [])`。`"all"`（大小無視）を含めば **直近5件** `made[-5:]`。
  - それ以外は名前ごとに、まず完全一致（大小無視）を新しい順に、無ければ部分一致（`w.lower() in filename.lower()`）。見つからなければ `missing` に積む。
  - 戻り要素 `{"filename","mime","data"}`。
- `POST /api/mail/send`（core.py:8869-8897, `@login_required`）: `body.confirm` 偽→400「確認されていません。」→ `_load_current()`（会話の鍵を取る）→ `_attachments_for(chat, draft.attach_filenames)`、`missing` あれば 400 → **`draft["from_user"], draft["from_user_name"] = g.user.username, g.user.display_name`（画面の値を信用しない）** → `mailer.send(draft, files, user=g.user.username)`（`MailError`→400、その他→500）→ `render_log` に `📤 message（件名 / 宛先 / 添付）` を追記 → `_persist(chat)` → `{ok, record}`。

#### 1-10. `alert_to` / `alert_kinds`（定期取り込みの警告メール）

#### 2-4. 利用者フォルダと命名（`save_to_user_folder`）

- `_BAD_NAME_CHARS = re.compile(r'[\\/:*?"<>|\x00-\x1f]+')`（core.py:5120）。
- `user_folder_name(user)`（core.py:5201-5205）: `username` を `_BAD_NAME_CHARS`→`_`、前後空白と `.` を落とし `[:64]`、空なら `"_"`。日本語はそのまま。
- `_STAMP_RE = r"[_-]\d{8}[_-]\d{4}(?=\.[^.]+$)|[_-]\d{8}(?=\.[^.]+$)"`（core.py:5209）。
- `save_to_user_folder(user, filename, data, *, stamp=True, overwrite=False) -> (Path, replaced)`（core.py:5212-5246）:
  1. `base = output_dir()`、`None` → `ImportError_("出力先フォルダが設定されていません…")`
  2. `check_output_dir(base)` 不可 → `ImportError_("出力先フォルダに書けません: …")`
  3. `folder = base.resolve() / user_folder_name(user)`; `folder.mkdir(exist_ok=True)`
  4. `safe = _BAD_NAME_CHARS.sub("_", filename).strip().strip(".") or "file"`; `stamp=False` なら `_STAMP_RE` で末尾の日時を除去
  5. `target = folder/safe`。存在時: `overwrite=True` → `replaced=True`（同名を置換）／`False` → `stem_2, stem_3, …` と空くまで連番
  6. `tmp = folder/f"{safe}.{os.getpid()}.tmp"` に `write_bytes` → `os.replace(tmp, target)`（原子的置換）
  - **パスは利用者にもAIにも指定させない**（この形に固定）。
- `POST /api/file/save-to-folder`（core.py:15359-15375, `@login_required`）: `token` → `_fs_get(token, g.user.username)` `None`→404「そのファイルはもう手元にありません…」→ `save_to_user_folder(g.user, filename, data)`（stamp=True/overwrite=False 固定）→ `ImportError_`→400／その他→500 → `print("[output] user → path")` → `{ok, path, replaced}`。

- `allowed_dirs()`（4594-4605）: `config.IMPORT_DIRS + extra_dirs()` を `resolve()` して重複除去（解決不能は飛ばす）。

#### 3-3. `is_allowed` / `is_within_allowed` / `is_allowed_dir` / `browse`

- `is_noise(name)`（4673-4681）: `~$` 始まり、`.` 始まり、`desktop.ini`、`thumbs.db`。
- `is_allowed(path)`（4684-4695）: `path.resolve(strict=True)`（`OSError`/`RuntimeError`→False）→ `is_file` かつ `not is_noise` → `suffix.lower() in IMPORT_EXTENSIONS` → `any(real == d or d in real.parents for d in allowed_dirs())`。**`..`・シンボリックリンク経由の脱出は resolve 後の実パスで判定**。
- `is_within_allowed(path)`（4698-4710）: 同じだが拡張子は問わない（一覧用）。
- `is_allowed_dir(path)`（4754-4762）: フォルダ版。
- `browse(path)`（4765-4815）: `path` 無し→許可フォルダ一覧。`is_allowed_dir` でなければ `ImportError_("そのフォルダは開けません（許可されたフォルダの外です）。")`。パンくずは許可ルートより上に遡らない。
- `check_readable(path)`（4817-4823）: `is_allowed` でなければ拒否、サイズ > `IMPORT_MAX_FILE_MB` 拒否。
- `list_all_files(depth, limit)`（4713-4740）: `IMPORT_SCAN_DEPTH`／`IMPORT_MAX_FILES` で打ち切り。
- ルート: `GET /api/import/dirs`（13901-13906）、`POST /api/import/dirs`（13909-13924, `action:"remove"` else add）、`POST /api/import/browse`（13927-13934）。すべて `@admin_required`。

#### 3-4. アップロード（`IMPORT_ALLOW_UPLOAD`）

- `check_upload(data, filename, trusted=False) -> ext`（4855-4870）: `not trusted and not IMPORT_ALLOW_UPLOAD` → `ImportError_("アップロードからの取り込みは無効化されています（IMPORT_ALLOW_UPLOAD）。")`；拡張子が `IMPORT_EXTENSIONS` 外→拒否；`len(data)/MiB > IMPORT_MAX_FILE_MB` →拒否。**`trusted=True`（スクレイパー出力）はアップロード禁止の制限を受けない（形式・サイズ検査は同じ）**。
- `POST /api/import/upload`（14033-14051, `@admin_required`）: `request.files["file"]` → `check_upload` → `_fs_put(data, filename, "application/octet-stream", g.user.username)` → `{ok, upload: token, name, size, sheets}`。ディスクには置かない。
- `_read_source(body)`（13939-13957）: `body.upload`（token）があれば `_fs_get(token, g.user.username)`（`None`→「アップロードしたファイルが見つかりません」）→ `read_upload(..., trusted=item["trusted"])`、無ければ `read_table(Path(body.path))`（内部で `check_readable`）。
- Flask 全体の上限 `MAX_CONTENT_LENGTH = 64*1024*1024`（core.py:15554）が `IMPORT_MAX_FILE_MB=100` より先に効く。
- 定期取り込みへの登録: `POST /api/jobs/save`（14287-14300）は `upload` トークンのファイルを**登録できない**（「アップロードしたファイルは定期取り込みに登録できません」）。

#### 3-5. スクレイパー（`scrapers/`）

- 定数: `SCRAPER_TIMEOUT_MIN_SEC = 10`、`SCRAPER_TIMEOUT_MAX_SEC = 3600`、`SCRAPER_INTERVAL_MAX_MIN = 10080`（4920-4922）。`scrape_defaults()`（4977-4985）で env 値を範囲に丸める。
- `_SCRAPER_RUNNER`（4925-4935）: 別プロセスで `runpy.run_path(script, run_name="__scraper__")` → `fetch(out_dir)` を呼ぶ。`fetch` 未定義なら exit 3。
- `list_scrapers()`（4942-4958）: `SCRAPER_DIR` **直下**の `.py` のみ。`_`・`.` 始まりは除外。
- `scraper_path(name)`（4961-4974）: `name == Path(name).name`（パス区切り禁止）、`.py` 終わり、`_`/`.` 始まり禁止、`(d/name).resolve(strict=True)` の `parent == d.resolve()` かつ `is_file`。**`..`・リンク経由を拒否**。
- `run_scraper(name, timeout_sec)`（5030-5108）: `tempfile.mkdtemp(prefix="scrape_")` に出力させる。`subprocess.Popen([sys.executable, "-c", _SCRAPER_RUNNER, script, out_dir], cwd=out_dir, stdin=DEVNULL, stdout/stderr=ファイル, 新プロセスグループ)`（`_scraper_group_kwargs` 4988-4993: Windows `CREATE_NEW_PROCESS_GROUP`、他 `start_new_session=True`）。`proc.wait(timeout)` 超過→`_kill_tree`（4996-5011: Windows `taskkill /PID /T /F`、他 `killpg(SIGKILL)`）→「時間切れ」`ImportError_`。`rc != 0` → 「エラーで終了（終了コード rc）」＋出力末尾 1,500 字（`_scraper_tail`）。出来たファイルは `IMPORT_EXTENSIONS` かつ非 noise、各 `IMPORT_MAX_FILE_MB` 以下。無ければ `ImportError_`。`finally` で `shutil.rmtree` を `(0, 0.5, 2)` 秒待ちで最大3回（**成功失敗によらずサーバに残さない**）。
- ルート: `GET /api/scrapers`（13962-13968）、`POST /api/scrapers/test`（13971-14002: timeout 範囲外→400、出力を `_fs_put(..., trusted=True, label="スクレイピング: x.py → a.xlsx")`）。`@admin_required`。
- ジョブ実行 `run_job`（6215-6256）: スクレイピング設定は `_jobs_lock` の**外**で取得（ロックを握ったまま分単位で待たない）。`_scraping: set` + `_scraping_lock`（6188-6189）で同一 `jid` の同時実行を拒否 `{"ok":False,"skipped":True,...}`（設定にも履歴にも残さない）。取得後 `_jobs_lock` 下で `_run_job_locked`。

#### 3-6. 定期取り込み実行時の安全弁（`_run_job_locked`）

- 元ファイルが `importer.is_allowed(path)` でなければ実行しない（core.py:6278）。
- 設定した列が1つもファイルに無い → 「設定した列が1つも見つかりません（ファイル側の見出し: …）」で中止（6296）。
- データ行 0（見出しだけ）→ 失敗扱いにして前回の内容を残す（6308-6314）。追記モードなら「何もしていません」。

### 4. マイロボットの安全（core.py 元 robots 区画）

#### 4-1. 保存ファイルと壊れたファイルの扱い（`_ROBOTS_BROKEN` → 409）

- 置き場 `_robots_path(user) = config.USER_META_DIR / (user.safe_key or str(user)) / "robots.json"`（9230-9232）。`User.safe_key`（auth.py:97-105）: `isalnum() or "-_.@"` 以外は `_`、`[:64]`、空・`.` 始まりは `_` を前置。
- ファイル形: `{"robots": [robot, ...], "last_ok": {指紋: ISO時刻}}`。robot は `{id, name, from_chat, from_title, questions[], steps[{name, arguments, produced}], holes[], tables[], folder_out, folder_stamp, folder_overwrite, owner{username, display_name, groups[], is_admin}, mail_auto, mail_table, notify_to[], schedule{_SCHEDULE_KEYS}, created_at, updated_at, last_run, last_status, last_message, history[{at, source, ok, message, chat_id}]}`（登録 10819-10842、書き戻し 10411-10435）。
- `_robots_raw(user) -> (data, broken)`（9235-9250）: ファイル無し→`({"robots":[]}, False)`。`_read_json` が dict でない／`robots` が list でない → `({"robots":[]}, True)`。**壊れていると黙って空を返さず、書く側で止める**（次の保存で1件だけに上書きされて全消失するのを防ぐ）。
- `_ROBOTS_BROKEN`（9073-9074）: 「マイロボットの保存ファイル（robots.json）が読めません。壊れている可能性があるため、上書きせずに止めました。管理者に連絡してください。」
- `ValueError(_ROBOTS_BROKEN)` を上げる箇所: `robot_save`（9292）、`robot_delete`（9325）、`robot_admin_stop`（12032）。
- HTTP への写像: `POST /api/robots/save` → `409 if str(e) == _ROBOTS_BROKEN else 400`（10850）／`RobotConflict`（同名・同内容）→409 `{"duplicate": true}`（10848）；`POST /api/robots/update` → `ValueError` は一律 409（10938-10939）；`POST /api/robots/delete` → 409（10945-10947）；`POST /api/catalog/robots/stop` → 409（12079-12080）；`POST /api/catalog/robots/test` → `robots_list(owner)` の `ValueError` を 409（12100-12102）。
- 例外を上げず黙るケース: `_robot_write_back` は `print("[robot] 実行結果を書き戻せませんでした: …")`（10433-10434）、`_robot_claim` は `print` して `None`（10459-10461）、`stop_robots_of` は `print` して `[]`（12055-12057）、`robots_due` は `_read_json` が dict でなければ空扱い（10563-10566）。
- `_robots_write(user, items, ledger)`（9257-9270）: `last_ok` 台帳を **31日**より古いものを落として `_write_json`（原子的置換）。`robot_delete` は台帳を残す（消して作り直す抜け道を塞ぐ、9330）。

#### 4-2. 本人の写し（owner snapshot）と権限

- `_owner_snapshot(user)`（10532-10535）: `{"username","display_name","groups": list,"is_admin": bool}`。
- 取得タイミング: 登録時（10829）、`POST /api/robots/run` で現在の写しと違えば取り直して `robot_save(check_dup=False)`（10877-10882）、`POST /api/robots/update` で何か変えたとき（10931-10932）。**定期実行は登録・変更時点の権限で動く**。
- `_robot_owner(dir_name, robot)`（10538-10548）: 写しから `auth.User(...)` を作る（写しが無ければフォルダ名の一般利用者）。
- `run_scheduled_robots`（10577-10620）: `_flask_app` が `None` なら何もしない。`app.test_request_context("/robots/scheduled")` の中で `g.user = user` を入れて実行（会話保存・権限判定が画面と同じ経路）。
- 管理者ツールの門: `_execute` → `tools.dispatch(..., admin=_is_admin())`（core.py:8416）、`_is_admin()` は `g.user.is_admin`（8211-8219）。`dispatch` 側でも `name in ADMIN_TOOLS and not admin` を再検査（brain.py:12850-12851）。`ADMIN_TOOLS` は `{"explore_import_files","analyze_usage"}`（brain.py:9989, 11448, 12558）。

#### 4-3. 二重実行の防止（`_robots_lock` / `_robots_running` / `_robot_claim`）

- `_robots_lock = threading.RLock()`（9070）：robots.json の「読む→差し替える→書き戻す」を直列化。`_robots_running: set`（9072）：`(safe_key or username, robot_id)`。
- `_robot_execute(user, robot, values, *, source="manual")`（10464-10496）:
  1. `_robots_lock` 下で `key in _robots_running` → `(None, False, "このマイロボットはいま実行中です…")`；`add`
  2. `_robot_run(robot, values)`
  3. `ok and robot.mail_auto` → `_robot_send_mails`
  4. `not ok and source == "schedule"` → `_robot_notify_failure`
  5. `_robots_lock` 下で `saved["_last_chat_id"] = chat.id` を保存
  6. `_robot_write_back(...)`
  7. `finally`: `_robots_running.discard(key)`
- `_robot_claim(user, rid)`（10438-10461）: 定期実行の直前に読み直し、`robot_next_scheduled(fresh)` が `None` または未来なら `None`（止められた・変更された）。`schedule.last_run = now, last_status = "running", last_message = "実行中…"` を**先に書く**（実行途中で落ちても次回起動で二重に動かない。「1回抜ける方が安全」）。
- `_robot_write_back(user, rid, ok, message, source)`（10411-10435）: `_robots_lock` 下。`robot_get` が `None`（実行中に削除）なら書かない。`last_run/last_status("ok"|"error")/last_message`、`history` に `{at, source, ok, message[:400], chat_id}` を追加し **`ROBOT_HISTORY_MAX = 20`** 件に切る（10350）。`source=="schedule"` なら `schedule.last_status/last_message` も更新し `last_run` は claim 時刻を保持。
- `robots_due(now)`（10551-10574）: 全利用者の robots.json を走査。`min_interval_hours` より短い間隔の設定は飛ばす（`floor_blocked`）。`robot_next_scheduled` が `TypeError/ValueError` を出すロボットは飛ばす（1件の壊れた日時で全員を止めない）。
- `run_scheduled_robots` のループ: `scheduler.stopping()` で `break`；`_robot_claim` が `None` なら `continue`；`_robot_missing_tables`（9866-9877）があれば `_robot_failed`；`_robot_execute` が `chat None`（手動実行中）なら `_robot_write_back(False, message, "schedule")` で印を残す；例外は `_robot_failed` で通知＋書き戻し。

#### 4-4. 「いま試す」の連打止め（try gap）と管理者の試運転

- `ROBOT_TRY_GAP_MINUTES = 3`（9059。t26 では `core.ROBOT_TRY_GAP_MINUTES = 0` にして回す）。
- `_robot_try_wait(robot)`（9207-9222）: `history` の新しい順で `source == "manual"` の最後の `at` + 3分がいまより後なら、その時刻を返す。`POST /api/robots/run`（10856-10890）は `409 {"error": "続けて押しています。次に試せるのは HH:MM 以降です（3 分あけてください）。", "next_run": ISO}`。**管理者の最低間隔（`min_interval_hours`）は「いま試す」には効かない**。
- 管理者の試運転 `_robot_admin_test(admin, owner_dir, robot, mail_to)`（10502-10529）: 別勘定 `_robot_admin_tests: dict`（10499）、キー `(admin, "test:" + id)`。同じ 3 分ギャップ、`_robots_running` の二重チェック。`_robot_run(robot, {}, test={"mail_to", "owner"})` を管理者名で実行 → 結果の会話は**管理者**のマイエージェントに入る。`mail_to` があり `compose_email` 手順があれば `_robot_send_mails(chat, admin)`（自動送信設定に関係なく送る）。**利用者の robots.json には何も書かない**。
- `_robot_run(..., test=...)` の上書き（9898-9964）: タイトル `"🤖 試運転: name（owner） MM/DD HH:MM"`；`compose_email` 手順は `to = mail_to, cc = [], bcc = []`、件名に `"[試運転] "` 前置、本文冒頭に「これは管理者の試運転です。本来の宛先: …」；`FOLDER_TOOLS` 手順は `save_to_folder = robot.folder_out`、`folder_stamp = robot.folder_stamp is not False`、`folder_overwrite = bool(robot.folder_overwrite)`（元会話の指定より決めごと優先、9956-9964）；手順ごとの所要時間を `chat["timings"]` に残す。
- ルート `POST /api/catalog/robots/test`（12089-12122, `@admin_required`）: `user` 文字列を `safe_key` と同じ規則で正規化し一致しなければ 404；`compose_email` 手順があれば `mail_to` を `_robot_notify_check` で検査（許可リストのアドレスのみ）、空なら 400；表が無ければ 400；二重・連打なら 409；成功時 `session["chat_id"] = chat.id`。

#### 4-5. 止める操作（`robot_admin_stop` / `stop_robots_of`）

- `robot_admin_stop(dir_name, rid)`（12020-12045）: `schedule.enabled = False`、`mail_auto = False`、`updated_at` 更新。中身は変えない。ルート `POST /api/catalog/robots/stop`（12075-12086）。
- `stop_robots_of(username) -> list[str]`（12048-12072）: その利用者の全ロボットの定期実行と自動送信を止める（手順は消さない）。呼び元は CLI `python core.py users remove`（`_mu_cmd_remove` 15686-15699）。壊れていれば止められず `[]`。

#### 4-6. 決めごと（`robot_settings`）

- `ROBOT_SETTING_RANGES = {"max_per_user": (1, 200), "min_interval_hours": (0, 720), "max_steps": (1, 100)}`（9054）。
- 初期値 config: `ROBOT_MAX_PER_USER=5`、`ROBOT_MIN_INTERVAL_HOURS=12`、`ROBOT_MAX_STEPS=20`、`ROBOT_SETTINGS_FILE=DATA_DIR/robot_settings.yaml`（config.py:91-95）。
- `robot_settings()`（9097-9119）: 画面保存 > env > 既定。読めない／範囲外／数でない値は**落とさず**範囲に寄せる（`_robot_clamp`）か既定に戻す。
- `save_robot_settings`（9133-9154）: 範囲外は `ValueError`、`write_text` 直接。ルート `GET/POST /api/catalog/robot-settings`（12872-12891, `@admin_required`）。
- `robot_save`（9281-9318）: 新規は `max_per_user` を超えると `ValueError`。同名は `RobotConflict`、同内容（`_robot_fingerprint`: 道具名・引数（`explanation` 除く）・result_id を「#手順.番号」に正規化・日付の扱い）も `RobotConflict`。台帳 `last_ok[fp]` から前回実行を引き継ぐ。

### 5. 原子的書き込み（一時ファイル → `os.replace`）

#### 5-1. `_write_json(p, data)`（core.py:1066-1075）

- `tmp = p.with_name(f"{p.name}.{os.getpid()}.{threading.get_ident()}.tmp")` → `write_text(json.dumps(data, ensure_ascii=False, default=str))` → `os.replace(tmp, p)`。
- 使用箇所: 会話一覧 `index.json`（1122, 1196）、会話本体 `<id>.json`（1343）、`robots.json`（9270）、利用状況レポート（12766）。

#### 5-2. `_replace_settings_file(tmp, p)`（core.py:1808-1824）

- `for i in range(5): os.replace(tmp, p)`。`PermissionError`（Windows でエディタ・ウイルス対策が開いている瞬間）なら `time.sleep(0.05*(i+1))` して再試行。5回目で失敗したら `tmp.unlink()` してから例外を上げる。
- 使用箇所: `save_chat_display`（1827-1850, `_chat_display_lock` 下、同じ tmp 命名）、`save_catalog_contrib`（1919-1932, `_catalog_contrib_lock` 下）。**読む側も同じ RLock を通す**（1805, 1859: Windows では読んでいる最中の置き換えが失敗するため）。

### 8. スケジューラの周回と停止（core.py 元 scheduler.py, 6500-6653）

- 設定: `IMPORT_SCHEDULER`（env、既定 `true`、config.py:74-75）、`IMPORT_SCHEDULER_TICK_SEC`（env、既定 `60`、config.py:77）。実際の待ちは `max(5, tick_sec)`（6626）。
- 状態: `_stop = threading.Event()`（6526）、`_state = {started_at, last_tick, tick_count, last_ran(直近10件), last_error}`（6528-6534）、`_prev_problems: list`（6564）。
- `is_running()`（6538-6539）: スレッド名で生存確認（フラグに頼らず二重起動を防ぐ）。`stopping()`（6542-6544）: `_stop.is_set()`。`scheduler_status()`（6547-6550）: `{**_state, running, tick_sec, enabled}`。
- `tick()`（6567-6603）の順序:
  1. `jobs.due_jobs()`（6090）を順に `jobs.run_job(job)`（同期・このスレッド内）、`_scheduler_log("OK  "/"NG  " …)`
  2. `_ROBOT_THREAD_NAME` が生きていなければ `_robots_pass` スレッドを起こす（重いロボットが取り込みや他人のロボットを遅らせない）
  3. `_state.last_tick/tick_count` 更新、`last_ran` は**足す形**で最新10件（別スレッドのロボット記録を消さない）
  4. `mailer.alert_import_problems(jobs.problems(), _prev_problems)`（`tick_count > 1` のときだけ）、例外は「通知の判定に失敗（続行）」
- `_robots_pass()`（6606-6615）: `run_scheduled_robots()` の結果を `_state.last_ran` に足す。例外は「マイロボットの定期実行でエラー（続行）」。
- `_loop()`（6618-6628）: `while not _stop.is_set(): try tick() except → _state.last_error, traceback(limit=3)`（1周こけても止めない）→ `_stop.wait(max(5, tick))`（sleep ではなく wait＝停止合図で即抜け）。
- `stop(timeout=2.0)`（6631-6641）: `_stop.set()` → 両スレッドを `join(timeout=2.0)`（ロボットが書き戻す前に落とすと次回起動で二重実行になるため少し待つ）。`_scheduler_log` は `_stop` 後は標準出力に触らない（6559-6565）。
- `start()`（6644-6653）: `IMPORT_SCHEDULER` 偽→False；`is_running()`→False；`_stop.clear()`、daemon スレッド起動、`atexit.register(stop)`。
- 呼び出し: `create_app()` 末尾で `_flask_app = app; scheduler.start()`（15599-15602）。
- `jobs.problems()`（6105-6145）: `failed`（`last_status=="error"`）／`degraded`（`last_degraded`）／`overdue`（`interval_minutes>0` かつ `now - last_run > interval*2`）。`INTERVALS` は 手動のみ0／15／60／180／360／1440／10080 分（5823-5831）。
- 実行の入口は4つ（5798-5806）: 画面「▶ 今すぐ更新」、登録直後の初回、アプリ内スケジューラ、`python core.py refresh`。`refresh_cli`（15772-15812）: `--list` 0、`--job ID` 無ければ 1、対象なし 0、1本でも失敗 1。

### 9. プロセスモデル（起動・待ち受け・デバッガ拒否）

- 末尾定数（core.py:15881-15889）: `HOST = "0.0.0.0"`、`PORT = 8000`、`THREADS = 8`、`DEBUG = False`。**env も環境変数も読まない**（他ソフトの `PORT` を拾う事故防止、15850-15854）。
- `__main__`（15891-15927）: 引数あり → `users`（`users_cli`）／`refresh`（`refresh_cli`）／`selftest`（`_sql_guard_selftest`）／それ以外は使い方を出して終了（サーバもスケジューラも起動しない）。`DEBUG and not _is_loopback(HOST)` → `SystemExit(_NO_DEBUG_REMOTE)`。`create_app()` → `DEBUG` なら `app.run(debug=True, use_reloader=False, threaded=True)`、通常は `waitress.serve(app, host=HOST, port=PORT, threads=THREADS)`。waitress が無ければ Flask 開発サーバ（`debug=False, use_reloader=False, threaded=True`）に落とし警告を出す。
- `_is_loopback(host)`（15516-15523）: `127.0.0.1` / `localhost` / `::1` のみ（空文字は 0.0.0.0 と同じなので不可）。
- `_refuse_debugger()`（15530-15540）: `FLASK_DEBUG` が `("1","true","yes","on","t","y")` → `SystemExit(_NO_DEBUG_MSG)`；`sys.argv[1:]` に `--debugger`/`--debug` → 同じ。`create_app()` の最初で呼ぶ（15543-15546）。理由: Werkzeug デバッガの PIN はユーザー名・MAC・マシンIDから作る固定値で守りにならない。
- `create_app()`（15543-15602）の順序: `_refuse_debugger` → `Flask(static_folder=None)`＋`DictLoader(TEMPLATES)`＋`/static/<path>` は `_static_file`（ETag/304）→ `app.config`: `SECRET_KEY=_secret_key()`、`MAX_CONTENT_LENGTH=64MiB`、`SESSION_COOKIE_HTTPONLY=True`、`SESSION_COOKIE_SAMESITE="Lax"`、`JSON_AS_ASCII=False` → ブループリント登録順 `bp_auth, bp_chat, bp_robots, bp_catalog, bp_import, bp_mail, bp_models, bp_knowledge, bp_usage, bp_help, bp_table, bp_api`（12個）→ `before_request(load_user_into_context)`、`teardown_request(_release_chat)`、`context_processor(inject_globals)` → `_warn_if_no_admin()`（15456-15481）→ `_ensure_default_db()`（15441-15452: `.db` が無ければ `data/データ.db` を空で作り `catalog.save_meta`）→ `after_request` で `text/html` に `Cache-Control: no-store` → `_flask_app = app; scheduler.start()`。
- `_secret_key()`（15425-15438）: `FLASK_SECRET_KEY` > `BASE_DIR/.flask_secret` > `secrets.token_urlsafe(48)` を生成して保存（`chmod 0o600` 試行）。
- **ワーカーは必ず1プロセス**（15866-15868）: スケジューラスレッドがワーカー数だけ立ち同じ取り込みを多重実行するため。同時アクセスは `THREADS` で稼ぐ。前段に nginx を置くなら SSE のため `proxy_buffering off;`（15870-15872）。
- 記録はすべて標準出力（`[scheduler …]`、`[mailer]`、`[robot]`、`[output]`、`[importer]`、`[chats]`、`[app]` などの接頭辞。ログファイル・世代管理なし）。
