## 第3部 技術仕様

ここから先は、実装のとおりに書いた技術者向けの章です。処理の順序・判定条件・しきい値・上限をすべて載せています。数値は現在の設定値で、「変更可」は起動フォルダの `env` ファイルで上書きできるもの、「固定」は `config.py` を書き換えないと変わらないものです。

### 3-1. 実行基盤

#### 構成

Python + Flask の1プロセス。画面（Jinja2テンプレート）とAPIを同じサーバが返します。機能ごとに12個のブループリント（マイエージェント／カタログ／取り込み／メール／モデル／ナレッジ／表示／ヘルプ／認証ほか）に分かれています。

#### 起動

`python core.py`。内部では waitress（1プロセス・マルチスレッドの本番用サーバ・スレッド32）が待ち受けるため、**開発も本番も同じコマンド**で起動できます。ホストは全アドレス（0.0.0.0）、ポートは**8000**、デバッグは既定で無効（切り替えは core.py 末尾の DEBUG。有効にするとブラウザからサーバ上のコードを実行できてしまうため、本番では False のまま）。**起動コード（core.py 末尾）は環境変数を読みません**（他のソフトが設定した PORT を拾う事故を避けるため）。

#### 本番向けの起動

同じ `python core.py` のままで本番運用できます。コマンドから直接起動する `waitress-serve --host=0.0.0.0 --port=8000 --threads=32 --call core:create_app` や `gunicorn -w 1 --threads 32 -b 0.0.0.0:8000 'core:create_app()'` も同等です。**ワーカーは必ず1本**（スケジューラのスレッドがワーカー数だけ立ち、同じ取り込みを多重実行するため）。同時アクセスはスレッド数で稼ぎます。前段にnginxを置く場合は逐次表示のため `proxy_buffering off;` が必要です。

#### 起動時の処理順

設定 → ブループリント登録 → リクエスト前処理の登録 → 管理者不在の警告 → DBが無ければ空DBを作成 → 応答ヘッダに `Cache-Control: no-store` → 取り込みスケジューラ開始。

#### アップロード上限

1リクエスト 64MB（サーバ全体）。取り込みファイルは別途100MB制限（後述）。

#### CLI

`python core.py users list|add|passwd|remove`（利用者管理）と `python core.py refresh [--all|--job ID|--list]`（定期取り込みの実行）。 refresh の終了コードは 0=全成功または対象なし、1=1本でも失敗。cronから叩けます。

### 3-2. 1つの質問が処理される順序

AIは「考える → 道具を使う → 結果を見てまた考える」を繰り返します。その繰り返しの制御が以下です。

| 段階 | 内容 |
|---|---|
| 前処理 | 質問の空チェック → API設定の確認 → 結果キャッシュの「今回の質問」の区切りを打つ → 会話の読み込み → 画像の検査 → **先に質問を保存**（途中で切れても質問は残る）→ 対象テーブルの決定 → リアルタイム取り込みの確認 → 最新のカタログでシステムプロンプトを作り直して先頭に差し替え。 |
| 往復の上限 | **10回**（変更可）。上限に達すると最終回答をまとめ、「ツールの呼び出しが10回に達したので、ここで一区切りにしました」と表示します。 |
| 同じ呼び出しの検出 | 同じ（ツール名・引数）の組み合わせは**2回目から実行せず差し戻し**、差し戻しが2回続いたら打ち切って回答をまとめます。成功の繰り返しと失敗の連鎖でメッセージを出し分けます。 |
| 空応答 | 本文もツール呼び出しも無い応答は、履歴から取り除いて**1回だけ**やり直します（この再試行も10回のうち1回を消費）。 |
| 出力が途中で切れた場合 | モデルの出力上限に達した回答には「『続けて』と送ると続きを書きます」の注記を付けます。 |
| ツールの失敗 | アプリ側では再試行しません。エラーの内容をAIに返し、AIが引数を直して呼び直します（同じ引数なら上記の重複検出で止まります）。 |

### 3-3. システムプロンプトの構成

毎回この順で組み立て直します（会話ごとに固定せず、カタログの変更が即座に効くようにするため）。

| 順 | ブロック | 内容 |
|---|---|---|
| 1 | 導入文 | 役割の宣言。文書検索が使えるかどうかで2種類。 |
| 2 | # 振る舞い | 実データを根拠にする・推測で答えない・日本語・用語集に従う。登録の提案は1回の回答につき最大1つ。検算の警告が来たら末尾に注記する。 |
| 3 | # 可視化の方針 | グラフの使い分けと、同じデータの使い回し方。 |
| 4 | # SQLで書けないこと | 統計・予測などは専用ツールを使うこと。 |
| 5 | # ファイル出力 | Excel/CSV/Word/PowerPointの作り方。 |
| 6 | # 利用可能なツール | 権限と有効・無効を反映した一覧（名前・引数・説明）。 |
| 7 | # 社内文書 | 検索対象を1件も選んでいなければ、このブロックごと出しません。 |
| 8 | # 状態に問題があるデータ | 定期取り込みが失敗している表があるときだけ。 |
| 9 | # SQLルール | 書き方の約束。 |
| 10 | # 選択中のデータカタログ | 表・列の説明、主キー、結合キー、まとまりのメモ、用語、例文。詳細は次項。 |
| 11 | 現在時刻 | 秒までのISO形式（「今月」などの相対表現の基準）。 |

カタログ本文の見出しは `## 使えるデータ` / `結合キー（JOINにはこれを使う）:` / `テーブルをまたぐ業務用語（質問にこの言葉が出たら必ずこの定義に従う）:` / `正しいと確認済みの質問とSQLの例:`。表ごとは `### 表名（N行）` と列一覧・サンプル3行。**検算だけはプロンプトに載りません**（ツールの実行結果に混ぜ込む方式）。

### 3-4. AIに見せるテーブルの決め方

#### ① 利用者の選択

サイドバーで外した表を最初に落とします。0件になればそこで終了。

#### ② 全部入るか判定

カタログ全文の文字数が上限以下なら**絞らずに全部渡します**（選び漏れゼロ・プロンプトが毎回同じで再利用が効く）。動作モードは auto（既定）／router（常に絞る）／ all（常に全部）の3種。

#### 上限の計算

`モデルの文脈長 × 0.5 ÷ 0.55`を、下限4,000字・上限400,000字で丸めた値。例: 文脈長105万のモデル → 40万字（上限で頭打ち）、12.8万のモデル → 約11.6万字。

#### ③ 表ルーター

収まらないときだけ、質問文と**要約版**カタログを別のモデル呼び出しに渡して関係する表を選ばせます。表の総数が8以下なら呼びません。使うモデルは画面で選んだものではなく**設定で固定されたモデル**、温度0・最大300トークン、直前の質問3件を手がかりに渡します。失敗したら**絞らずに要約モードへ**（ルーターの不調で答えられなくなるのが最悪のため）。

#### ④ 会話中の表を復活

この会話で実際にSQLが触った表は、ルーターの選から漏れても必ず戻します（「それをグラフに」のような続きの質問のため）。

#### ⑤ 関連から1ホップ補完

登録済みの関連をたどり、選ばれた表が参照している先（マスタ等）を機械的に足します。**子→親の一方向・1ホップだけ**（逆方向や連鎖にすると芋づる式に増えるため）。

#### ⑥ それでも溢れたら

詳細版をやめて要約版（列名なし）に落とし、その旨の注意書きを添えます。

### 3-5. 文脈長の見積り

文字数からトークン数を推定する係数は、日本語主体の本文が**0.55**、ツール定義のJSONが**0.31**（実測にもとづく値）。モデル設定画面の使用量メーターは、推定ではなく実際に組み立てたプロンプトを測って表示します。

| モデル | 文脈長（トークン） |
|---|---|
| gpt-5.6 系 | 1,050,000 |
| gpt-4.1 系 | 1,047,576 |
| gpt-5 / mini / nano | 400,000 |
| o1 / o3 / o4 系 | 200,000（o1-mini のみ 128,000） |
| gpt-4o / gpt-4o-mini / gpt-4-turbo | 128,000 |
| gpt-4-32k / gpt-4 | 32,768 / 8,192 |
| gpt-3.5-turbo 系 | 16,385 |
| 表に無いモデル | 128,000として扱い、画面に「推定」と表示（管理者が上書き可） |

### 3-6. 逐次表示（ストリーミング）と会話履歴

#### 通信方式

Server-Sent Events。イベントは5種類 — `delta`（文字が届くたび）/ `text_end`（ひとまとまり終了）/ `running`（ツール実行開始。日本語名を添えて表示）/ `item`（表・グラフ・ファイルなどの描画物）/ `end`（会話IDとタイトル）。

#### 中断したとき

画面を閉じる・更新すると接続が切れます。**そこまでの内容は必ず保存されます**（完了イベントだけ送られません）。

#### 履歴の2本立て

`messages`（AIに送る列）と `render_log`（画面に描く列）を別に持ちます。システムプロンプトは保存せず、開くたびに最新のカタログで作り直します。

#### APIに送る量

選んでいるモデルが一度に読める量に収まるよう、**古いやり取りから順に外して送ります**（直近のやり取りと、いちばん最初の指示は必ず残します）。要約はしません。外したぶんは「（以前のやり取りは省略しています）」と伝わるので、 AIが勝手に忘れたふりをすることはありません。  
質問に付けた画像は、直近の何回かを過ぎると本文から外します（画面の表示には残ります）。1枚で数MBあるものを毎回送り続けないためです。  
ツールの結果は残したまま送ります。長い会話ほど費用と時間は増えますが、上限を超えて失敗することはありません。

#### 書き直して送信

指定した「何回目の発言か」の直前で、AIに送る列と画面の列をそれぞれ切り詰めます。本文を空で送ると巻き戻すだけ（元の文面を入力欄に戻す）。この経路は常に非ストリーミング。

#### 時刻

各アイテムに秒精度の時刻が付きます（質問は送信時刻、回答は完了時刻）。

### 3-7. モデル呼び出しの再試行

#### 混雑（レート制限）

最大**3回**まで待って投げ直します（変更可）。待ち時間は ①応答の `retry-after` ②エラー文中の「try again in …」＋0.5秒 ③手がかりが無ければ 2秒→4秒→8秒 の順で決め、いずれも**20秒**で頭打ち。 3回で解消しなければ、ここまでのデータは残したまま中断を知らせます。 OpenAIのSDK自体も2回再試行するので、その上乗せになります。

#### モデルが受け付けない引数

エラー文を読んで引数を直し、最大4回まで投げ直します（推論の指定・温度・最大トークンの指定方法の違いを吸収）。学習した調整はプロセスが動いている間だけ覚えます。

#### それ以外の失敗

再試行せず、原因ごとに読みやすい文言へ変換して画面に出します（応答の乱れ／ローカルLLMのメモリ不足／時間切れ ほか）。

#### 共通の設定

温度は**0**（SQL生成の安定のため）、上位確率と最大トークンは既定で未指定、ツールの選択は常にAIに任せる設定。

### 3-8. SQL実行の安全機構（4層）

AIが書いたSQLは、次の4つの関門をすべて通ったものだけが実行されます。

#### ① 構文の検査

前後の空白と末尾の `;` を落とし、**引用符の中身を伏せた検査用のコピー**を作ってコメントを除去してから判定します（文字列の中の「delete」やセミコロンで誤判定しないため。実行するのは元のSQL）。拒否するのは — 空／複数文（`;` が残る）／`SELECT`・`WITH` 以外で始まる／書き込み・定義系の語（insert, update, delete, drop, alter, create, truncate, attach, detach, reindex, vacuum, pragma, grant, revoke, begin, commit, rollback, savepoint, merge の19語）／`REPLACE INTO` の並び。なお単独の `replace` は文字列関数なので通します。

#### ② 読み取り専用で接続

空のメモリDBを土台に、各データベースを**読み取り専用モード**で接続します。 1つのSQLで扱えるのは10個まで（SQLiteの制限）。

#### ③ 実行直前の遮断

SQLiteの認可コールバックで、許可するのは「参照」「読み取り」「関数呼び出し」だけ。さらに**選択されていない表への読み取りはその場で拒否**します。プロンプトから消すだけではAIが名前を覚えている場合に読めてしまうため、最後の関門をデータ層に置いています。

#### ④ 時間と件数の制限

実行時間は**10秒**（SQLiteの命令1万回ごとに経過を確認して中断）。取得は**2,000行**まで（上限+1行だけ取って「超えたか」を判定し、超えていれば実際の総件数を数え直して警告を添えます）。ファイル出力だけは別枠で最大100万行（Excelは1,048,575行で丸め）。 AIに渡すのは先頭40行だけで、画面には全行渡します。

補足: データの選択は「見る範囲を絞る」ためのもので、③の遮断が実際のアクセス制御です。カタログ画面の検証機能など、SQLが名指ししたデータベースは選択外でも接続されます。

### 3-9. エラーの言い換えと結果の使い回し

#### エラーの変換

SQLiteのエラーは「何が悪いか」だけでなく「次に何をすべきか」まで書いた文に置き換えます。**存在しない関数**は代わりに使うものを名指しで案内（24語の対応表。標準偏差・中央値・パーセンタイル→統計ツール、相関→相関分析、date_trunc→strftime、concat→`||`、 top→LIMIT など）。**列名の誤り**は「推測で列名を作らず describe_table で確認」、**構文エラー**は「ウィンドウ関数の一部・PIVOTは使えない、専用ツールに任せる」と添えます。これを添えないとAIが同じ書き方を何度も繰り返します。

#### 結果の使い回し

取得したデータには識別子（result_id）が付き、後続のツールはSQLの代わりにそれを指せます（「集計→グラフ→レポート」で同じSQLが3回走るのを防ぐ）。**覚えておくのは400件・総セル数200万まで**で、超えると古いものから捨てます。時間による期限はなく、プロセスを再起動すると消えます。

#### 取り違え防止

識別子は「同じデータの選択範囲」でしか引けません（当てずっぽうのIDで選んでいないデータは出ません）。AIが指示に従わず同じSQLを書き直してきた場合も、**同じ質問の中で・同じ範囲で・空白の違いを無視して同一**なら機械的に使い回します。

#### 切り詰めの引き継ぎ

2,000行で切れたデータを、より多くの行を扱えるツール（ファイル出力）が使うときは、元のSQLで自動的に取り直します。

### 3-10. ツール基盤

#### 定義の形式

OpenAIのfunction calling形式（名前・説明・引数のJSONスキーマ）。グラフ系は共通の引数定義から機械生成しています。実際に渡る一覧は下の「ツール一覧」に自動表示されます。

#### AIに渡すまでの絞り込み

権限で除外（管理者専用のツールは一般利用者のAIには渡しません）→ 管理者が無効にしたものを除外 → 説明の差し替えを適用 → 文書検索ツール（登録があるときだけ・選択中の対象名を埋め込んで動的生成）→ ユーザー定義ツール（定義に不備が無いものだけ）。

#### 引数の受け取り

配列で受ける引数に文字列が1つ来たら要素1つの配列に直します（直さないと日本語の列名が1文字ずつに散り、「『地』という列がありません」という意味不明なエラーになります）。必須引数が欠けていれば、何が足りないかと確認方法を添えて差し戻します。0やfalseは正しい値として通します。

#### 実行の流れ

引数のJSON解釈 → 権限チェック → 引数の整形 → 必須チェック → 引数の木を再帰的にたどってSQLを収集（レポートの節やExcelのシートの中まで）→ 実行 → 検算の自動割り込み。**ツール内の例外はすべて捕まえて**エラーとして返します（1つの失敗でアプリを落とさない）。

#### SQLの日本語解説

SQLを組み立てるツール（24種）の宣言に `explanation` 引数を**ツール定義の組み立て時に一括で足して**います（1か所で配るので、ツールを増やしても自動で付きます）。AIはSQLと同じ呼び出しの中で解説も書くため、**追加のAI呼び出しは発生しません**。必須にはしていないので、解説が無くても SQLは実行されます（過去の会話も従来どおり表示されます）。ユーザー定義ツールのSQLは人が登録したものなので、AIの解説ではなく登録時の説明文を出します。

#### 2つの戻り値

AI向け（トークン節約のため先頭40行と要約）と画面向け（全行）を作り分けます。グラフはAI向けに行データを入れず「描画した」という事実と識別子だけを返します。

#### ユーザー定義ツール

Pythonは書かせず、SQLとパラメータ定義だけ。パラメータは必ずバインド変数として渡すので SQLインジェクションは起こりません。検査は — 名前（英字始まり・英数字と_・48文字以内・組み込みや既存と重複しない）／説明必須／SQL必須／パラメータ名と型／**SQL中の `:名前` と定義の対応を双方向で**／出力形式ごとの必要項目。

#### 組み込みの上書き

無効化は「どれか1つのデータで無効なら無効」（安全側）、説明は最初に見つかったものを採用。

### 3-11. データの自動プロファイル

人が何も書かなくても分かることは、AIに渡す前に自動で調べます。

| 項目 | 内容 |
|---|---|
| 集める情報 | 列（名前・型・NULL可否・主キーと複合キー内の順番）／外部キー宣言／行数／サンプル**5行**／列ごとの統計。ビューも対象です。 |
| 列の統計 | 値の種類が**20以下**なら「値と件数の一覧（多い順）」を、 21以上なら「最小値と最大値」を持ちます。これがカタログ画面の「実際の値」欄と、 AIに渡すコード値の手がかりになります。行数200万を超える表は統計をスキップ。 |
| 時間の制限 | プロファイル用の問い合わせは**30秒**で中断（行数だけ取れないときは「行数不明」）。 |
| キャッシュ | 結果は `data/.profile_cache/` にJSONで保存。**更新時刻とファイルサイズが一致するときだけ**再利用します（内容のハッシュは取りません）。カタログ本文の組み立て結果も、DB・カタログ・プロファイルの更新時刻をキーに最大64件まで覚えます。 |

### 3-12. 整合性の警告（カタログ画面の⚠）

カタログに書いてある内容が、実際のデータとずれていないかを毎回照合します。検出するのは次の12種類です。

| 種類 | 判定 |
|---|---|
| 説明のある表が存在しない | カタログにあってデータベースに無い（以降その表の検査は飛ばす） |
| 説明のある列が存在しない | 同上（列単位） |
| 指定した主キーの列が無い | 人が指定した主キーの列が実在しない |
| 関連の列が無い／表が無い | 関連の端点が実在しない（他データベースを指すものは対象外） |
| 例文が存在しない表を使用 | 例文のSQLに、実在しない「まとまり__表名」が出てくる |
| 検算が存在しない表を使用 | 左右のSQLとドリルダウンを合わせて判定 |
| 関連の列数が合っていない | 複合キーの関連で、左右の列の数が違う。 |
| ツールが存在しない表を使用 | ユーザー定義ツールのSQLに、実在しない表が出てくる。 |
| まとまりのメモだけが残っている | メモはあるのに、そのまとまりの表が1つも無い。 |
| まとまりのメモの表名が実在しない | メモの中で案内している表が、いまは無い。 |
| まとまりのメモの案内先が無い | メモが、存在しないまとまりへ案内している。 |
| 用語のSQL式が存在しない表を使用 | SQL式を持つ用語のみ対象 |

表名の抽出はUnicode対応の語切り出しで行うため、日本語のテーブル名も正しく拾います。判定対象は「まとまり__表名」形式の名前だけです。

### 3-13. 結合候補の出どころ

ER図の「結合候補」ボタンで出る青い点線は、**「結合を探す」で作った候補**（3-14 の「結合を探す」を参照）と、過去の分析SQLで実際に JOIN されたのに未登録の組み合わせ（使用回数の多い順に8件まで）です。すでに登録済みの関連と、データベースの外部キー宣言にあるものは除きます。まだ探していなければ候補は出ません。以前の「列名からの推測」（`〜_id` の規約・同名の主キー・先頭200種類の値の重なり）は廃止しました。大きな表では連番の ID に小さな整数がたまたま収まって雑な候補が混ざり、画面を開くたびに全列を読み直していたためです。

### 3-14. 関連（リレーション）の扱い

#### 多重度の表記

両端に `0..1`／`1`／`0..*`／`1..*` のどれかを置き、「子側:親側」の形で保存します（例: `0..*:1`＝多対1、`1..*:1`＝親には必ず子がある多対1、 `0..*:0..1`＝親の無い子もある多対1、`1:1`、`0..*:0..*`＝多対多）。組み合わせは順不同で10通りで、線をクリックすると、見出しに子と親の表名を示した10通りのボタンから選べます。下限の `0..` は「相手の無い行がある」、`1..` は「必ずある」の意味で、 AIには多重度の読み方（0.. の側がある表を落とさない LEFT JOIN の注意を含む）を1行添え、既定（0..*:1）以外の関連には「「受注」1件につき「明細」は1件以上」のような日本語を添えて渡します。データ品質の検査でも、親側が 0.. の関連では「親に無い値」を異常ではなく注意として出します。図の線には値をそのまま両端に描きます（IPA表記に合わせ矢印は使いません）。古い保存（N:1／1:N／1:1／N:M）は読み込み時に読み替えます。

#### 向きの自動修正

from/to は描画順ではなく「どちらが参照している側か」を表します。片方だけが単独主キーなら、そちらを親側にして**自動で入れ替え、多重度も反転**します（逆向きに登録されると参照整合性の検査が反対の意味になるため）。

#### 複合キーの結合

複数列の組で1つの結合になる関連（複合キー）は、**1本の線**として登録します。 ER図では、対象の列それぞれから出た線がいったん合流し、1本の幹で相手側へ渡り、相手側でまた各列へ分かれる形で描きます（1つの結合であることと、使っている列の両方が分かるように）。すでに関連がある表ペアへ2組目の列をドラッグすると「複合キーとして列を追加するか、別の関連か」を確認します（作成者と承認者のように、同じ表を別の意味で2回参照する関連は「別」が正解のため、機械では決めず人が選びます）。保存形式は`表.(列1, 列2)` のように括弧で列をまとめ、AIには「全列を同時に結合条件にする」と明示して渡します。列の組で一意になる場合は、単独列の重複警告を出しません。

#### 登録時の実データ検証

保存前に必ず実データを照合し、結果を3段階で返します。**阻止** =値が1件も一致しない。**警告** =一致しない値が30%以上／型が違う／主キー同士を結んでいる／参照先の値が一意でない／区分値とIDを結んでいる疑い（相手の値が10種類以上あるのに自分は10種類以下で、相手の半分未満しか使っていない）。**情報** =親に無い値が少しある。警告は確認のうえ強行できますが、阻止は保存できません。大きな表でも止まらないよう、一致率と参照率は「値の種類」の標本（既定 2,000 種類。相手の表は1回読むだけ）で見積もり、標本の範囲で一致が無いときは全体に1件でもあるかを確かめてから阻止にします。親の一意性はデータベースが宣言した主キー・UNIQUE 索引があれば読まずに確定し、無ければ全行で数えます（時間内に終わらなければ先頭 10 万行で概算し、その旨を添えます）。1本のクエリは 5 秒で切り上げ、間に合わなければ、そこまでの判定に「確認が時間内に終わりませんでした」の警告を添えて人が決めます（登録後、データ品質の検査で親に無い値を数えられます）。検査中は「実データを確認しています…」と出て、次の線は終わってから引けます。

#### 主キーの決め方

人が指定した主キー（実在する列だけに絞る）→ データベースの宣言 → 無し、の順。人が指定した場合はプロンプトに「（人が指定）」と明記し、複合キーなら「結合するときは全列を条件にする」、キー無しなら「重複行があり得る」と添えます。

#### 線の濃さ

全利用者の会話履歴から実行済みSQLを集め、JOINの端点を正規表現で解析して使用回数を数えています（薄い灰色＝未使用）。向きは問わず同一視します。

#### 結合を探す

道具の「結合を探す」を押すと、全表の全列を実データで調べて、値が重なる列の組を結合の候補にします（列名の規約や主キーの宣言は要りません。列名が同じことは手がかりとして使います）。親になれるのは値が一意な列で、宣言が無ければ実データで数えます。子の標本 2,000 種類を親の列全体に引いて 9 割以上（列名が同じなら 5 割以上）一致すれば候補にし、多重度も推定します（子に空欄があれば親側 0..1、親の値がほぼすべて参照されていれば子側 1..*）。値の種類が 2 万を超える大きな親は標本で絞らず、全種類を索引つきの一時表に持って直接引きます（新しい親だけを参照する明細も見逃しません）。型が違う組（文字と整数）も値が一致すれば候補にし、根拠に「型が違う」を添えます。偶然の一致を除くため、連番の主キーどうしは結ばず、整数の親は（子の値の種類が 1,000 未満なら）参照率が半分以上のときだけ候補にします（月や数量のような小さな整数が連番のキーに収まるだけの組を除くため）。まとまり違いの同型表は結ばず、相手が複数あるときは同じまとまりの相手だけ、それでも 4 つ以上なら曖昧として出しません。結果は表の定義（列名と型）の指紋と一緒に `data/join_candidates.json` に保存し、以後の「結合候補」はこれを出します。表が増えたり列が変わったりすると「表が増えました」と出て、増えた表に関わる組だけ探し直せます。表やまとまりを改名しても、保存した候補は新しい名前に付け替わります（列と型は同じなので探し直しは要りません）。裏で動き、進み具合（列の調べ／組の確認）を出します。どのクエリも 5 秒で切り上げ、間に合わない列や組は飛ばします。

#### ER図の座標

保存があればそれ、無ければ4列グリッドに自動配置。保存は送られたノードだけを上書きするマージ方式で、壊れた項目は読み飛ばします（1つの不備で図全体が出なくなるのを避けるため）。

### 3-15. 業務用語

#### 構造

1つの用語は「説明」と「SQL式（任意）」を持ちます。置き場所は表ごとと全体（テーブルをまたぐ）の2階層。

#### プロンプトへの載り方

SQL式があれば「この式をそのまま使う」、無ければ「列情報をもとに自分で組み立てる」と添えます。**説明だけでも効きます**。表ごとの用語は、詳細を渡すときだけ定義を載せ、一覧のときは名前だけ知らせます。

#### 選択外への漏れ防止

表を絞っているときは、**SQL式が表示中の表しか引かない**かつ**説明文に表示外の表名が出てこない**用語だけを渡します（説明文を素通しにすると、選んでいない表の名前と役割が漏れるため）。関連と例文にも同じ絞り込みが掛かります。

#### 「検証」の判定

式が触れる表を、①式中の表名 ②画面での選択 ③式中の語がすべて列名として存在する表（最も列数の少ない＝限定的なもの1つ）の順で推定します。複数表なら登録済みの関連でJOINを組み立て、関連が無ければ総当たりになる旨を注記します。まず**条件式**として評価し（該当件数と全体件数、該当行を3行まで表示）、失敗したら**計算式**として再評価します。

### 3-16. 例文と検算

#### 例文の上限

**200件**。例文は毎回プロンプトに載るため、増やすほど表の説明が押し出されます。上限を超えた分は保存されず、入らなかった件数を画面で知らせます（黙って捨てません）。

#### 例文の重複判定

「質問文」と「空白と大小を無視したSQL」の**組み合わせ**が同じものだけを1件に。質問文だけ・SQLだけの一致は重複としません（同じ質問に拠点ごとの別SQLが正当に共存するため）。

#### 例文の検証

実行して5行まで取得。判定は OK／0行（条件が厳しすぎないか）／エラー。

#### 検算の構造

「一致するはずの2つのSQL」＋許容差＋不一致時に差の中身を見せるSQL。左右のSQLは**1行1列の数値**を返すこと。許容差の既定は**0.5%**（丸め誤差を拾わない程度）。

#### 検算の発火条件

ツールが実行したSQLが触れた表と、検算の左右のSQLが触れる表が**重なるときだけ**走ります。比較は「差 ÷ 左右の絶対値の大きい方 × 100」が許容差以下なら一致。両方0なら一致。**一致したとき・実行できなかったときは何も言いません**（毎回「問題ありません」と出しても読まれなくなるため）。不一致のときだけ、画面とAIの両方に割り込みます。ドリルダウンは不一致時のみ実行し8行まで。

#### 検算のキャッシュ

ルールの内容とデータの更新時刻の組でキャッシュ。同じ警告は1つの会話で1回だけ出します。

#### 検算の保存

同じ名前は許します（拠点ごとに同名の検算を持つのが普通のため）。内容が完全に同じものだけを1件に間引き、落とした件数を知らせます。

### 3-16b. ビュー

#### 実体

SQLiteの `CREATE VIEW`。保存されるのは**SELECT文だけ**で、データは複製されません（20万行の表にビューを作ってもファイルは1バイトも増えません）。開くたびに元の表から計算し直すので、常に最新です。書き込みはできません（読み取り専用）。

#### 作り方

日本語で「欲しい一覧」を書くとAIがSQLを組み立て、その場で実データに当てて確かめます。通らなければエラーを添えて1回だけ書き直させます。SQLを自分で書くこともできます（「AIに解説を書かせる」で解説だけを後から付けられます）。保存前には必ず実行し、動かないSQLはカタログに入れません。

#### 解説と使ったデータ

AIの解説（「このSQLがしていること」）はカタログの表の記述（`tables.<名前>.explanation`）に残し、登録後の行にも出します。SQLを直して解説なしで保存すると外れます。「使ったデータ」は保存せず、そのつど SQLite のオーソライザで数えます: 定義SQLに `EXPLAIN` を付けて下ごしらえだけさせると、読む表と列（`SQLITE_READ`）が1つずつ知らされ、データは読みません。ビューが中で読む元の表も SQLite が展開して知らせるので、そのまま出ます。

#### 安全

定義SQLはSELECT専用ガードを通します（書き込み・DDL・複数文は登録できません）。ビューを読むときも通常の権限が効き、**元の表を選択から外している人はビューも読めません**（SQLiteのオーソライザが元の表への読み取りを止めるため）。

#### 扱い

名前は表と同じ「まとまり__名前」の規約。登録するとテーブル一覧（「ビュー」の印つき）・ ER図・マイエージェントの表選択に出て、説明・列の説明・用語も表と同じように付けられます。削除すると定義だけが消え、元の表とデータは残ります。

#### 注意

SQLiteには結果を保存しておく仕組み（マテリアライズドビュー）がありません。重い集計を毎回計算することになるので、そのぶん時間がかかります。元の表を削除・改名するとビューは動かなくなり、一覧に「動きません」と出ます（作り直してください）。

### 3-17. 取り込みの内部処理

#### 対応形式

`.csv .tsv .txt .xlsx .xlsm`（固定）。Excelとそれ以外は拡張子で分岐します。

#### 文字コードの推定

CSV系は utf-8-sig → cp932 → utf-8 → shift_jis → euc_jp の順に試します。全滅したら「UTF-8かShift_JISで保存し直してください」と案内。

#### 区切りの推定

指定が無ければ .tsv はタブ、それ以外は自動判定。画面ではカンマ／タブ／パイプ／セミコロン／空白も選べます。

#### 型の推定

空白を除いて**全件が数値ならINTEGER/REAL、1件でも数値でなければTEXT**。ただし**先頭ゼロ（0123）・桁区切り・全角数字・小数表記の整数**は「コード」とみなしてTEXTのまま残します（社員番号の先頭ゼロが消える事故を防ぐため）。**日付を判定する仕組みはなく、日付はTEXTになります**。推定はプレビューが読む2,000行から行い、書き込み直前に全行を再検査して、数値にできない値があればその列をTEXTに降格し、降格した列名を警告します。

#### テーブル名の正規化

全角を半角にし、記号と空白を `_` に。**日本語はそのまま残ります**。数字始まりは先頭に `_`、SQLiteの予約語67語は末尾に `_`、**64文字**で切り詰め。まとまりの区切り `__` だけは保持します。

#### 更新のしかた

全件入れ替え（毎回DROPして作り直し）と追記（既存列と照合し、足りない列があれば中止）。**取得日時列はどちらのモードでも必ず付きます**（「いつ時点のデータか」が分からないと断面を説明できないため）。

#### 世代の保持

追記のときだけ保持回数を指定（1〜**800**、既定値なし＝必ず自分で決める）。古い世代の削除は取得日時の新しい順に指定回数だけ残し、それ以外を削除します（取得日時が空の行は消しません）。

#### 件数と大きさの上限

1テーブル**100万行**、1ファイル**100MB**、フォルダの一覧は2,000件まで、プレビューは30行表示。

#### 取り込み元の制限

許可フォルダの中だけ。実パスに解決してから判定するので `..` やリンク経由の脱出はできません。ドライブ直下やファイルシステムのルートは登録を拒否。 Excelのロックファイル（`~$`）や隠しファイルは無視。**データベースは data/ 直下にしか作れません**。アップロードは既定で無効（サーバの許可フォルダに一本化した方が追跡でき、定期取り込みにもそのまま載せられるため）。

#### SQLの組み立て

テーブル名・列名は引用符をエスケープして囲み、値は必ずプレースホルダで渡します。

### 3-19. 文書検索（ナレッジベース）

#### 通信

検索は各サーバの `/query/data` にPOST、認証はAPIキーをヘッダで送ります。疎通確認は `/health`、キーの有効性は `/documents/pipeline_status` （どちらも15秒）。検索のタイムアウトは**180秒**。再試行はしません。

#### 複数サーバの並列

最大**8台**を同時に呼びます。1台が失敗しても他は続行し、失敗したサーバだけを結果に記録します。全滅したときだけ、原因をまとめて知らせます。

#### 既定値

検索方式 mix（他に hybrid / local / global / naive）、取得チャンク数10（1〜100）、関連情報の広さ40（1〜200）、文脈の上限12,000字（1,000〜20,000）。利用者ごとに変更できます。 AIが多めのチャンク数を指定してきても「利用者設定の2倍」「100件」で頭打ちにします。

#### 結果の統合

本文のハッシュで重複を除き、**まず各サーバから1件ずつ（短いものから）**採り、以降は順番に回しながら文字数の予算まで詰めます（1台が予算を独占しないため）。出典番号は採用順の連番で、出典一覧にはサーバ名・ファイル名・スコア・本文の先頭200字を付けます。

### 3-20. グラフと統計のアルゴリズム

グラフは**Plotly**、統計は**SciPy / statsmodels / NumPy / pandas**。 scikit-learn は使っていません。有意水準は 0.05。

#### グラフ

**54種・6分類**（比較12／推移11／構成8／分布8／関係12／指標3）。画面へは図をJSONで渡し、Word・PowerPointへは画像化して貼ります（画像化に失敗しても文書生成は止めず、表と説明だけで作ります）。 2軸グラフは棒を左軸・折れ線を右軸に置きます。

#### 基本統計

件数・平均・標準偏差・最小・四分位・中央値・最大。グループ指定で群ごとに算出。

#### 相関

ピアソン（既定）／スピアマン。偏相関・時差相関にも対応。

#### 外れ値

5手法 — 四分位範囲（既定・係数1.5）／Zスコア（既定3）／修正Zスコア（MAD）／パーセンタイル／マハラノビス距離（複数列）。

#### 仮説検定

**13手法** — 1標本t／**Welchのt**（等分散を仮定しない）／対応のあるt／ Mann-Whitney U／Wilcoxon／一元配置分散分析／Kruskal-Wallis／カイ二乗（独立性）／カイ二乗（適合度）／母比率／正規性（Shapiro-Wilk）／等分散性（Levene）／相関。効果量も併せて出します（Cohen's d、η²、Cramer's V ほか）。分散分析で有意かつ3群以上なら、全ペアに**Bonferroni補正**つきの多重比較を行います。カイ二乗は期待度数5未満が2割を超えると警告します。

#### 回帰

最小二乗（OLS）／ロジスティック／ポアソン。文字列の説明変数は自動でダミー化。係数・標準誤差・p値・95%信頼区間を出し、OLSでは**多重共線性（VIF>10）**と**残差の自己相関（Durbin-Watson が1.5〜2.5の外）**を警告。 30行以上なら**7:3のホールドアウト検証**で当てはまりの良さも報告します。

#### 予測

7手法 — 直近値／ドリフト／移動平均／線形／Holt／Holt-Winters／ARIMA （次数はAICで自動選択）。自動選択では、季節性の指定があり2周期分あればHolt-Winters、 8点以上ならHolt、それ以外は線形。区間は残差の標準偏差から±1.96σ（95%）。 8点以上なら**ローリング・バックテスト**で誤差（MAE/MAPE）も報告します。最低4点必要、予測期間は1〜120。

#### 時系列

移動平均・前期比・累計・前年同期比、傾向は線形回帰、季節分解は加法モデル（2周期分必要）、自己相関は最大6ラグ。

#### シミュレーション

モンテカルロ: 試行1万回（100〜20万）、乱数の種は固定で再現性あり。分布は正規／一様／三角／対数正規／ポアソン／二項／**実データそのまま**／固定値。式は組み込み関数を無効にした環境で評価します。感度分析つき。

#### 信頼区間

ブートストラップ法。復元抽出5,000回（200〜5万）、パーセンタイル法で2.5%〜97.5%。群ごとの比較では信頼区間の重なりも判定します。

#### クラスタ分析

k-means（k-means++で初期化、標準化あり）。**kは自動選択可**（2〜8を総当たりし、シルエット係数が最大のものを採用。0.25未満なら「はっきり分かれていない」と警告）。各クラスタの特徴は、全体平均から0.8標準偏差以上ずれた列を最大3つ拾って言語化します。

#### ABC分析

合計の降順に累計構成比を出し、既定で70%までA・90%までB・残りC。

### 3-21. ファイル出力とメール

#### 生成ライブラリ

Excel=openpyxl、Word=python-docx、PowerPoint=python-pptx、CSV/テキスト/ZIP=標準ライブラリ。

#### 行数と名前

ファイル出力は最大100万行（Excelは1,048,575行）。Wordの1表は40行、 PowerPointの1表は12行まで。ファイル名は使用禁止文字を除き80文字で切り、 `_年月日_時分` を付けます。シート名は31文字で、重複には連番を付けます。

#### 受け渡し

生成物は**ディスクに書かず**メモリに置き、ランダムなトークンのURLで渡します。**持ち主が一致しないと渡しません**（URLを推測されても他人のファイルは取れません）。**時間の期限は無く、200件を超えると古いものから消え、再起動で全部消えます**。会話履歴には2MBまで埋め込み、それを超えると再ダウンロードはできません。

#### メールの組み立て

差出人・宛先・Cc・返信先・件名・日時・Message-IDを付けます。**Bccはヘッダに書かず**送信時の宛先にだけ入れます。

#### 宛先の検索

列名のヒント（メール・氏名・部署）から対象の表を推測し、先頭12列を対象に部分一致で検索します（値はプレースホルダ渡し）。アドレスは「メール列のうち @ を含む最初の値」を採用。

#### 送信の制限

宛先はTo+Cc+Bccの合計で**20件**まで。実際に送れるのは**許可リストに完全一致するアドレスだけ**で、**リストが空なら誰にも送れません**（未設定＝全許可にはしません）。既定は試送モード（SMTPに接続せず内容だけ返す）。 SMTPのパスワードは設定ファイルではなく起動環境の設定からのみ読みます。

### 3-22. 認証と権限

#### 認証方式

2種類を設定で切り替え。**local**＝サーバ上のユーザー定義ファイル、**http**＝社内の認証APIへ問い合わせ（ユーザー名とパスワードのキー名、成功の判定に使う項目、表示名とグループの項目、タイムアウト10秒を設定で指定）。 APIが400/401/403を返せば「認証失敗」、それ以外の異常は「認証エラー」として区別します。

#### パスワードの保存

**PBKDF2-HMAC-SHA256、20万回、ソルト16バイト（利用者ごとに個別生成）**。平文は保存しません。反復回数は保存値から読むので、後で回数を変えても古いパスワードのまま検証できます。比較は時間差の出ない方法で行います。

#### 非常口の管理者

認証APIが落ちても入れるように、設定ファイルに1つだけ管理者を直接書けます。**パスワードを空にするとこのアカウント自体が無効**になります（空パスワードでのログイン事故を防ぐため）。同じIDが入力されたときは、パスワードが違っても外部認証には回しません（同名の別人と取り違えないため）。

#### 常設の一般ユーザー

設定ファイル（auth.py の BUILTIN_USERS）に書かれた、動作確認用の固定アカウント。マイエージェントだけ使える一般権限です。管理者と同じく、 IDが一致したら外部認証には回しません。**本番ではリストを空にして、この仕組みごと止めてください。**

#### セッション

署名付きCookie。**ブラウザを閉じると切れます**（永続化しません）。 JavaScriptから読めない設定・同一サイト送信の制限つき。署名鍵はファイルに保存して再起動でログアウトしないようにしています（無ければ自動生成）。

#### 権限の判定

所属グループに管理者グループ名が含まれるかどうか。管理者専用の画面とAPIはサーバ側で止めます（画面からメニューを隠すだけでは、 URLを直接叩かれると素通りするため）。APIは403、画面は403ページを返します。

#### 利用者管理

サーバ上で `python core.py users add <名前> --admin` など。パスワードは対話式に2回入力（コマンドラインに書くと履歴に残る旨を警告します）。削除はユーザー定義だけで、その人の設定・履歴フォルダは残ります。

#### その他の防御

ナレッジベースのAPIキーは画面・APIの応答から必ず落とします（設定済みか否かだけ返す）。マイエージェントからのカタログ登録は管理者と、管理者メニュー → 画面 の一覧にある人だけ（カタログは全利用者のプロンプトに載るため）。

### 3-24. 同時実行の制御

#### 裏で動くスレッド

3本あります。**定期取り込みのスケジューラ**（60秒ごとに1周）、その周回が起こす**マイロボットの定期実行**（前の分が終わっていなければ起こさない＝1本まで）、回答のあとに1回だけ動く**パーソナライズの書き直し**（利用者ごと・回答は待たせない）。ロボットの実行は要求の外なので、Flaskの要求の文脈を作り、本人の名前（登録時の写し）で動かします。同じロボットの二重実行は実行中の目印で止め、結果の置き場とマイロボットの保存は錠で直列にします。

#### 定期取り込みのジョブ

再入可能な鍵で直列化（裏で回るスケジューラと画面の「今すぐ更新」が同時に走りうるため）。同じ表へ同時に書きません。

取り込み履歴／カタログ履歴／個人設定／モデル設定／メール設定／ナレッジ登録簿／生成ファイル置き場／画像キャッシュに、それぞれ書き込み用の鍵。

#### カタログの保存

ファイルロックは持たず、**書き込み口を管理者だけに絞る**ことで代えています。読み込みは共有キャッシュをそのまま返すため書き換え禁止で、編集時は必ず複製を渡します（下見の処理がキャッシュを壊す事故があったため）。

#### SQLiteの待ち時間

書き込み接続は30秒待ち。分析用の読み取りは時間制限を別方式（前述）で持ちます。

### 3-27. 設計上の制約（運用で気をつける点）

隠さず書いておきます。いずれも「1台・小規模・社内」という前提のうえで、複雑さを増やさないために選んだ割り切りです。

#### ワーカーは1本

スケジューラが常駐スレッドなので、プロセスを増やすと同じ取り込みが多重実行されます。同時アクセスはスレッド数で増やしてください。

#### 生成ファイルはメモリ上

再起動すると未ダウンロードのファイルは消えます（全体で200件まで。あふれたときは「いちばん多く預けている人」の古いものから破棄するので、他の人の送信待ちや取り込み待ちは巻き込まれません）。結果の使い回し用のデータも同様で、取り出せるのは預けた本人だけです。

#### カタログ保存の同時操作

カタログ（統合.db.meta.yaml）は、読む→直す→書くをファイル単位で順番待ちにしています。 2人が同時に保存しても、片方の変更が消えることはありません（長引いて順番待ちが切れたときは「いま別の人が保存しています」と断ります）。用語集・例文・検算は、画面を開いたあとに他で変わっていれば保存前に知らせます。変更履歴も残ります。

#### 会話ファイルの同時送信

同じ会話への送信は順番待ちにしています。待ちきれないときは「いま別の送信を処理しています」と断るので、やり取りが消えることはありません。どの会話に書くかは画面が毎回指定するので、タブを2つ開いても混ざりません。

#### 会話履歴は切り詰めない

長い会話ほど毎回の送信量が増え、費用と時間が伸びます。区切りのよいところで新しい会話を始めるのが安全です。

#### SQLの解析は正規表現

「どの表に触れたか」の判定はSQLの構文解析ではなく名前の照合です。用途が「多い・少ない・ゼロ」の把握なので、多少の取りこぼしで結論は変わりません。

#### 日付の型推定は無い

取り込み時、日付はTEXTとして入ります。並べ替えや期間の絞り込みは ISO形式（YYYY-MM-DD）で書いておくと辞書順で正しく動きます。

#### この答えはどうだったか（評価の記録）

置き場は `data/feedback.jsonl`（1行1件の追記専用）。**会話ファイルとは別**にしてある。利用者が会話を消しても、要望が残っていないと意味がないため。

#### 利用者が押したもの

`POST /api/feedback`。種類は ok / wrong / off_target / sql_ok / sql_ng と、AIの申告への返事 gap_confirm / gap_dismiss。**質問文・何で答えたか・使った表は、画面から来た値ではなくサーバが会話ファイルから取り直す**（画面の値を信じると、押した人が書き換えられる値の上に要望の一覧を作ることになる）。同じ人が同じ質問に同じ種類を2回押しても、1件しか残らない。

#### AIの申告

道具 `report_gap(kind, what)`。 kind は data / doc / feature / explain。答えきれないと自覚したときに1回だけ呼ばせる。追加のAI呼び出しは要らない（答えを書く流れの中で手順が1つ増えるだけ）。

#### 0件で終わった文書検索

誰も押さなくても自動で1行。「予算に入らなくて渡せなかった」と「本当に無かった」を区別していて、後者だけを残す。

#### 引用率（社内文書の当たり具合）

AIは根拠にした箇所に `[出典1]` のように番号を添える決まりになっている。つまり**返した出典と、実際に引いた出典の両方が会話の記録に残っている**。その比が引用率で、**誰も押さなくても取れる**うえ、**過去の会話からもさかのぼって数えられる**。出典番号は質問ごとに1から振り直されるので、質問の区切りごとに突き合わせる（まとめて数えると、前の質問の番号を今の回答が引いたことになる）。

引用率が低いときは、取ってくる件数が多すぎるか、文書の切り方が粗いか、そのナレッジベースがその質問に向いていないかのどれか。「使われた機能」タブにナレッジベース別で出る。

#### デバッガは開かせない

デバッガが開いていると、例外が出たときに**ブラウザからサーバの Python を実行できる**。 PIN で守られているように見えるが、PIN はユーザー名・MACアドレス・マシンIDから作る固定値で、同じ機械なら毎回同じものが出る。守りにならない。

| 断るもの | どこで止めるか |
|---|---|
| `flask run --debug` | 環境変数 `FLASK_DEBUG` に落ちてからアプリが読み込まれるので、`create_app` の入口で見る。 |
| 環境変数 `FLASK_DEBUG=1` | 同上。コマンドに書かなくても同じ扱い。 |
| `flask run --debugger` | こちらは環境変数を通らない別の引数なので、起動時の引数も見る。 |
| `DEBUG = True` のまま外に出す | `HOST` が自分のPCからしか届かないアドレスでなければ、起動そのものを止める。 |

#### 利用状況の新しい口

| ルート | 内容 |
|---|---|
| `POST /api/feedback` | この答えはどうだったか。ログインしていれば誰でも。自分の会話でなければ 404。同じ質問に同じ種類は1件しか残らない。 |
| `GET /api/usage/report?method=requests` | 要望の集計（管理者のみ）。 |
| `GET /api/usage/report?method=premises` | 前提の地図（管理者のみ）。 |
| `GET /api/usage/reports` | 保存したレポートの一覧と1本の中身（管理者のみ）。 |
| `POST /api/usage/report-build` | レポートを1本作る。**ここだけAIを1回呼ぶ**（管理者のみ）。押したときにしか動かない。 |

レポートは集計ではなく読み物なので、`/api/usage/report?method=report` では取れない（400）。 Excel出力の対象にもならない。

通常の起動は `python core.py`（waitress）。 `flask run` は Werkzeug の開発サーバで、接続ごとにスレッドを無制限に作り、遅いクライアントも切らない。本番の待ち受けには向かない。
